## Claim under test

**"ECE 能判别接近校准的正常模型与注入错误置信度的模型"（判据 (c)）能否在真实数据上被关闭**——以及为此引入的观察空间评分是否**加法式**落地（不改动既有冻结基线）。要证六件事：

1. **加法式落地**：`ScoreSpace` 进核心、默认 `WorldXZ` 使阶段 A/B/C 的冻结基线与既有指标键**逐位不变**；
2. **两空间确有差异**且差异的方向可断言（不是"换个说法"）；
3. **判据 (c) 的分离量**：真实面板 + 真实标注 + 观察空间 + 纯感知配置下，`|ece:rtdetr_v2_s − ece:blob_detect_overconfident|` 对照 0.30 阈值（**阈值不动**）；
4. **口径自证**：分离量必须与**覆盖率**、**每生产者样本量**、**分母**一起报（problem-log 015），实验条件由工件阶段键自证（problem-log 016）；
5. **尺度分层**：判别力在目标尺度上是否均匀（problem-log 005 的同族坑：聚合掩盖结构）；
6. **适用边界**：观察空间评分只用于同一观察序列内的校准比较，**不得**支撑跨场景定位主张（ADR-0013 / R-D7）。

**明确不在本片主张之内**：任何 GPU/零拷贝主张（D5）、类别正确性（评分是**纯位置**的，D3 报告 §9 条目 4）、跨场景定位、mAP 类横向比较。

### §3 主判据：判据 (c) 在真实面板上的分离量

**M1 = 全面板 200 帧 + 观察空间 + 纯感知（`--models ""`）+ 两个生产者同时在环**（L2 §5.2 写死的裁定条件）：

| 量 | 值 |
|---|---|
| `ece:rtdetr_v2_s`（诚实侧） | **0.19981957184206142** |
| `ece:blob_detect_overconfident`（注入侧，固定声称 0.99） | **0.5050000095367432** |
| **separation = \|差\|** | **0.3051804376946818** |
| 阈值 | 0.30（不动） |
| **裁定** | **达标（PASS）** |
| **余量** | **0.0051804376946818** |

⚠️ **余量与量化效应同量级（如实登记）**：余量 `0.00518` 与 §4 实测的**空间间量化差 `0.00401`** 是同一量级（比值约 1.3）。也就是说：**全面板的裁定落在一个像素量化步长之内就会翻面**。这不是"判定不稳"的托词——它是一个可算的结论：本面板上判据 (c) 的通过与否，与评分空间的选择**部分耦合**。稳健的读法是"分离量在 `0.30` 附近既不远离阈值、也未系统性偏向某一空间"，而不是"0.305180 是一个稳固的通过值"。§5 的大目标层塌陷（0.220196）与本条是同一件事的两面：**判据 (c) 在本面板上的余量并不厚实。**

**必须同时报告的伴随量（problem-log 015，缺一不可）**：

| 量 | 聚合 | `rtdetr_v2_s` | `blob_detect_overconfident` |
|---|---|---|---|
| `claims:<producer>`（样本量） | 1 210 | **1 010** | **200** |
| `coverage`（匹配/全部主张） | **0.33553719008264465** | 0.30495049504950494 | 0.49 |
| `divergence`（定位误差均值） | 0.052052823904772956 | 0.0533644726602937 | 0.04793049924456481 |
| `divergence_n`（**均值必须连同分母**） | **406** | 308 | 98 |

分母自洽性核对：`(308 + 98) / (1010 + 200) = 406 / 1210 = 0.33554` = `coverage` ✅；`divergence_n = 406` = 全部匹配条目 → **R3 在本面板触发 0 次**（真实面板的真值位置是归一化框心、恒在 `[0,1]²` 内，R3 是合成面板的护栏，本面板上惰性）。工件 `applied = 406 / announced = 804 / rejected = 0 / faults = 0`，与分母完全对齐。

**分离来自哪里（problem-log 012 的纪律）**：诚实侧自身的 ECE **不为 0**（0.1998），因为本面板的"正确"是**纯位置**判定（关联策略不看类别，适配器也不铸类别标签，D3 报告 §9 条目 4）。分离量 0.305 是"诚实侧尚有 0.20 的定位误差"与"注入侧 0.99 的置信度对应 0.49 的正确率"之间的差，**不是**"一个完美模型 vs 一个坏模型"。这一点必须与裁定并列阅读。

### §4 空间对照：两空间的差在像素量化界内

| 量 | M1（observation） | M2（world） | 差 |
|---|---|---|---|
| `ece:rtdetr_v2_s` | 0.19981957184206142 | 0.19882947283216043 | **+9.900990e-4 = 恰好 1/1010** |
| `ece:blob_detect_overconfident` | 0.5050000095367432 | 0.5000000095367432 | **+5.000000e-3 = 恰好 1/200** |
| separation | **0.305180** | **0.301171** | **+4.0099e-3** |
| `divergence:rtdetr_v2_s` | 0.0533644726602937 | 0.05328337448978919 | +8.1e-5 |
| `divergence_n` | 406 | 406 | 0 |

**上界核对（L2 §5.2 要求"超过像素量化上界必须解释"）**：本画布 640×480，每轴 1 px 的归一化量分别为 `1/640 = 1.5625e-3` 与 `1/480 = 2.0833e-3`；主张与真值各自最多平移 1 px，故误差值的最大改变量 = `√((2/640)² + (2/480)²) = **5.2083e-3**`。实测 separation 差 **4.0099e-3 < 5.2083e-3** → **在界内，无需额外解释**。

**差值的机制（可精确复原）**：ECE 的差恰为 `1/N`（N = 该生产者的主张数），说明**每个生产者恰有 1 条主张跨过了容差边界**（共 2 / 1 210 条 = 0.165%）。这与 L2 §3.3 的预期一致：本引擎的相机是单位正方形 ↔ 像素的**恒等**归一化投影，两个空间是同一平面上的两套刻度（连续 vs 量化到 1 px 栅格）。

**R5 的可断言形态**：M1 与 M2 的 `world_hash`（`725d0db5f1fad19a`）与 `ledger_hash`（`5d9a2a225a57875e`）**完全相同** → 评分空间不写真值、不改账本、只改"错误在哪儿量"。

### §5 尺度分层：判别力在目标尺度上**不均匀**

分层规则（L2 §5.3，数据侧零核心改动）：每帧尺度 = 该帧**保留框**的归一化面积中位数；阈值 = 全面板各帧尺度的中位数；`small` = ≤ 阈值、`large` = > 阈值。工具 `tools/stratify_panel.mjs` 自证其认定的保留框数与工件 `annotation_truth.boxes_kept` 一致（**1 219 = 1 219**，不一致即报错退出）。

| 层 | 帧数 | 保留框 | 帧尺度中位数 |
|---|---|---|---|
| 阈值 | — | — | 0.05052614124799999 |
| small（≤） | 100 | 913 | 0.0095423088725 |
| large（>） | 100 | 306 | 0.196470276163 |

排除帧数 **0**（本面板每帧都有保留框）。

| # | 面板 | 空间 | `ece:rtdetr_v2_s` | `ece:blob_detect_overconfident` | separation | 裁定 |
|---|---|---|---|---|---|---|
| M4 | small | observation | 0.14282898830645013 | 0.5000000095367432 | **0.357171** | ≥ 0.30 |
| M5 | small | world | 0.14114548662294843 | 0.49000000953674316 | **0.348855** | ≥ 0.30 |
| M6 | large | observation | 0.28980419483895486 | 0.5100000095367432 | **0.220196** | **< 0.30** |
| M7 | large | world | 0.28980419483895486 | 0.5100000095367432 | **0.220196** | **< 0.30** |

> ⚠️ **判别力在目标尺度上不均匀**：大目标层的分离量塌陷到 **0.220196 < 0.30**（两个空间同值，均低于阈值），小目标层则达 0.357171。**主判据仍按全面板裁定（PASS，0.305180）**，但这条必须写在裁定旁边——只报聚合值就是把"聚合掩盖结构"重演一遍（problem-log 005 的同族坑，L2 §5.2 明令"不允许只报聚合值"）。

**为什么会塌陷**（机制，不是猜测）：大目标层的定位**相对**误差天然更小——RT-DETR 对大框的框心定位精度远高于小框，而 ECE 的"正确/不正确"判定用的是**同一个绝对容差** `kCorrectTol = 0.1`（归一化世界单位）。于是大目标层里诚实侧的正确率**上升**（ECE 0.2898，比小目标层的 0.1428 高），注入侧的正确率几乎不变（0.51 vs 0.50），**分离量因此被压缩**。小目标层则相反：诚实侧更容易判错（ECE 更低 0.1428），分离量更大。

**分层的限制（L2 §5.3 末段，必须写）**：分层是**帧级**的（按该帧的典型目标尺度），不是逐目标的；两层是**不同的图像**，因此层间比较是**生态学**的（不同样本），不是配对的。层内的分离量是各自总体上的有效 ECE。

### §6 世界模型对照（M3）：逐生产者指标与"神谕稀释"无关，聚合指标有关

M3 = 全面板 + 观察空间 + `--models zero_delta`（D3 发布配置）：

| 量 | M1（纯感知） | M3（+zero_delta） | 关系 |
|---|---|---|---|
| `ece:rtdetr_v2_s` | 0.19981957184206142 | 0.19981957184206142 | **逐位相同** |
| `ece:blob_detect_overconfident` | 0.5050000095367432 | 0.5050000095367432 | **逐位相同** |
| `divergence:rtdetr_v2_s` | 0.0533644726602937 | 0.0533644726602937 | **逐位相同** |
| `divergence:blob_detect_overconfident` | 0.04793049924456481 | 0.04793049924456481 | **逐位相同** |
| `divergence_n:rtdetr_v2_s` / `:blob_detect_overconfident` | 308 / 98 | 308 / 98 | **逐位相同** |
| `coverage:rtdetr_v2_s` / `:blob_detect_overconfident` | 0.30495 / 0.49 | 0.30495 / 0.49 | **逐位相同** |
| `claims:rtdetr_v2_s` / `:blob_detect_overconfident` | 1 010 / 200 | 1 010 / 200 | **逐位相同** |
| **聚合 `divergence`** | **0.052052823904772956** | **0.013005197849438658** | **塌陷 4.0×** |
| **聚合 `coverage`** | **0.33553719008264465** | **0.6689995883079457** | **虚高** |
| 聚合 `divergence_n` | 406 | 1 625 | 稀释源 |

**这组对照证实了两件事**（L2 §5.4 对 M3 的原文："验证'逐生产者指标与世界模型集合无关'这一**待验证**命题，不预设它成立"）：

1. **逐生产者指标确实与世界模型集合无关**——零_delta 读真值、精确预测真值位置，其 `divergence:zero_delta = 0`、`coverage:zero_delta = 1`，**只会稀释聚合值，不会扰动任何其他生产者的逐项指标**；
2. **聚合指标确实被神谕稀释**：`divergence` 从 0.052053 塌到 0.013005（分母里塞进了 1 219 条误差为 0 的神谕条目），`coverage` 从 0.3355 虚高到 0.6690（同样的 1 219 条"匹配且自洽"的条目把分母吹大）。

**这两条结论的适用范围要说准**：它们是在**本面板、这两种配置**（纯感知 vs `+zero_delta`）上**证实**的，不是被"证伪"的，也不构成对任意世界模型集合的一般性证明。L2 §5.4 要验的那条命题（逐生产者指标与世界模型集合无关）在本片给出的配置范围内成立；把范围外推需要另做实验。**第二条（聚合被稀释）则是本面板上的实测事实**，与外推无关。

**这就是 problem-log 015 的病态在真实面板上的复现**：只报聚合 `divergence` + ECE 分离量的人，会看到一个"更好看"的数字，而真相是分母被换掉了。本片的逐生产者分解正是为了让这种塌陷**可见**——它在 M3 里是实测出来的，不是推演出来的。

| 工件 | 阶段键 | 读出的事实 |
|---|---|---|
| M1 / M2 / M4 / M5 / M6 / M7 | `truth_load · frame_fetch · detect:rtdetr_v2_s · detect:blob_detect_overconfident · adjudicate · metrics` | **无任何 `predict:*`** → 世界模型**确未**在环（纯感知），不是"省略 `--models` 却跑了默认模型" |
| M3 | 同上 **+ `predict:zero_delta`** | 世界模型在环 ✅ |

所有 7 个工件：`rejected = 0`、`adapter_faults = 0`、`first_fault = ""`、`boundary_events = 0`、`mode = reference`、`acceleration = none`。CLI 的 `--models` 默认值是 `{zero_delta, linear_extrapolation}`，**只有 `--models ""` 才产出零模型**——M1 的阶段键是对这一纪律的逐工件证明。

### §8 观察空间评分买到了什么（以及没买到什么）

**买到的**：

1. **比较空间被显式限定在同一观察序列内**（ADR-0013 的核心）。世界空间问"在这张图的坐标系里两个位置差多远"，观察空间问"在这张图里这两个位置是不是同一个点"——后者是判据 (c) 真正要问的问题（**置信度与正确率的偏差**，不需要跨场景绝对定位）。
2. **不依赖外部标定**：不需要深度、不需要相机内外参，回避了 KITTI 类数据集的非商业许可冲突（阶段 D L1 §2 条 7）。
3. **R3 堵掉一条假阳性路径**：相机的 `pixel_x/pixel_z` 会**钳制**到边框，视野外的真值若照样投影会与边框上的主张"距离为零"→ **钳制伪造出"正确"**。视野外的对现在 ECE 留在分母不给分、divergence 均值排除，`divergence_n` 让排除量可见。
4. **经相机而不绕过相机**（R2）：uv 只由 `ViewCamera::pixel_x/pixel_z` + `world_x/world_z` 得到，metrics 里没有第二套映射——投影语义只有一个来源。
5. **单写者与契约④⑤零改动**：真值仍只由 `TruthWorld` 写；本片改的只是"在哪里比"。

**没买到的（如实登记）**：

- **没有发明新几何**。本引擎的相机是单位正方形 ↔ 像素的**恒等**归一化投影，两空间是同一平面上的两套刻度，误差值只差 ≤ 1 px（实测差 4.0e-3，界内，见 §4）。`ObservationUV` 的价值是**语义的限定**与**未来的可扩展性**（相机不再是恒等时世界刻度会随场景旋转/缩放而变、观察刻度不会），**不是**换算创新。报告不得把它写成后者。
- **没有解决大目标层的判别力塌陷**（§5）。观察空间与世界空间在 large 层给出**完全相同**的 0.220196 → 这条塌陷**不是**评分空间造成的，是**绝对容差 vs 目标尺度**的结构性问题。
- **没有让 `identity_stability` 有语义**。本面板每 tick 换场景、无 track id，该指标恒为 0（其语义 ≡ "相邻两 tick 都零匹配"的频率，见研究笔记 E1），**不可作为本片任何主张的佐证**。

### §9 适用边界（ADR-0013 / L1 §7 R-D7）

观察空间评分的结论**只对同一观察序列内的校准比较有效**。本报告的全部数字都来自单一面板（200 帧，640×480，同一相机参数），因此**不得**被引用为任何跨场景的位置/定位主张。**契约⑦ 的语义未变**：置信度仍是自报的"主张正确概率"、仍零裁决权力；变的只是"正确"在哪个度量空间里判定。

### §10 附录 A：标注装载口径（L1 §7 R-D4 要求判据 (c) 报告附口径）

> 真实标注本身有噪声与协议差异（遮挡 / 截断 / 每数据集规则不同），可能把"模型错"误判成"真值错"。**没有这段口径，本报告的分离量就无法区分"检测器定位不准"与"标注口径放大了差异"。**

**本面板采用的画布与来源**

| 项 | 值 |
|---|---|
| 数据集 | COCO val2017 子集 200 张（`tools/fetch_coco_subset.manifest.json` 固定 image ids + SHA256 + 每图许可） |
| 许可 | 标注 CC BY 4.0（COCO Consortium）；图像按每图 CC，准入许可 id 4 |
| 画布 | **640 × 480**（`width=640` / `height=480`，写在真值清单头部） |
| 坐标 | 归一化 `[0,1]`，原点左上；框心即真值实体位置 |
| 取整幅拉伸 | 源图长宽比 → 画布的拉伸比：min 0.288 / **median 1.000** / max 2.243（`panel_stats.json`）——这是**模型侧混淆项**，不是真值错误 |

**冻结的装载协议**（D3 L2 §4，规则即定义，改动走切片、不走进命令行）：

| 规则 | 内容 | 常量 |
|---|---|---|
| 1 · crowd | 数据集 crowd 标记的框**整条丢弃** | — |
| 2 · 钳制 + 可见面积 | 坐标先钳到 `[0,1]`，再按**钳制后**面积判定退化 | `kAnnotationMinArea = 1e-6`（归一化面积；640×480 上约 **0.31 px²**） |
| 3 · 每帧实例上限 | 超出的按 `source_id` 升序**稳定截断** | `kAnnotationPerFrameCap = 20` |
| 7 · `source_id` 排序 | 规则 3 的确定性来源（`stable_sort`，不引入新身份） | — |

规则 2 的面积阈值**刻意用归一化单位**：若用"1 px"，同一份标注在另一分辨率下"正确"的含义就变了——协议必须与画布解耦。

**本面板的实测计数**（工件 `annotation_truth` 节，M1–M7 一致）：

| 计数 | 值 |
|---|---|
| `frames` | 200 |
| `boxes_kept`（保留框） | **1 219** |
| `dropped_crowd` | 10 |
| `dropped_degenerate` | 0 |
| `dropped_over_cap` | 0 |

**这些计数对本报告读数的影响**：1 219 个保留框、每帧上限 20 **本面板一次都没触发**（`dropped_over_cap = 0`）⇒ 分层子面板（§5）的两个层覆盖的是**同一批框的全部**（913 + 306 = 1 219），层间不重叠、不遗漏。`dropped_crowd = 10` 意味着 10 个"拥挤不可分"的实例**没有进入真值**——它们既不算"模型错"，也不算"模型对"，这是**口径**而非**性能**的一部分。

### §11 偏差、遗留与如实限制

| # | 条目 |
|---|---|
| 1 | **工件级门槛主动降级**（L2 §9 偏差 1）：默认工件不再是逐字节不变，降级为"既有键逐项相同 + 新键纯追加"。仍冻结：600/42 两哈希、`slice11/12/16` 字面量、既有指标键的值与相对顺序。 |
| 2 | **`ViewCamera` 从 `observation/` 搬到 `core/`**（L2 §9 偏差 2）：纯搬移，动机是避免新增 `metrics → observation` 模块边。既有使用者靠既有 include 链继续拿到它，无需改写。 |
| 3 | **`Metric::feed` 增了一个带默认实参的参数**（L2 §9 偏差 3）：既有单测的调用点不动，但虚函数签名变了 → `slice05` 里那个自定义 Metric 的覆写改了一行。默认实参语义写在头文件里。 |
| 4 | **D4 二进制的复现检查**：D3 报告 §2 记的"新旧二进制逐字节对照未执行"（worktree 被权限拦下）在本片被**同配置重跑**补上（§2 表）——这是**同一主张的更弱但可执行**的形态，不是二进制级对照。 |
| 5 | **R3 在真实面板上触发 0 次**：本面板真值位置恒在 `[0,1]²` 内（归一化框心），R3 是合成面板的护栏。它在 slice19 里有专门用例，但**在本面板的测量中未被行使**。 |
| 6 | **`ViewCamera` 是恒等投影**（L2 §3.3 / 研究笔记）：本引擎的世界 x/z **就是**归一化画布坐标，所以"世界距离"与"uv 距离"在本片是同一物理量的两套刻度。观察空间的真实收益要到**相机不再是恒等**时才在数值上显现——本片无法度量它。 |
| 7 | **评分是纯位置的**：关联策略不看类别，适配器也不铸类别标签。本面板的"正确"＝定位正确，**不是 mAP**，不可与 COCO 官方检测结果横向比较。 |
| 8 | **面板取整幅拉伸**（median 畸变 1.000，最差 2.243，D3 报告 §4）：这是模型侧混淆项，会压低真实检测器成绩，也是 §5 大目标层塌陷的候选成因之一——**本片未做畸变分层**（数据侧可做，属后续）。 |
| 9 | **本片不碰 GPU**：全程 CPU（ON 构建 + RT-DETR CPU EP）。CUDA/cuDNN 仍阻塞 D5，不受本片影响。 |
| 10 | **大目标层分离量 0.220196 < 0.30 未被解释为可修复项**：机制已在 §5 给出（绝对容差 vs 目标尺度），但**修复方向未定**——候选包括按目标尺度自适应容差（会改 `kCorrectTol` 语义 → 需新 ADR）或换带 track id 且许可可用的数据集（Phase 4 数据侧立项）。本片如实登记，不假装它已被解决。 |
| 11 | **L2 §7 测试项 1 的夹具字面量被换成实测值**：L2 写的 `0.496` / `0.504` / `0.015625` 是**十进制近似**，在二进制浮点下不精确（`0.496f` 的实际值不是 0.496）。断言若照抄 L2 的小数，会因末位差异失败；实现改用**可被二进制精确表示**的夹具（`slice19` 内实测），并断言"两空间不等"这一**性质**而非某个十进制数。**性质不变，实现取的是可复现的数**。 |
| 12 | **相机守卫只能在首帧观察到达之后才生效**：R3 的"视野外不评分"需要 `ScoreContext.view`，而相机是**跟着观察一起到达**的（契约⑧）。因此首帧之前没有相机 ⇒ 无相机即不投影（`view.width <= 0` ⇒ 不评分），而不是"用默认相机评"。这条在 `slice19` 里有专门用例，但**真实面板的测量中它从未触发**（同 §11 条目 5）。 |
| 13 | **工件发射器曾丢过一个分隔符，而所有既有断言都没抓到**：`config.command_line` 加入后，`"score_space"` 与 `"command_line"` 之间少了逗号 ⇒ 产出的工件**不是合法 JSON**（任何解析器都读不了）。既有测试只做**子串查找**，逐条通过。发现路径是"用解析器打开工件"这一步。已修，并**新增一条 JSON 语法守卫**（`slice19` 内自带严格 JSON 校验器，先用反例自证校验器本身有效，再断言工件可解析）。**这条记在这里，是因为它说明"测试全绿"不等于"工件可用"**——证据文件必须真的能被工具读一次。 |
