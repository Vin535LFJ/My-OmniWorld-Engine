# 面试叙事（interview narrative）

> **这是什么**：把 `problem-log.md` 的踩坑记录，蒸馏成**面试时能讲的故事**。单文件累积，按阶段追加。
> **谁写**：AI 起草，**owner 用自己的话确认**（W02 步骤 4 的第二个检查点）。
> **为什么单独一个文件**：面试前你只需要打开这一个文件，不用在 5+ 条 problem-log 里现拼故事。
>
> **挑选标准**（重要）：优先**反直觉、能体现判断力**的条目，而不是技术名词堆砌。
> 面试官分辨"真做过"和"背过"的方式，是听你怎么描述**决策过程**，而不是你用了什么工具。

---

## 格式（每条一个 STAR）

```markdown
### <一句话标题：这个故事的钩子>

- **情境（Situation）**：当时的约束与背景是什么？
- **任务（Task）**：你要解决什么？
- **行动（Action）**：你具体做了什么决定？**为什么否掉其他选项？**
- **结果（Result）**：可验证的结果是什么？（数字 / 文件路径 / 提交号）
- **一句话提炼**：这条经验能迁移到哪类问题？
```

**写作纪律**：
- 结果必须**可验证**（有提交号、有文件、有数字）。没有证据的故事不要写进来。
- 行动部分必须写**被否掉的选项**——这是判断力的证据。
- 不要写"我使用了 X 技术"；要写"我为什么选 X 而不是 Y"。

## 阶段 A（核心引擎重建）

### 1. 确定性测试在空实现下"平凡通过"

- **情境**：引擎的核心主张是"同 seed 逐字节复现"。我为它写了确定性断言：同 seed 跑两遍，状态哈希必须相等。
- **任务**：切片 01 红相位（实现故意留空）应该全部失败。
- **行动**：跑下来 8 处断言失败，但 `hash(wa) == hash(wb)` 这条**居然通过了**。定位：两个空实现的世界状态都是空的，哈希当然相等——**"同输入同输出"在实现什么都不做时天然为真**。决定：把测试改成**行为断言与确定性断言成对出现**——`tick==10 且 pos==2.5`（证明它动了）与 `hash 相等`（证明它可复现）缺一不可。
- **结果**：红相位同时暴露两者（行为失败、确定性平凡通过），绿相位同时转绿才可信。记录于 `docs/design/problem-log.md` 002。
- **一句话提炼**：**不变式断言必须搭配进展断言**——数学上，不变量在零状态下总成立。任何"每次结果都一样"的测试，要么配一个"结果确实变了"的测试，要么它什么都不守护。可迁移到幂等性测试、缓存命中测试、序列化往返测试。

### 2. 兼容性疑虑用一次降级实验终结，不用观点辩论

- **情境（Situation）**：白纸重建定 C++20 后，owner 两次提出兼容性疑虑——"很多项目还在用 C++11，很少用 C++17/20"。
- **任务（Task）**：回答"C++20 会不会导致兼容性差"。这不是立场问题，是关于这个代码库的事实问题。
- **行动（Action）**：做降级实验而不是辩论——把 CMake 的 `CXX_STANDARD` 从 20 改到 17 重建：一次通过、ctest 全绿；改回 20 再验：同样绿。同时核查代码实际只用了 C++11 级设施（struct/enum class/uint64 算术/模板）——"C++20"只是工具链的一个设置，不是代码的依赖。**被否选项**：无脑降标准换一个"兼容姿态"（丢掉已验证工具链，且没有任何消费者层面的证据支持降级）。决定：保留 C++20 设置 + boring-core 纪律，结论落 problem-log。
- **结果（Result）**：problem-log 003 + 提交 `3011cd0`；0 行代码修改即可双向编译。
- **一句话提炼**：兼容性争议用**降级实验**回答（改一行、编一次、跑测试），不用观点争论；"设置里选的版本"与"代码实际依赖的特性"是两件事。

### 3. 聚合指标会被"产量最大"的分量绑架

- **情境（Situation）**：阶段 A 收口的 Gate-1 对齐运行里，判据 (c) 要求指标能区分"正常模型 vs 故意注入错误置信度的模型"，但在环两组检测器的 ECE 几乎一样（0.4977 vs 0.4963）。
- **任务（Task）**：解释判别力为何消失——是指标算错了，还是别的东西错了。
- **行动（Action）**：定位到聚合 ECE 被**产量**淹没：一轮 9746 条便签里世界模型占 9600 条（固定 0.5 置信度、准确率≈1），每条贡献 ~0.5 的 |acc−conf| 项，把检测器 ~300 条的真实差异彻底淹掉。**被否选项**：① 改指标公式——错的方向，问题在聚合不在公式；② 把检测器置信度公式调到"好看"——那是对合成场景过拟合。决定：per-producer ECE 排期阶段 B（pre-rebuild 的报告本来就是按 producer 分表的——旧设计防的正是这个坑），并把教训升格为通用规则：**聚合指标必须附按来源分解的视角**（workflow-manual 反模式 #13）。
- **结果（Result）**：problem-log 005 + 对齐报告 Findings F1；机制级判别仍然精确（单元测试：诚实组 ECE == 0.0 vs 夸大组 == 0.125，全二进制精确）。
- **一句话提炼**：**任何"全体平均"型指标都要同时保留"按来源分解"的视角**——平均误差、平均延迟、总分，都会被配额最大、信息最少的分量变成主角。迁移场景：把"平均响应时间"当性能判据的压测报告。

### 4. 门卫拦下了它自己的作者——两次

- **情境**：阶段 B 的实现期，我为仓库装了 pre-commit 门卫（测试 + 文档图 lint + 产物卫生），本意是防未来的 AI 会话犯机械错误。
- **任务**：连续写 B2/B3 两份详细设计文档，各自带一张 Mermaid 时序图。
- **行动**：提交两次都被自己的 lint 拦下——一次图里残留 ASCII 花括号（`run（models={...}）`），一次消息文本带半角括号。**没有绕过，没有关 hook**：按错误行号改写法、重跑 lint、再提交。**被否选项**：`--no-verify` 跳过（10 秒的事，但跳过一次就会跳过第二次）；把 lint 规则放宽迁就自己的图（那是让门卫适应作者，不是作者适应门卫）。
- **结果**：B2/B3 均在修正后入库（236e9f6 / 85e3cd6）；GitHub 渲染零报错；此后每份设计图先过 lint 再进提交。提交 `4cf6740` 的工具链 + 两次记录。
- **一句话提炼**：**Guardrail 的价值在拦住作者自己时才兑现**——机械错误的最高发人群不是粗心的新人，是赶进度的作者本人；把检查放在提交路径上，比放在"记得要检查"的脑子里可靠一个数量级。

## 阶段 C（AI 入环）

> **草稿状态**：按本文件规则，AI 起草、**owner 用自己的话确认后**才算定稿。素材来自 problem-log 008–012 与 C3/C4/C5 三份 regression 报告。

### 1. 两个真实模型，对"要不要归一化"给出相反答案

- **情境（Situation）**：引擎第一次接真实预训练模型（RT-DETRv2-S 检测、Depth-Anything-V2-Small 深度）。设计文档写了预处理方案：缩放到模型输入尺寸、像素除 255、按 ImageNet 均值方差归一化——这是检测论文语境里的"标准动作"。
- **任务（Task）**：让模型真的产出可解释的检测结果，而不是"跑通了"。
- **行动（Action）**：第一版照做，实测 **logits 全为负**（区间 [-9.57, -0.38]，一个框都不该有信心）——这是链路错的信号，不是"场景里没东西"。于是去拉基座仓库的 `preprocessor_config.json` 一手核对：`do_normalize` 居然是 **false**，ImageNet 均值方差是惰性参数。撤回归一化、改回 ÷255 + 双线性，同一批输入立刻在真实照片上出 5 个框（最大置信度 0.950），**类别、位置、尺度与图像内容逐一对上**（两只猫、沙发、两个遥控器）。三个月后接第二个模型时，同一张配置表又给出**相反**答案：DA-V2 的 `do_normalize` 是 **true**，插值核还是 bicubic。**被否选项**：把 C3 学到的"不归一化"当成品味迁移到 C4（会立刻错）；按论文默认给 C3 加归一化（也已经错过一次）。
- **结果（Result）**：两条纪律入库——预处理归适配器所有，但**必须与产出该 ONNX 的参考处理器同语义**；**预处理常数不许跨模型迁移，逐模型拉一手配置**。证据：C3 报告 §2/§3、C4 报告 §3。
- **一句话提炼**：**"能跑"只证明 ABI 通了；检出的东西类别和位置都对，才证明链路对**。而"标准预处理"是文档里的传说，配置表才是事实。

### 2. "零幻觉"被写成验收条件，同一个坑在两个切片里各摔一次

- **情境（Situation）**：C3 的详细设计里有一条验收："全背景帧 → 空 Proposal 列表（无幻觉项）"。听起来天经地义——没有东西就该报没有。
- **任务（Task）**：让这条测试通过，或者诚实地改掉它。
- **行动（Action）**：实测空白帧返回 **1 个框**，置信度 0.330，是个 `w=h=1` 的整帧退化框，模型还自报了个类别（tvmonitor）。定位：这条 AC 假设了"COCO 检测器对无物体输入零误报"——那是模型在**分布内**的经验性质，被顺手写成了**契约属性**。改判据而不是改场景迁就模型：断言换成"有界 ≤5 + 两次调用逐字段相等"（上界仍能抓住 sigmoid 套两次 → ~300 框这类失控回归）。**三个月内同一个陷阱复发**：C4 我为"纯平深度帧 → 空列表"又写了行为行，写测试时又差点 `CHECK(empty)`；实测**RGB 全 0x80 的纯灰帧照样产出 32 条结构化提案**（ViT 会从位置编码里造出结构）。
- **结果（Result）**：problem-log 008 及其复现证据；此后模型侧断言的默认检查项是"这条性质是接口保证的，还是模型恰好具备的？"
- **一句话提炼**：**契约可以断言具体值，模型能力只能断言边界**（有界、单调、可复现），**永远不要断言"零"**。同族坑：把第三方库的经验行为写成本地契约测试。

### 3. 隔离层吞掉异常之后，故障原因在工件里彻底蒸发

- **情境（Situation）**：主循环对每个参与者的异常做隔离——单个适配器崩了不许拖垮整轮（这是契约属性）。第一阶段就写成了 `catch (...) { ++faults; }`。
- **任务（Task）**：用 GPU 执行提供者跑一次，确认失败形态。
- **行动（Action）**：程序正常跑完、退出码 0，工件里只有 `adapter_faults: 1`——**原因一个字都没有**，只存在于推理框架自己打到 stderr 的日志里。而工件是"可交接证据"，等于诊断信息为零。补 `RunReport::first_fault`（`生产者名: what()`，只留第一条），并把 JSON 字符串转义扩到控制字符（自由文本进 JSON 的前置条件）。顺着这条又挖出一个更糟的：**setup 期的异常根本没有出口**——`main()` 没有 try/catch，未知适配器名导致进程以 `0xC0000409` fastfail，stdout/stderr 零输出、工件不写。
- **结果（Result）**：problem-log 009；`first_fault` 作为工件附加字段回写契约权威文本；C5 经 owner 批准补上 CLI 出口（setup 异常 → 具名错误 + 非零退出；性能模式有故障 → 非零退出，但**工件照常写出**）。实测对照：修前静默 fastfail，修后 `error: unknown perception adapter: does_not_exist` / exit 1。
- **一句话提炼**：**任何"吞掉异常换取存活"的设计，必须同时留一条最小诊断通道**，否则故障计数是一个只能看不能查的数字。同族：`ignore_errors` 循环、静默 fallback、降级开关。

### 4. 可选依赖把测试矩阵从 1 变成 2，而没人跑第二个

- **情境（Situation）**：为了让参考模式保持"零外部依赖"，ONNX Runtime 做成默认 OFF 的 CMake 选项。此后仓库里事实上存在**两种构建配置**。
- **任务（Task）**：C3 收口时跑 ON 构建的全量测试。
- **行动（Action）**：ON 构建第一次跑全量 ctest 就红——注册表测试写死了 `names.size() == 2`，而 ON 下多注册一个真实模型适配器变成 3。此前 ON 侧只跑过新切片的单测，**这条断裂潜伏了三个切片**。修法不是放宽成 `>= 2`，而是按构建配置断言**精确集合**（既守住"没有意外条目混进来"，也承认注册表随配置增长）；并把纪律写进 AGENTS 硬规则：**新构建配置一旦存在，它的全量套件就是必须跑的**。
- **结果（Result）**：problem-log 010；C4 注册第四个适配器时，这条断言按预言变红又按规则改绿（3 → 4），成为哨兵而非事故。
- **一句话提炼**：**引入可选依赖的真正成本不是依赖本身，是测试矩阵翻倍**——没跑的那个配置，等于不存在的回归保护。

### 5. 判据挂了三个阶段，最后发现要等的不是实现，是一个前提

- **情境（Situation）**：Gate-1 的判据 (c)——"ECE 能区分正常模型与注入错误置信度的模型"——从阶段 A 起就是 PARTIAL（分离量 0.189 < 0.30）。两轮诊断（problem-log 006/007）都指向同一个说法：合成场景没有那个故障，**等真实模型进场就能关闭**。阶段 C 把两个真实模型请进了环。
- **任务（Task）**：C5 重测，给出裁定。
- **行动（Action）**：先定义面板再测。结果：真模型 vs 注入者的分离量 **0.232，仍 < 0.30**；而且**被注入错误的那个始终是 ECE 最低、看起来最校准的（0.010）**。更决定性的是——同一个真模型换面板换 seed，ECE 在 **0.24–0.49** 之间漂移。定位：判据要的是"一个接近校准的正常模型"这个席位，而它需要**模型的定义域与真值域相交**；本世界的真值是平面上 8 个彩色方块，COCO 检测器在其中没有可对应对象，它的"正确"只能来自框心碰巧落在实体 0.1 半径内。**被否选项**：把 0.30 调到 0.25 让它过线（前两轮已立此纪律）；把"数值上有分离"当成达标；把这条结论写进测试（那会让未达标的判据在 CI 里显示为绿灯——所以 slice16 只冻结面板参数与 ECE 字面量，**故意不断言"分离量 < 0.30"**）。
- **结果（Result）**：判据 (c) 如实维持 PARTIAL，**关闭条件重新定位到 Phase 3**（真实视频 + 真标注）；problem-log 012；阶段 C 出口五条：三条达成、两条 PARTIAL 且各自注明卡点（一条缺 cuDNN，一条缺可比真值）。
- **一句话提炼**：当一条判据被归因为"等某个前置到位就能关闭"时，**先验证那个前置提供的是判据所指的语义，而不只是一个新的实现对象**——"真实模型进环"是进度，"真实模型有可比真值"才是前提。另外：**失败的形态必须是报告，不能是绿灯。**
