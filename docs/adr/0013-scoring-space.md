# 评分空间：世界坐标之外新增观察归一化坐标（加法式扩展）

Status: accepted（2026-10-19）

判据 (c)（"ECE 能判别接近校准的正常模型与注入错误置信度的模型"）从阶段 A 一路挂到阶段 C。三轮诊断的结论收敛到同一处：不是指标坏了，也不是实现没做完，而是**真值与模型的定义域不相交**——真值世界是 y≡0 平面上 8 个彩色方块，COCO 检测器在其中没有可对应的对象，它的"正确"只能来自固定格心偶然命中实体（problem-log 006 / 007 / 012）。阶段 D 引入真实视频与真实标注，正是为了造出那个相交。

但真实视频带来一个此前不存在的几何事实：**它只有图像坐标**。现有 `matched_error`（`src/metrics/metrics.cpp`）比的是**世界 x/z** 距离，而把图像标注反投影回世界系需要相机标定与深度——带这两样的公开数据集（KITTI 那一类）许可多为非商业，与作品集 Gate 的"clone 即跑 + 可公开展示"直接冲突（阶段 D L1 §2 条 7 已裁定数据不入库）。另一条路也不通：`TruthWorld` 是具体类，`world_state.hpp` 用 `friend class TruthWorld` 把"唯一写者"钉在这个类名上，真值权威与契约④⑤不能为了评分方便而改动。

于是"位置正确"必须在**观察自己的坐标系**里定义。契约⑧ 早就为此留了位置：相机与分辨率是观察的组成部分，观察自带"如何被看到"——在同一观察序列内部，归一化图像坐标是一个自洽、可复现、不依赖外部标定的比较空间。

决定引入评分空间的选择，并**严格以加法式落地**：

- **`enum class ScoreSpace { WorldXZ, ObservationUV }`**，放在 `core/types.hpp`（与 `BoundsPolicy` / `ExecProvider` 同一先例：被多个接缝共享的值类型属于 core）。
- **默认值 = `WorldXZ`**，现有全部路径与断言的行为逐字不变。
- `matched_error` 按 `ScoreSpace` 分派：`WorldXZ` 走现有世界距离；`ObservationUV` 把主张与真值都换算到观察归一化坐标（经 `ViewCamera` 的投影，不绕过相机）后比距离，容差语义不变（仍是同一个 `kCorrectTol`）。
- **适用边界写进契约与报告**：观察空间评分只用于**同一观察序列内**的校准比较（判据 (c) 要的是"置信度与正确率的偏差"，不需要跨场景绝对定位）；**不得**用它支撑任何跨场景的位置/定位主张。
- 真值来源仍是 `TruthWorld`——它新增"装载外部标注"的能力（阶段 D L1 §2 条 5），单写者与契约④⑤零改动。本 ADR 只改"在哪里比"，不改"谁能写真值"。

## Consequences

- **阶段 A/B/C 的冻结基线全部继续有效**：`world_hash 574361e62eec92b9` / `ledger_hash 459ff85132cc103e` 与 `slice11/12/16` 的字面量必须逐位通过。它们不是"旧数据"，而是可复现性主张的地基；若观察空间的改动让它们变红，按**回归缺陷**处理，而不是更新基线（这是本 ADR 最重要的一条约束）。
- 判据 (c) 第一次有了**可关闭的面板**：真实帧 + 真实标注 + 观察空间评分。阈值 0.30 不动（006/007/012 三轮纪律）。
- 引入新的误差来源：**标注本身的噪声与协议差异**（遮挡、截断、各数据集标注规则不同）。因此报告必须附标注口径说明，否则会把"标注没说"误判成"模型错了"（阶段 D L1 §7 R-D4）。
- 契约⑦ 的语义**不变**：置信度仍是自报的"主张正确概率"、仍零裁决权力；变的只是"正确"在哪个度量空间里判定。这一点必须写进 L0 §2 ⑦ 的追加说明，避免后来者误以为置信度获得了新含义。
- 观察空间比较对**相机内参与畸变不敏感**（同一序列内是固定投影），但**对帧间目标尺度变化敏感**——大目标与小目标在同一 uv 容差下难度不同。判据报告需按目标尺度分层，否则又是一次"聚合掩盖结构"（problem-log 005 的同族）。
