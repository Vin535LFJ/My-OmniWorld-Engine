## 1. 程序描述

阶段 D 的主线是 GPU 数据流，而本机连 ORT 的 CUDA EP 都载入失败（C3/C4 两次实测）。在写任何一行接入代码之前，先把"能不能做"变成**每条都带一手来源的结论**：硬件与传输能力实测、cuDNN 缺口的准确形态、FFmpeg 与 Video Codec SDK 的许可边界、以及候选数据集的许可与字段（**修订**：ADR-0013 落地后评分在观察空间，故**不再要求相机标定**，只需 2D 框 + 帧序列）。

## 2. 数据结构

无。新增产物只有一份 research note 与票据更新。

## 3. 关键机制

- **探测而非假设**：硬件能力用仓库自有 `runtime_probe --json` 实测（CUDA 驱动/运行时版本、设备、H2D/D2H 带宽），不引用旧文档；缺口用文件系统核验（头文件、运行时 DLL）。
- **许可只认一手来源**：FFmpeg → `ffmpeg.org/legal.html`；NVIDIA SDK → 官方 license agreement；数据集 → 官方 terms of use。每条结论标注"已核验（来源）/ 未核验（待办）"，**不把博客或经验帖当依据**。
- **传输带宽是零拷贝主张的分母**：实测 H2D/D2H 的 p50 带宽，据此算出"一帧 1080p 少一次往返能省多少 ms"——D5 的判据需要这个数才谈得上"下降百分比"。

## 7. 偏差与扩展记录

1. **「CPU 对照基线冻结」无法在本片完成**：基线的定义是"解码→推理路径"的拷贝字节数/p95，而解码路径要到 D5 才有。本片只交付**传输带宽基线**（H2D/D2H 实测），把逐路径基线移到 D5 的前置测量里。原 AC 是我写票时的排序错误，在此更正。
2. **「构建级证明」延后到 D5**：默认 OFF 的开关要有依赖可关才有意义；现在加一个空的 `OW_WITH_NVDEC` 只会给构建系统增加无用的分支。保留结论：接入时必须与 `OW_WITH_ONNXRUNTIME` 同构（ADR-0012 先例）。
3. **数据集要求被 ADR-0013 简化**：不再需要相机标定与 3D 标注——评分在观察归一化空间完成。这把候选集从"KITTI 类"扩大到"任何带 2D 框的数据集"，也解掉了"带标定的数据集几乎都是非商业许可"的死结。
4. **NVDEC 会话数/格式限制未实测**：本机无 SDK，只能到"驱动与设备可用"这一层。结论里明确写"未核验"，留 D5 补测。
