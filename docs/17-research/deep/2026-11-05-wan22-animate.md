## 0. 摘要

Wan2.2-Animate（论文名 Wan-Animate）是阿里 Wan 团队的开源角色动画模型：给定角色图 + 驱动视频，同一模型完成「角色动画」（复现驱动视频的动作与表情）与「角色替换」（换人并适配场景光照）（[P 摘要]；许可/硬件见 [卡§3/§4](../projects/wan22-animate.md)）。**核心原理一句话**：在 Wan-I2V 的 DiT 基座上后训练，把参考图外观、时间引导帧与待生成区域统一进 Wan-I2V 原有的 noise latent / conditional latent / binary mask 三元输入，再并联骨架（加性注入）与人脸隐式特征（cross-attention 注入）两路控制信号。

最关键的三个机制：

1. **统一输入范式**：参考图 latent 拼在序列**时间维最前**（而非作首帧），mask 区分保留/生成；Animation 模式目标条件零填充 + mask=0（全帧生成），Replacement 模式条件为人物置零的环境帧 + mask 在人物区为 0。不破坏 Wan-I2V 输入结构 ⇒ 后训练分布偏移最小（[P§3.2]）。
2. **身体/表情双通道解耦**：ViTPose 骨架经空间对齐渲染、Wan-VAE 编码、专用 Conv3d patchify 后**加到** noise latents（reference 帧除外）；表情不用 landmarks，用 LIA 式编码器把 512×512 驱动脸压成逐帧 512 维向量（QR 正交基投影），因果卷积时间对齐后由每 5 层共 8 处 FaceBlock 注入（[P§3.3] + [C]）。
3. **Relighting LoRA**（替换专属）：基座管外观一致、LoRA 管光照适配，训练对由 IC-Light 合成（[P§3.4]）。

对本项目的意义：pose/face/mask/bg 四路条件接口是路线笔记 §6「运动数据层」的典型下游消费者，其「reference latent = 身份单一来源、mask = 空间 ownership、关键点置信度门槛」与 World Contract 逐轴同构（§4）；帧级不确定 + 分钟级延迟 + 预处理外置 ⇒ 只能作侧项目的生成后端/评测对象，进不了 Grounding Loop（[卡§6](../projects/wan22-animate.md#6-与-omniworld-的边界--族谱归宿)）。

## 2. 原理详解

### 2.1 架构总览：从 DiT 到 Wan-I2V，Animate 改了什么

**（a）DiT 视频生成范式（Wan 基座，[W§4.2.1] + [D]）**

Diffusion Transformer 的要点是用纯 transformer 替换 U-Net 主干、直接在 latent patch 序列上做扩散（[D]："a transformer that operates on latent patches"；scale 越大 FID 越好的 scaling 结论亦出自 [D]）。Wan 的具体实现分四步，全部在官方源码可对照：

1. **3D causal VAE（Wan-VAE）压缩**：视频 `V∈R^((1+T)×H×W×3)` 压到 `x∈R^((1+T/4)×H/8×W/8)`、16 通道——时间 4×、空间 8×8；首帧只做空间压缩（"1+T" 结构，兼顾图像数据与时间因果性，following MagViT-v2）；用 RMSNorm 替换 GroupNorm 保因果，127M 参数，feature cache 机制支持任意长视频分块编解码（[W§4.1]）。
2. **Patchify**：kernel/stride 为 (1,2,2) 的 3D 卷积把 latent 变成 token 序列，`L=(1+T/4)×H/16×W/16`（[W§4.2.1]；[C:model.py:378-379,448-457] `patch_embedding = nn.Conv3d(in_dim, dim, kernel_size=patch_size, stride=patch_size)`）。
3. **40 层 transformer block（14B）**：每块 = full spatio-temporal self-attention（全序列非因果，RoPE 三轴分频 [C:model.py:39-66]）+ cross-attention 注入 umT5 文本嵌入（512 token）+ FFN；条件调制用**共享 adaLN**：共享 MLP（`time_projection`）从时间嵌入预测 6 个调制参数、每块只学一组 bias（`modulation` 参数），省约 25% 参数（[W§4.2.1]；[C:model.py:216-217,384-386,462-468]）。
4. **Flow matching 训练 + ODE 采样**：Rectified Flow 线性插值 `x_t = t·x_1 + (1−t)·x_0`，速度目标 `v_t = x_1 − x_0`，MSE 损失，logit-normal 时间步采样（[W§4.2.2 式(1)–(3)]）；Animate 推理默认 Flow-DPM++ 20 步、shift 5.0，或 UniPC（[C:wan_animate_14B.py:35-36; animate.py:485-504]）。

**（b）Wan-I2V 的输入三元组——Animate 一切改造的起点（[W§5.1.1]）**

Wan-I2V 把 I2V 定义为"从给定首帧生成视频"：条件图与零帧沿时间维拼接 → VAE 编码成条件 latent `z_c`（16ch）；二值 mask `M∈{0,1}` 标注保留帧（1）/生成帧（0），按 VAE 时间步幅 s=4 重排成 4 通道；noise latent `z_t`（16ch）。三者**通道维拼接**（16+16+4=36 通道）进 DiT，另加一个 zero-init 投影层承接多出的通道；条件图还经 CLIP 图像编码器提特征、三层 MLP 投影后以 decoupled cross-attention 注入作全局上下文（[W§5.1.1]）。

**（c）Animate 在基座上加了什么（[P§3] + [C] 全量对照）**

| 组件 | 出处 | 作用 |
|---|---|---|
| `pose_patch_embedding`：Conv3d(16→5120, kernel=(1,2,2)) | [C:model_animate.py:292-294] | 骨架 latent 的专用 patchify + 投影，加性注入（§2.3） |
| `motion_encoder`：LIA 式 Generator(size=512, style_dim=512, motion_dim=20) | [C:model_animate.py:327; motion_encoder.py:295-307，文件头注明 "Modified from wyhsirius/LIA"] | 驱动脸 → 逐帧 512 维运动向量（§2.4） |
| `face_encoder`：FaceEncoder（因果 Conv1d ×3，stride 1/2/2） | [C:model_animate.py:334-338; face_blocks.py:129-176] | face 向量时间下采样 4×，与 DiT latent 轴对齐（§2.4） |
| `face_adapter`：FaceAdapter = 8 个 FaceBlock | [C:model_animate.py:328-332 `num_adapter_layers=self.num_layers // 5`] | 每 5 层注入一次表情特征（§2.4） |
| `img_emb`：MLPProj(1280→5120) + cross-attention 的 `k_img/v_img` | [C:model_animate.py:88-146,322,422-424] | Wan-I2V 遗产的 CLIP 全局上下文分支（条件图 257 个 CLIP token） |
| PeftAdapterMixin + `relighting_lora.ckpt` | [C:model_animate.py:246; wan_animate_14B.py:15] | 替换模式光照适配（§2.5） |

**dense 单模型的 config 硬对照**：`wan_animate_14B.py` 只有单一 transformer 配置（dim 5120 / ffn 13824 / 40 层 / 40 头 / window_size=(-1,-1) 全局注意力）；对照同仓库 `wan_i2v_A14B.py`（Wan2.2 的 A14B MoE 双专家）有 `low_noise_checkpoint` / `high_noise_checkpoint` / `boundary = 0.900` 三行而 Animate config 没有（[C:wan_animate_14B.py vs wan_i2v_A14B.py]）。Animate-14B 是 **dense 单模型 + 20 采样步 + CFG=1.0 + 30fps**（[C:wan_animate_14B.py:35-39]），A14B 家族是双专家 + 40 步 + CFG 3.5。这把事实卡 §1 的"形态上更像单模型"推断升级为 config 级证据。

**（d）数据流总览（一段生成的完整路径）**

```
驱动视频 ──预处理──▶ src_pose.mp4 ──Wan-VAE──▶ pose_latents ──Conv3d patchify──┐(加到 noise 帧位 1..20)
        └──────────▶ src_face.mp4(512×512 脸) ──LIA──▶ 512 维/帧 ──因果Conv1d 4×──┐(cross-attn，帧位 1..20)
角色图 ─────────────────────▶ Wan-VAE ──▶ ref_latent（序列帧位 0，mask=1）
（替换模式另加）src_bg.mp4 + src_mask.mp4 ──▶ 目标段条件 latent + 4 通道 mask
noise [16, 21, H/8, W/8] ⊕ 条件 y [20, 21, H/8, W/8] ──通道拼接 36ch──▶ 40 层 DiT ──▶ 预测速度 ──20 步 ODE──▶ 解码（丢帧位 0）
```
（[C:animate.py:406-637] 逐行可对照；帧位标注依 [C:model_animate.py:342-343 `x_[:, :, 1:] += pose_latents_`] 与 [C:animate.py:637 `self.vae.decode([x0[0][:, 1:]])]`。）

### 2.2 统一输入范式：reference latent / temporal latents / mask 如何编码两个任务

**怎么做**（[P§3.2]；[C:animate.py:406-581]）

1. **序列结构**：noise latent 形状 `[16, lat_t+1, lat_h, lat_w]`——比目标视频多出的**第 0 个 latent 帧位留给参考图**（[C:animate.py:463-464 `lat_t = T // 4 + 1; target_shape = [lat_t + 1, ...]`]，T=77 → 21 个 latent 帧位 = 1 参考 + 20 目标）。参考图单独经 Wan-VAE 编码成 `ref_latents`，其 mask 全 1（保留）；条件张量 `y` = [mask 4 通道 ‖ 条件 latent 16 通道]，与 noise 在**时间维拼接**后随模型输入做通道拼接（[C:animate.py:512-517,580-581; model_animate.py:388-389]）。
2. **temporal latents（长视频句柄）**：第 2 段起，把**上一段输出的最后 1 或 5 帧**（`refert_num`，代码 assert 只允许 1 或 5）作为条件帧填入目标段开头，对应 mask=1 整帧；训练时以随机概率使用（probabilistic training strategy），让模型学会在不同条件组合下平衡生成能力（[P§3.2]；[C:animate.py:351,428-436]）。
3. **Animation 模式的目标段条件**：零填充（`torch.zeros(3, T, H, W)` 编码），mask=0 → 整帧自由生成，背景继承自参考图——"analogous to the standard I2V mode"（[P§3.2 Environment Formulation]；[C:animate.py:567-578]）。
4. **Replacement 模式的目标段条件**：把驱动视频逐帧分割出人物、人物区域置零得到 environment 帧作为条件内容；mask 在环境区=1、人物区=0 → 模型只在 mask=0 的区域生成，原背景保留（[P§3.2]；代码：[C:animate.py:550-566] `y_reft = vae.encode(bg)`、mask 通道取 `1 − mask_video`，即 mask 视频白色（人物）→ 0（生成）、黑色（背景）→ 1（保留）——与 diffusers 文档"黑=保留、白=生成新角色"一致，[卡§5]）。
5. **输出裁剪**：denoise 对整段（含 reference 位）输出，解码时 `x0[:, 1:]` 丢掉 reference 位；第 2 段起再丢掉开头 `refert_num` 帧（时间引导位被重复生成），余下拼接成长片（[P§3.6 Long Video]；[C:animate.py:637-647]）。

**为什么这样设计**（[P§3.2]）

- **最小分布偏移**：论文原话 "this approach preserves the original input structure of Wan-I2V, thereby minimizing distributional shift during post-training"（[P§1]；§3.2 结尾另有 "This adaptability allows the model to be fine-tuned rapidly and effectively during post-training"，[P§3.2]）。条件 latent + 二值 mask 的通道拼接是 Wan-I2V 预训练时已经学会的"语言"，Animate 只是**改变各帧位里填什么**（参考图放序列头、驱动信号走旁路），让后训练收敛快、总训练量省。
- **任务统一**：Animation 与 Replacement 的差别被压缩成"目标段条件填零还是填环境帧 + mask 是全 0 还是人物区 0"——同一符号表示、同一模型联合训练（仅 Relighting LoRA 是 replacement 专属附件），"reducing redundant training efforts"（[P§3.2]）。
- **参考图≠首帧的语义转变**：I2V 里图像是内容起点（生成的第一帧），Animate 里它是**外观引用**——生成内容"dictated by driving signals, not initiated from the character image itself"（[P§3.2]）。放在序列头（而非通道拼接）使参考帧与目标帧共享同一套时空 self-attention，外观信息可以按注意力自然流向目标帧——这是"利用 Wan 预训练的帧间一致性能力"的设计（论文："To fully leverage the inter-frame consistency capabilities pre-trained in the Wan model, the reference latent is concatenated with the conditional latents along the temporal dimension"，[P§3.2 Reference Formulation]）。

**代价是什么**

- **计算冗余**：每段 denoise 都携带 reference 帧位且对其完整输出后丢弃（[C:animate.py:637]）；每段 78 帧里 1 帧纯为外观锚定服务。
- **长视频一致性受限**：段间只靠 1/5 帧条件传递，任何跨段外观/光照漂移都无法被模型自身修正——论文未给漂移定量数据（**推断**：滑窗误差累积是逐段扩散生成的通病，依据是段间信息带宽仅 1–5 帧，[P§3.6]）。
- **段长与填充的硬约束**：`clip_len` 须为 4n+1（VAE 1+T/4 结构决定，[C:animate.py:320-322 docstring]）；驱动视频不足整段时用**回弹重复（ping-pong）**填充到段边界（[C:animate.py:201-213 `inputs_padding`]）——片尾动作会往返重复，这是官方代码内建的行为而非可选项。
- **mask 粒度权衡**（替换模式）：官方 UserGuider 明示——小而细的 mask 保背景多但"可能限制角色生成区域（外观差异可导致 shape leakage）"；大而粗的 mask 生成自由但"包含更多背景、可能影响背景一致性"，需按素材调参（[C:UserGuider.md §2.3]）。

### 2.3 身体控制：空间对齐骨架 + Body Adapter 加性注入

**怎么做**（[P§3.3 Body Control]；[C:UserGuider.md / process_pipepline.py / model_animate.py]）

1. **提取**：驱动视频逐帧经 YOLOv10m 行人检测 + **ViTPose-H wholebody**（ONNX）得 2D 关键点（[C:UserGuider.md §2.1 目录结构 `pose2d/vitpose_h_wholebody.onnx` + `det/yolov10m.onnx`]；论文称训练时骨架 "extracted using VitPose"，[P§3.3]）。角色图同样跑一次姿态检测（retarget 的比例参照，[C:process_pipepline.py:135]）。
2. **Retargeting（animate 模式建议开启）**：按两角色对应肢体长度比缩放目标骨架骨长，并平移对齐角色位置——参考点按景别取（全身=脚、半身/肖像=颈）（[P§3.6 Pose Retargeting]）。因为 2D 骨架的骨长受姿态影响，提供辅助方案：用 **FLUX.1-Kontext-dev** 把角色图与驱动首帧都编辑成标准 T-pose（代码按臂/腿可见性生成三种 prompt，[C:process_pipepline.py:237-277]），再从 T-pose 图量骨长算缩放因子，"in most scenarios, this approach leads to more accurate retargeting"（[P§3.6]）。
3. **渲染成空间对齐信号**：retarget 后的骨架画在**零底 canvas** 上，canvas 尺寸对齐参考图（`canvas = np.zeros_like(refer_img)`），即骨架帧与目标视频帧同分辨率同坐标系——"spatially-aligned" 的落地（[C:process_pipepline.py:218-228]）；产物 `src_pose.mp4`。
4. **注入**：`src_pose.mp4` 经**同一个 Wan-VAE** 编码成 16 通道 latents（与视频 latent 同空间，[C:animate.py:508-510]）；模型内由专用 `pose_patch_embedding`（Conv3d 16→5120）patchify 后**逐元素加到** noise latents 的第 1..N 帧位——`x_[:, :, 1:] += pose_latents_`，**reference 帧位（索引 0）不加**（[C:model_animate.py:340-343]）。

**为什么这样设计**（[P§3.3]）

- **骨架 vs 3D SMPL 的取舍**：骨架泛化性好（"particularly for non-humanoid characters with unconventional shapes"）、对关键点缺失更鲁棒；SMPL 对复杂姿态的肢体关系更精确但 extremity 不精、非人形捕捉差，且**渲染的 SMPL 图带体型信息**——"This can cause the model to rely on the shape cues embedded within the motion signal, which complicates the learning of identity consistency, especially if the SMPL shape is not accurate"（[P§3.3]）。结论："we adopt the skeleton-based representation… as it better caters to the majority of mainstream use cases"。
- **加性注入的合理性**：空间对齐信号与 noise latent 逐元素对应，论文原话 "As this signal is spatially aligned, it is injected by being added to the initial noise latents"（[P§1]）；§3.3 的机制句为 "We use a projection layer to patchify the pose latents and add them to the patchified noise latents"（[P§3.3]）。机制上（**推断**，依据如下）这是三条经典条件注入路径（通道拼接 / ControlNet 式旁路 / cross-attention）之外最轻的一条：骨架经同一 VAE 编码后与 noise 同空间同尺度，加法即"骨架决定初始噪声的结构"，无需新增注意力或通道——通道拼接已被子 DiT 的 36 通道输入占满（那是条件帧/mask 的位置），旁路网络会引入 Animate 想避免的额外训练量。
- **reference 帧不加 pose**：论文原话 "the reference latent is not injected with pose information. This design choice serves to temporally differentiate the reference latent from the target latents"（[P§3.3]）——参考帧在序列里的"角色"是外观引用，混入姿态会污染这一语义。

**代价是什么**

- **2D 骨架的表达上限**（论文承认）："it faces challenges in representing complex motions due to spatial ambiguity and is susceptible to issues like missing or erroneous keypoints"（[P§3.3]）——肢体前后遮挡关系（如交叉手臂谁在前）在 2D 骨架里丢失，复杂动作靠生成模型自行脑补。
- **预处理栈外置且必跑**：姿态检测→retarget（可选 Flux 编辑）→骨架渲染→VAE 编码，全部在 DiT 之外；输入不能是原始视频（diffusers 文档原话，[卡§2](../projects/wan22-animate.md#2-边界与限制) 已引）。换驱动视频必须重跑整条预处理。
- **retarget 质量依赖上游**：简化版 retargeting 官方声明 "NOT guaranteed to be perfect"，建议逐帧人工检查中间产物；FLUX.1-Kontext 的 T-pose 编辑同样 "NOT guaranteed"（[C:UserGuider.md §1.1/§2.2]）。基本 retarget 还要求参考图与驱动首帧均为正面舒展姿态（[C:UserGuider.md §2.2]）。
- **替换模式禁用 retarget 的副作用**：为不破坏人物与环境的交互关系，replace 模式 "we do not recommend using pose retargeting"——体型差异大的角色替换会出现形变，论文列为明确 limitation（[P§3.6]；[C:UserGuider.md §1.2 WARNING]）。

### 2.4 表情控制：LIA 隐式面部特征 + Face Blocks 时间对齐 cross-attention

**怎么做**（[P§3.3 Face Control + Figure 3]；[C:motion_encoder.py / face_blocks.py / model_animate.py / process_pipepline.py]）

1. **驱动脸裁剪**：用骨架的面部关键点定人脸框（scale 1.3），逐帧裁出并 resize 到 **512×512**（[P§3.3 "Input face images are resized to 512×512"]；[C:process_pipepline.py:170-176 `get_face_bboxes(meta['keypoints_face']...)` → `cv2.resize(..., (512, 512))`]）。产物 `src_face.mp4`。
2. **逐帧压成 1D 隐向量（身份剥离的第一步）**：512×512 人脸经 **LIA 式编码器**（[C:motion_encoder.py 文件头 "Modified from https://github.com/wyhsirius/LIA"]；论文："an encoder structure identical to that of Wang et al. (2022)"，即 Latent Image Animator，[P§3.3]）编码：卷积金字塔逐级下采样 → 4×4 特征图 → EqualConv2d 压成 **512 维向量**；再经 MLP 头压成 **20 维运动码**，投影到一个 **512×20 可学习基矩阵的 QR 正交化基**上（`Direction` 模块，`custom_qr`），得到逐帧 512 维运动向量（[C:motion_encoder.py:205-243,271-307]）。这正是论文说的两件事："We spatially compress the facial image into a 1D latent, which reduces the storage of low-level, identity-specific information" 与 "We also employ Linear Motion Decomposition to orthogonalize these features"（[P§3.3]）。
3. **时间对齐**：FaceEncoder 用**因果 Conv1d**（stride 1→2→2，时间下采样 4×）把逐帧 face 向量压到与 Wan-VAE latent 轴同长，每 latent 帧得到 4 个头向量 + 1 个学习到的 padding token（[C:face_blocks.py:112-176 `CausalConv1d` / `padding_tokens`]）；模型侧在时间维**前面补一个零向量**（`pad_face`），使 face 信号从帧位 1 开始——与 pose 一样对齐"帧位 0 = reference 无运动信号"（[C:model_animate.py:355-361]）。
4. **注入：8 处 FaceBlock**：`after_transformer_block` 在 `block_idx % 5 == 0` 的层（0,5,10,15,20,25,30,35，共 8 处）执行 `face_adapter.fuser_blocks[block_idx // 5]` 并残差相加（[C:model_animate.py:364-369]；论文："we perform this injection every 5 layers in the 40-layer Wan-14B model, resulting in a total of 8 injection layers"，[P§3.3]）。FaceBlock 本体是 cross-attention：Q 来自 DiT 隐状态、K/V 来自 face tokens；关键 reshape `q: B (L S) H D → (B L) S H D`、`k/v: B L N H D → (B L) N H D` 把注意力**限制在同一 latent 帧内**——第 L 个 latent 帧的空间 token 只能看到第 L 帧的 face token（[C:face_blocks.py:334-378]）。这是论文 "a temporally-aligned cross-attention mechanism, where the attention computation is confined to the corresponding set of tokens at each timestep"（[P§3.3]）的代码形态。
5. **身份剥离的第二步（训练侧）**：对 face 图做 scaling / color jitter / random noise 增强，"introduces deliberate discrepancies between the augmented face and the target face, discouraging the model from overfitting to identity features"（[P§3.3]）。因为训练是自监督（驱动视频=目标视频），不剥离身份就会 identity leakage。
6. **CFG 只作用于 face（视觉条件）**：默认 `guide_scale=1.0` 单次前向；开启时无条件分支把 `face_pixel_values` 全置 −1（空白脸），pose/条件帧/参考分支全部保留——文本侧则换成负提示词 `context_null`（[C:animate.py:592-601 `face_pixel_values_uncond = face_pixel_values * 0 - 1` 且 `"context": context_null`]；[C:wan_animate_14B.py:37]）——论文 "CFG can be optionally enabled for the face conditioning input to adjust the reenactment effect"（[P§4.3]）。

**为什么这样设计**（[P§3.3]）

- **不用 facial landmarks**：dense landmarks 提取"can lose fine-grained details… making it difficult to fully replicate the expressiveness"，且密集信号对精度要求高——跨身份场景脸形差异大时，landmark retarget 的误差"can severely compromise identity consistency"（[P§3.3]）。直接用原图 "to preserve maximum detail"（[P§1]）。
- **隐式特征而非像素**：512×512 → 512 维的空间压缩**结构性地**丢掉像素级身份细节（皱纹、痣的精确位置），保留运动语义；正交基投影让 20 维运动码各方向解耦（LIA 的设计目的），进一步把"表情"与"长相"分离。
- **稀疏注入省算力**："To reduce the computational load, we opt to inject face information only into specific layers"（[P§3.3]）——8/40 层的注入密度是算力取舍。

**代价是什么**

- **依赖裁剪质量**：face 分支的入口是骨架驱动的 bbox 裁剪——头部检测失败/出画即表情信号丢失（预处理前置依赖，[C:process_pipepline.py:170-176]）。
- **解耦是"抑制"而非"保证"**：论文的措辞是数据增强 "discouraging the model from overfitting to identity features"（[P§3.3]）——身份泄漏风险被压制但无结构性消除；跨身份驱动时表情向量仍可能携带驱动者的微观身份痕迹（**推断**：机制上 512 维向量由共享编码器产生，未做对抗式身份剥离；依据 [C:motion_encoder.py] 无任何 identity 对抗分支）。
- **时间分辨率 4× 粗化**（**推断**，依据 [C:face_blocks.py:135-139] 两次 stride-2 因果卷积）：face 信号在 latent 轴上的时间步长是原始帧的 4 倍（30fps 下约 7.5fps 的表情控制带宽），极快表情（2–3 帧的眨眼）的逐帧差异在 latent 层被平均——论文未讨论此点。
- **多一次前向**：开 CFG 表情精调时延迟近似翻倍（两次 DiT 前向，[C:animate.py:609-623]）。

### 2.5 替换模式与 Relighting LoRA：一致性 vs 光照适配的解耦

**怎么做**（[P§3.4]；[C:process_pipepline.py:280-343 / animate.py:179-189 / animate_utils.py:7-19]）

1. **人物分割**：SAM2 视频预测器（`sam2_hiera_large.pt`）+ **骨架关键点作正点提示**——每 400 帧一块、每块选 4 个关键帧，用 8 个身体关键点（索引 [0,1,2,5,8,11,10,13]：鼻/肩/髋/踝——躯干两端加双踝；`keypoints_body` 为 20 点 AAPose 格式，由 `split_kp2ds_for_aa` 从 wholebody 输出重排而来，[C:pose2d_utils.py:1102-1103]；打点处 [C:process_pipepline.py:302]）打点后全段传播（[C:process_pipepline.py:280-343 `get_mask`]）。mask 后处理：`get_mask_body_img`（iterations=3, k=7 外扩）+ `get_aug_mask`（w_len/h_len 网格粗化）→ 白=人物（生成区）、黑=背景（保留区）→ `src_mask.mp4`；`bg = frame × (1−mask)` 得人物置零的环境帧 → `src_bg.mp4`（[C:process_pipepline.py:97-124]）。mask 策略沿用 Animate Anyone 2（[P§3.2 "Following the mask formulation strategy from Hu et al. (2025)"]）。
2. **推理时的条件组装**：见 §2.2 第 4 条——`y_reft = VAE(bg)`，mask 通道 = `1 − mask_video`（[C:animate.py:550-566]）。
3. **Relighting LoRA**：rank=128、alpha=128、gaussian init，经 peft `add_adapter` 挂载（[C:animate.py:179-189; animate_utils.py:13-19]）。**训练数据构造**：从视频 clip 采一帧作参考图 → 分割裁出人物 → **IC-Light** 把人物合成到随机新背景（人物光照/色调被新背景影响，与原视频序列形成光照差）→ 以合成图为 reference、原视频为目标训练，LoRA 学会"保持角色外观一致的同时施加环境光照与色调"（[P§3.4 + Figure 4]）。

**为什么这样设计**（[P§3.4 + §5.4 ablation]）

- **两个目标天然冲突**："Strictly maintaining appearance consistency can lead to a mismatch between the animated character's lighting and color tone and those of the new environment"（[P§3.4]）。基座的训练目标（animate 模式）就是外观一致；光照适配直接混进基座训练会互相拉扯。
- **LoRA 作为可开关的加性模块**：基础模型保一致性、LoRA 加光照灵活性——"adds a degree of flexible adaptability on top of the strong consistency requirement"（[P§5.4]）；animation 模式不加载 LoRA、行为不受影响（[C:animate.py:50 `use_relighting_lora=False`]）。消融证据：无 LoRA 时角色光照与参考图强一致但与环境不协调；有 LoRA 时融合更真实"without breaking the character's perceptual identity"（[P§5.4]）。
- **IC-Light 合成对**：不用真实重打光数据（拍摄成本高），借 IC-Light 的光照编辑能力低成本制造"同角色、异光照"配对——训练信号即"把 reference 的光照改成 bg 的光照"（[P§3.4]）。

**代价是什么**

- **mask 调参负担转移给用户**（[C:UserGuider.md §2.3]）：`iterations/k`（外扩量）与 `w_len/h_len`（粗化粒度）需要按素材手调——细 mask 保背景但有 shape leakage 风险，粗 mask 伤背景一致性。
- **单人视频假设**：mask 提取流程 "designed for single-person videos ONLY"，多人视频关键点跟踪会错（[C:UserGuider.md §1.2 WARNING]）。
- **不 retarget 的形变**（§2.3 已述，[P§3.6]）。
- **论文与开源代码的 target 范围差异**（来源矛盾，如实记录）：论文说 LoRA "applied exclusively to the self-attention and cross-attention layers within the DiT blocks"（[P§3.4]）；开源推理代码 `get_loraconfig` 把 `blocks` 内**所有** `nn.Linear`（排除 face 模块与 `modulation` 参数）都列为 target——包含 FFN 的两个 Linear（[C:animate_utils.py:9-11]）。训练代码未开源，无法判定论文口径与训练实现谁准（**UNVERIFIED**，见 §5）。影响：若复刻 relight 能力，target 选择需自行消融。
- **合成域差距**（**推断**）：IC-Light 的重打光分布与真实片场光（多光源、遮挡阴影、镜面反射）存在域差距；论文未给出真实光照场景的量化评估（依据：[P§3.4/§5.4] 只有定性消融图）。

### 2.6 训练课程与推理工程

**怎么做——五阶段课程**（[P§3.5]）

| 阶段 | 训练内容 | 关键设置 |
|---|---|---|
| 1 Body Control | 仅 Animation 模式、仅身体信号（无 face 注入） | 先学会新输入范式（reference/temporal 帧位配置）+ 骨架对齐 |
| 2 Face Control | 引入 Face Adapter + Face Block | 部分参数用 LIA 预训练编码器权重初始化；**portrait 数据为主**（脸部动态占主导）；用 landmarks 定位头/眼/嘴区域施加更高 loss 权重 |
| 3 Joint Control | 阶段 2 的 face 模块 + 阶段 1 主模型联合 | 全数据；实验发现 face 模块单训后已具备强表情驱动，全模型快速收敛 |
| 4 Joint Mode | 数据扩展到 Animation + Replacement 两种格式 | 因输入范式与 Wan-I2V 预训练兼容，"this transition is remarkably smooth" |
| 5 Relighting LoRA | 仅 replacement 的光照能力 | IC-Light 数据对（§2.5） |

**为什么课程化**（[P§5.4 ablation]）：消融对照（从头联合训练全部控制模块）结果是"表情驱动不准、模型难收敛"。论文归因两条：身体动作更复杂、先学身体对齐能促进后续表情学习；脸在一般数据里占比小、portrait 数据（脸占比大）显著加速表情模块收敛。

**推理工程**（[P§3.6/§4.3/§4.2]；[C:wan_animate_14B.py / animate.py]）

- **分段**：每段 78 帧 = 1 个静态保留的 reference 帧位 + 77 个目标帧（77=4×19+1）；非首段用 1 或 5 帧（1 或 2 个 latent）作 temporal guidance，来自上段结尾；输出裁剪后拼接（[P§4.3 + §3.6]；[C:animate.py:351,397-436,637-647]）。
- **分辨率**：支持任意分辨率——按 patchify 后 token 总数逼近 1280×720 的目标 token 数来选；Animation 模式纵横比随角色图、Replacement 随驱动视频（[P§4.3]）。
- **采样**：Flow-DPM++（默认）或 Flow-UniPC，20 步，shift 5.0，CFG 默认 1.0（关闭）（[C:wan_animate_14B.py:35-37; animate.py:485-504]）。注意 Animate 用 **30fps**（`sample_fps=30`），不同于 Wan 共享 config 的默认 16fps——预处理按此重采样驱动视频（[C:wan_animate_14B.py:39 vs shared_config.py:18; process_pipepline.py:57-62]）。论文正文未提帧率数字，30fps 来自 config（代码事实）。
- **训练并行**：DiT 与 T5 用 FSDP、其余 DP；DiT 叠加 2D Context Parallelism（外层 RingAttention + 内层 Ulysses，同 Wan 主模型）；face 特征提取按 Ulysses 组把单视频的人脸帧当 batch 并行（[P§4.2]）。
- **文本控制地位**：训练数据用 QwenVL2.5-72B 生成描述，但 "the motion signal is the dominant control factor, making text control a non-core feature. In practice, we recommend using a default text prompt"（[P§4.1]）——官方 config 的默认 prompt 即一句中文「视频中的人在做动作」（[C:wan_animate_14B.py:40]）。

### 2.7 为什么这个架构适合角色动画、不适合通用编辑

这是把 §2.2–2.5 的设计选择放在一起看的必然结论，三条结构性理由：

1. **控制信号是"人形中心"的，编辑需要"语义中心"的信号**。Animate 的全部条件接口都以"画面里有一个可检测的人"为前提：骨架来自 ViTPose（人体关键点检测，[C:UserGuider.md §2.1]）、表情来自人脸裁剪（[C:process_pipepline.py:170-176]）、mask 来自"分割出人物"（SAM2 + 人体关键点提示，[C:process_pipepline.py:280-343]）。通用编辑（改任意物体、换风格、按指令增删对象）没有对应入口——模型没有接受过"任意区域 + 指令"的条件训练。
2. **对照实验就在同门**：VACE 是 Wan 系的通用可控生成/编辑模型（"Reference-to-video generation、Video-to-video editing、Masked video-to-video editing" 三类任务、Video Condition Unit 统一接口，[V 摘要]），其输入表示（任意帧序列 + 任意 mask 的 VCU）才是通用编辑的形状。而 Wan-Animate 论文的定性对比明说：Animation 模式下 VACE "being a general-purpose controllable video generation model, shows instability in character animation tasks"；Replacement 模式下 VACE "has issues with identity consistency… highly dependent on parameter tuning, resulting in a higher barrier to entry"（[P§5.3]）。反之亦然：Animate 没有提供 VACE 式的任意编辑语义。两者是**同一基座上的两个特化方向**——Animate 把条件空间收窄到"人"换取角色任务的稳定性与易用性。
3. **它是"重新生成"不是"编辑"**：替换模式下人物区域是**整段重新去噪生成**的（mask=0 区域自由生成，[P§3.2]），身份靠 reference latent 锚定、背景靠 mask 保留——这与 inpainting 式编辑同构，但生成自由度被骨架/表情信号强烈约束（人物姿态必须跟骨架走）。77 帧滑窗（[P§4.3]）与段间仅 1/5 帧衔接（§2.2）进一步使它不适合需要全局时间一致性的通用编辑任务。论文自己的能力清单也全部围绕角色：Performance Reenactment / Cross-Style Transfer / Complex Motion Synthesis / Dynamic Camera Movement / Character Replacement（[P§5.5]）。

## 3. 能力边界与工程现实

**官方承认的机制性限制**（论文/官方文档原文；事实卡层面的边界不在此重复，见 [卡§2](../projects/wan22-animate.md#2-边界与限制)）：

| 限制 | 出处 |
|---|---|
| 输入不能是原始视频，姿态/面部预处理必须在模型外完成（diffusers 侧截至核验日未集成预处理） | [卡§2 引 diffusers 文档] |
| 2D 骨架的空间歧义 + 关键点缺失/错误敏感性 | [P§3.3] |
| 替换模式不做 pose retargeting → 体型差异大时形变 | [P§3.6]；[C:UserGuider.md §1.2 WARNING] |
| mask 提取仅支持单人视频 | [C:UserGuider.md §1.2 WARNING] |
| retargeting 简化版与 FLUX T-pose 编辑均"NOT guaranteed" | [C:UserGuider.md §1.1/§2.2] |
| 文本控制非核心，建议默认 prompt | [P§4.1]；[C:wan_animate_14B.py:40] |
| 不建议与 Wan2.2 训练的 LoRA 混用 | [卡§2 引 README] |
| 长视频滑窗：段间仅 1/5 帧条件衔接（漂移无模型内修正机制） | [P§3.6]（定量数据未公布，**推断**为误差累积风险） |

**工程现实**（引擎视角）：

- **确定性**：生成式逐帧扩散 + 随机噪声初始化 ⇒ 同输入不同输出，帧级确定性不成立；与引擎"位级确定性、没有 benchmark 不宣称性能"的纪律冲突——只能作为进程外生成后端/评测对象（[卡§2 推断栏]，本报告源码核验与之相符：noise 由 `torch.randn(generator=seed_g)` 产生、seed 默认 −1，[C:animate.py:353-354,465-475]）。
- **延迟/显存**：14B dense + 20 步 ODE + 78 帧分段 + （可选）双前向 CFG——官方无 Animate 专项显存/耗时数字（[卡§4](../projects/wan22-animate.md#4-硬件要求显存驱动os) 两处核验）；同族 14B 锚点为数十 GB 量级。
- **部署形态**：预处理栈（YOLOv10m + ViTPose-H + SAM2 + 可选 FLUX.1-Kontext）与生成模型是两套独立权重，后者还含 T5-XXL / CLIP-H / Wan2.1-VAE / relighting_lora.ckpt 四个附件（[C:UserGuider.md §2.1; wan_animate_14B.py:10-17]）——接口契约见 [卡§5](../projects/wan22-animate.md#5-可集成接口api--导出--控制面--资产格式)。
- **验收指标缺位**：官方只给 SSIM/LPIPS/FVD 自重建基准与 20 人用户研究（[P§5.1/§5.2]），无可复现的跨身份质量口径——沿用路线笔记 §7 的自测验收（PCK/MPJPE、身份余弦、时序抖动）（[路线笔记§7](../2026-10-27-character-animation-route.md)）。

## 4. 与 OmniWorld 的关系深化（World Contract 四轴）

Animate 的接口契约恰好是 World Contract 四轴的一个"野生对照物"——它用工程约定解决的问题，正是引擎要用契约系统性解决的问题：

- **identity**：参考图 latent 是身份的**单一事实来源**——每个 77 帧段都携带同一个 reference latent（[P§3.2]），身份不随时间演化、不随段切换重述。但段间衔接只有 1/5 帧，身份漂移（色调、服饰细节、脸）在长片里只能靠外部位验（ArcFace/CLIP 余弦，路线笔记 §7）。对照引擎：World Contract 的 identity 要求"实体有稳定 id + 可核验的凭证"；Animate 的机制说明**生成式后端的 identity 是"每段重新证明"的**，接入侧项目时身份核验必须做成逐段闸门而不是一次性的。
- **time**：Animate 内部有两套时间轴——像素域 77 帧 @30fps 与 latent 域 1+T/4 的 20 帧（[C:wan_animate_14B.py:38-39; animate.py:463]）；段间靠 temporal latents 显式传递"上一段的结尾就是下一段的开头"（[P§3.6]）。驱动视频若是 24/25fps，预处理按目标 fps 重采样（[C:process_pipepline.py:57-62]）——**时间基准转换发生在数据层，且必须显式**。这正是路线笔记 §6 运动数据层 `timestamp/frame_index + 时间基准` 字段的必要性实证：不显式定基准，动作整体变速且难察觉。
- **ownership**：二值 mask 就是空间 ownership 的声明——"这些像素归原视频（保留）、那些像素归生成器（重写）"（[P§3.2]；[C:animate.py:550-566]）。它天然是**单写者**的：一个区域只有一个写者，写者之间不协商。这与 World Contract 的 ownership（哪个组件可写哪个状态字段）同构；且 mask 粒度参数（UserGuider §2.3）说明**ownership 边界本身就是可调的系统参数**——引擎里等价于"生成后端允许触碰的状态范围"要在接入时显式划定。
- **confidence**：输入侧有显式置信度（姿态关键点分数，代码里已有 ≥0.75 的门槛用法，[C:process_pipepline.py:243-244]；SAM2 mask logits 阈值 0，[C:process_pipepline.py:334]），低置信度关键点可被下游丢弃——运动数据层"每点置信度"字段（路线笔记 §6）在 Animate 预处理里是真实消费的。但**输出侧没有任何置信度**：模型不告诉你哪帧表情没跟上、哪段身份漂了——输出质量只能靠外部验收指标重构（PCK/MPJPE、身份余弦、时序抖动）。这对引擎的启示：生成式适配器的 confidence 必须由**评测环**在输出端补齐，World Contract 的 confidence 轴不能指望生成后端自带。

结论：Animate 的 pose/face/mask/bg 四路条件接口是"运动数据层"（路线笔记 §6）最典型的下游消费者——运动数据层的字段设计（时间基准、逐点置信度、质量标记）直接决定 Animate 输入的质量上限；而它作为生成后端的一切机制性缺陷（不确定性、无输出置信度、段间漂移）都必须在**侧项目的评测环**里解决，与事实卡 §6 "评测对象的用法" 定位一致（[卡§6](../projects/wan22-animate.md#6-与-omniworld-的边界--族谱归宿)，此处不重复 P2 实验设计）。

## 5. 未解决问题 + 证据缺口
