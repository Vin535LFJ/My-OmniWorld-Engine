## 0. 摘要（给赶时间的人）

GVHMR（浙大 zju3dv，SIGGRAPH Asia 2024）把**单目视频变成世界坐标系下的人体运动序列**：输出 SMPL-X body 参数（局部姿态 θ + 形状 β）、相机系轨迹、以及全局（世界系）轨迹。事实卡 §1 收录其官方能力声称；本报告讲"怎么做到的"。

**核心原理一句话**：不直接在世界系里回归运动，而是把"人的全局姿态"改在一个**逐帧定义的 Gravity-View（GV）坐标系**（由世界重力方向 + 相机视线方向张成）里回归，使学习目标天然重力对齐、逐帧唯一、帧间只剩 1 自由度（绕重力轴 yaw）差异；再用相机相对旋转把 GV 序列**几何展开**回世界系——网络只负责消歧的部分，坐标系换算交给确定性几何。

**最关键的三个机制**：

1. **GV 坐标系解耦**（§2.2）：重力对齐消除了相机 roll/pitch 对学习目标的污染；帧间自由度从 3-DOF 降到 1-DOF，使相机旋转误差的影响降阶——EMDB 上把 VO 旋转换成 GT 陀螺仪，GVHMR 仅 276.5→274.9 mm（几乎不变），WHAM 掉 19.5 mm（论文 §4.2）。
2. **Relative Transformer + RoPE 非自回归主干**（§2.4）：逐帧并行预测（无 RNN 递推），RoPE 相对注意力赋予时间平移一致性，±L 带状注意力掩码让任意长视频一次前向——消融显示去掉 RoPE 全局误差 126.3→304.4 mm（论文 Table 3）。
3. **stationarity 后处理**（§2.7）：网络输出的手/脚静止概率驱动全局平移修正 + CCD-IK 重解局部姿态，脚滑 FS 6.8→3.0 mm——脚滑不是网络自动消掉的，是后处理修的（论文 §3.2/§4.3）。

**对本项目的意义**：GVHMR 是"视频 → 世界坐标 3D 运动"这一级目前最有代表性的开源生产者（研究地图行：`../third-party-research-map.md` GVHMR 行），其输出契约（`smpl_params_incam` / `smpl_params_global` / 逐帧 stationary 概率）与 World Contract 的 time/identity/confidence 同构（§4）。归宿是**②适配器（运动观测生产者）**，非商用许可决定其只存在于独立 Python 环境的可选依赖层——事实卡 §3/§6 权威，不重述。

## 1. 项目定位与生态位（简短）

- **在动作恢复方法谱系里**：GVHMR 是"回归式 + 世界系"路线的代表。与之对照的三条路线：经典 HMR（相机系根节点，见 §2.9）、自回归全局恢复（WHAM：RNN 递推相对运动）、优化式全局恢复（GLAMR/SLAHMR：SLAM + 运动先验优化，SLAHMR 一段视频 >6 小时 vs GVHMR 网络前向 0.28 s，论文 §4.2）。与同期 WHAC/TRAM 的差别：它们把相机系结果转换到世界系还需要精化网络/场景尺度，GVHMR 直接预测（论文 §2）。

## 2. 原理详解

### 2.1 架构总览：两段式——网络回归中间表示 + 确定性几何展开

**问题形式化**（论文 §3）：输入单目视频 {I^t}，输出三组量：
1. SMPL-X 局部姿态 θ^t ∈ ℝ^(21×3) 与形状 β ∈ ℝ¹⁰；
2. 相机系轨迹：全局朝向 Γ_c^t ∈ ℝ³ 与平移 τ_c^t ∈ ℝ³；
3. 世界系轨迹：Γ_w^t 与 τ_w^t。

论文明确指出世界系**不唯一**——"any rotation of W around the gravity direction is valid"（绕重力轴任意旋转都合法）。GVHMR 的解法不是消除这个歧义，而是把它**推迟到最后一步的几何展开**：世界系取第 0 帧的 GV 系（"we use GV_0 as the world reference system W"），网络从头到尾不感知世界系定义。

**全链路数据流**（demo 路径，代码逐站核实）：

```
video ──30fps 重编码──▶ [Tracker: YOLOv8x]──bbx──▶ [ViTPose-H]──kp2d (F,17,3)
   │                                                        │
   └──[Extractor: HMR2 ViT]──f_imgseq (F,1024)              │
   └──[SimpleVO / DPVO / -s 静态相机]──R_w2c──▶ compute_cam_angvel (F,6)
                                   │
                                   ▼
        NetworkEncoderRoPE（12 层 RoPE Transformer，512 dim）
          ├─ pred_x (F,151)：body_pose 126 + β 10 + incam 朝向 6 + GV 朝向 6 + local_transl_vel 3
          ├─ pred_cam (F,3)：弱透视相机（CLIFF 式）
          └─ static_conf_logits (F,6)：6 个手/脚关节的静止概率
                                   │
        EnDecoder.decode ──▶ get_smpl_params_w_Rt_v2（GV→世界系几何展开，§2.5）
                                   │
        pp_static_joint / pp_static_joint_cam + process_ik（后处理，§2.7）
                                   ▼
        hmr4d_results = { smpl_params_incam, smpl_params_global, K_fullimg, net_outputs }
```

来源：`tools/demo/demo.py:98-200`（预处理与 load_data_dict）、`hmr4d/model/gvhmr/gvhmr_pl_demo.py:15-46`（predict 入口）、`hmr4d/model/gvhmr/pipeline/gvhmr_pipeline.py:54-108`（forward 主流程）、`hmr4d/network/gvhmr/relative_transformer.py:109-185`（网络）。

**关键设计立场**：全局恢复不是端到端黑箱。网络只回归三类"消歧中间表示"——GV 系全局朝向、SMPL 局部系根速度、静止概率；从 GV 到世界系的坐标换算（yaw 累积旋转、速度积分、y 轴翻转）全部是**无参数的确定性几何**（`get_smpl_params_w_Rt_v2`，gvhmr_pipeline.py:321-384）。这个拆分是后面所有机制的基础：确定性部分不引入学习误差，学习部分不背坐标系歧义的锅。

### 2.2 Gravity-View 坐标系：相机运动与人体运动的解耦核心

**怎么做**（论文 §3.1 + 源码 `hmr4d/utils/geo/hmr_global.py:7-29` 逐行对应）：

每个视频帧 t，在**相机坐标系**里用两个方向张成一个正交基：

- **y 轴 = 重力方向**：y = R_w2c · g，其中世界重力方向在代码里硬编码为 `[0,0,-1]`（`get_R_c2gv` 的默认参数 `axis_gravity_in_w=[0,0,-1]`，hmr_global.py:7）——即 y 轴指向重力方向（"向下"）；
- **x 轴 = y × view**，view = [0,0,1]^T 是相机系图像平面法向（视线方向）；
- **z 轴 = x × y**（右手系闭合）。

人体的相机系全局朝向 Γ_c 重表达为 Γ_GV = R_c2GV · Γ_c，R_c2GV = [x, y, z]^T。

代码里有一个论文没提的**退化情形处理**：当视线与重力方向平行（相机垂直朝上/朝下拍），y × view 的模长趋零，x 轴无定义——源码 fallback 到相机 x 轴（hmr_global.py:22-24：`axis_x_of_gv[axis_x_of_gv_norm < 1e-5] = [1,0,0]`）。仰拍/俯拍素材会走到这个分支。

**为什么这样设计**（三重理由，均有论文原文或消融支撑）：

1. **重力对齐 = 消除学习目标的相机依赖**。在相机系里，相机的 roll/pitch 会让人"看起来倾斜"——同一个人做同一个动作，学习目标随相机姿态漂移。论文的论证是（§3.1 原文）："humans can easily infer the orientation and gravity direction of a person in an image. And for consecutive frames, estimating the relative rotation around the gravity direction is intuitively easier and more robust."——重力方向是单帧图像里可辨识的强先验，且帧间只需估计绕重力轴的相对旋转。消融证实：去掉 GV 坐标系（纯相机系回归），RICH 上 W-MPJPE100 从 126.3 恶化到 278.9 mm（论文 Table 3）。
2. **逐帧唯一 = 把世界系歧义推出学习问题**。GV 系由该帧相机姿态唯一决定，不需要序列级的世界系定义；"世界系绕重力旋转不唯一"的歧义被推迟到 §2.5 的 yaw 展开里一次性处理。
3. **帧间自由度 3→1 = 对相机旋转误差鲁棒**。相邻两帧的 GV 系 y 轴都是重力方向，两系之间的差异**只剩绕重力轴的 1-DOF 旋转**（yaw）。相机旋转估计误差对这 1-DOF 的影响是二阶的。实验证据（论文 Table 1 尾行，EMDB）：把 DPVO 估计的相机旋转换成 GT 陀螺仪（ARKit），GVHMR 的 W-MPJPE100 从 276.5 变 274.9 mm（差异在噪声内），RTE 2.0%→1.9%；对照 WHAM 同一实验掉 19.5 mm / 1.9%。论文自述机制（§3.1 原文两句）："In the rotation recovery algorithm between GV systems, we utilize the consistency of the y-axis in the GV system to systematically avoid cumulative errors in the gravity direction. This also mitigates potential errors in camera rotation estimation."

**代价是什么**：

- GV 系只管**朝向**，不管位置——世界平移仍然要靠速度 rollout（§2.5）与后处理（§2.7），一阶积分的漂移没有被这个机制消除。
- GV 是 **y 向下**的非常规坐标系（y = 重力方向），最终输出前要做一次 y 轴翻转（代码 `get_tgtcoord_rootparam(..., tsf="any->ay")`，即绕 z 轴 π 旋转，hmr_global.py:32-37、gvhmr_pipeline.py:381）。对接外部约定（如 y-up 世界）时这是必经的一跳。
- 依赖"世界重力方向已知"（硬编码 [0,0,-1]）；若输入视频来自重力方向未知/非轴对齐的世界系，需要外部保证（-s 静态相机分支直接假设 R_w2c = I，demo.py:178-179）。

### 2.3 相机旋转从哪来：预处理链与 cam_angvel 的定义

**怎么做**（demo 路径，`tools/demo/demo.py:98-200` + 预处理源码）：

| 步骤 | 实现 | 机制细节（代码级） |
| --- | --- | --- |
| 人体 bbox | `Tracker` = YOLOv8x（conf 0.5，classes=0） | 跟踪所有行人，但 `get_one_track` **只取 bbox 面积和最大的 top-1 轨迹**（tracker.py:71、80-81：`id_sorted = list(id2area_sum.keys())`——长度排序结果算出但不参与选择）；缺失帧线性插值（tracker.py:89）+ 两次窗口 5 的滑动平均平滑（tracker.py:92-93） |
| 2D 关键点 | `VitPoseExtractor` = ViTPose-H | 在 bbox 内提取 COCO-17 关键点（含置信度），demo.py:123-135 |
| 图像特征 | `Extractor` = HMR2（4DHumans）ViT encoder，**冻结** | 256×256 crop，输出 (F, 1024)，batch 16（vitfeat_extractor.py:60-86；源码注释 batch 16 约占 5 GB @ 3090） |
| 相机旋转 | 默认 `SimpleVO`；`--use_dpvo` 切 DPVO；`-s` 跳过 | SimpleVO：0.5 缩放、每 8 帧采样、SIFT 匹配、pycolmap 两视图求解（给定焦距 f_mm，默认 24 mm）、累积 T_w2c、插值回全帧（simple_vo.py:14-45）。DPVO 输出 (L,7) 四元数轨迹（demo.py:153-168）。`-s` 直接 R_w2c = I（demo.py:178-179） |

相机旋转进入网络前的编码（`hmr4d/utils/geo_transform.py:567-576`）：

```
cam_angvel_t = R_w2c^{t+1} @ (R_w2c^t)^T   （相对旋转矩阵，转 rotation-6D，末帧 padding）
```

即**帧间相对旋转**（"R @ R_{w2c}^t = R_{w2c}^{t+1}"，gvhmr_pipeline.py:330 的 docstring），不是完整相机位姿。训练时它经 `stats_compose` 的手动 mean/std 归一化（gvhmr_pipeline.py:47-50、61-62）。

**为什么这样设计**：

- **只需要旋转，不需要 SLAM 平移/尺度**——这是与 GLAMR/SLAHMR 类"SLAM 重建场景再恢复运动"路线的本质分工。GV 系构造（y 轴）与 yaw 展开（§2.5）都只消费旋转；平移/尺度歧义被排除出学习问题，世界平移改由人体运动学 rollout 提供（§2.5）。这就是"相机运动与人体运动解耦"的完整含义：**旋转作为条件输入，平移根本不进入网络**。
- SimpleVO 的存在是工程取舍：DPVO 是外部 submodule、编译重（事实卡 §4 已收录依赖链），内置 SIFT+pycolmap 两视图方案以已知焦距为前提、足够轻。
- 对**位级确定性纪律**的一个有意思的对照：SimpleVO 源码注释明确写出并行路径"NOT bit-for-bit equivalent to the serial path. pycolmap RANSAC is non-deterministic"（simple_vo.py:67-69）——预处理层本身不提供逐字节复现承诺。这与本仓库 ADR-0009 的确定性口径形成对照（我们的确定性主张只覆盖参考模式核心，适配器产出若要入库需注意这一点）。

**代价是什么**：

- 预处理是**运行时瓶颈**：论文口径 1430 帧共 46.0 s（YOLOv8 4.9 + ViTPose 20.0 + ViT 特征 10.1 + DPVO 11.0）vs 网络前向 0.28 s，慢两个数量级（论文 §4.4 Running Time；注意该口径含 DPVO，与仓库 2025-03-08 起默认 SimpleVO 的现状不同——事实卡 §1 已收录此口径差异）。
- VO 失败模式（弱纹理、旋转突变、帧间大基线）**直接传进 cam_angvel**，网络没有机制甄别输入质量；SimpleVO 每 8 帧采样 + 插值的做法对快速旋转场景尤其存疑——SimpleVO 与 DPVO 的精度差距**没有官方数字**（论文全部实验用 DPVO），标 **UNVERIFIED**（§5）。
- `-s`（静态相机）是**用户决策**不是自动检测：判定错了要么白跑 VO、要么丢掉真实相机旋转（事实卡 §2 已收录该边界）。

### 2.4 网络主干：Relative Transformer、RoPE 与多任务输出

**怎么做**（`hmr4d/network/gvhmr/relative_transformer.py:14-185`，release 配置 `hmr4d/configs/siga24_release.yaml`）：

- **主 token**：17 个 2D 关键点（bbox 归一化坐标 x,y + 置信度 c，`normalize_kp2d`，gvhmr_pl_demo.py:30-31）→ 低置信度帧的坐标**置零并替换为 learned embedding**（relative_transformer.py:124-128：`f_obs * visible_mask + learned_pos_params * ~visible_mask`）→ linear(2→32)×17 → MLP → **512 维逐帧 token**。
- **条件融合（early fusion）**：三条条件流各自过 embedder 后**逐元素相加**进主 token（relative_transformer.py:131-140）：
  - `f_cliffcam`（3 维，CLIFF 式 bbox 信息 = 框在全图中的位置/尺寸相对内参，`compute_bbox_info_bedlam`，gvhmr_pipeline.py:59）；
  - `f_cam_angvel`（6 维相对相机旋转，归一化后）；
  - `f_imgseq`（1024 维 HMR2 图像特征）。
  embedder 结构：Linear+SiLU+**zero_module** Linear（零初始化最后一层，训练初期条件不扰动主路）；图像特征走 LayerNorm+zero_module Linear。训练时全部条件以 **0.1 概率随机置零**（`randomly_set_null_condition`，gvhmr_pipeline.py:70、138-147）。
- **主干**：12 层 EncoderRoPEBlock，8 头，hidden 512，mlp_ratio 4，dropout 0.1。注意力用 **RoPE（Rotary Positional Embedding）实现相对位置**：token s 对 t 的注意力偏置由相对索引 R(p^s − p^t) 决定，512 维拆成 256 个 2D 旋转子空间（论文 Eqs. 3–5）。
- **任意长并行推理**：L > max_len(120) 时构造**带状注意力掩码**，每帧只 attend 前后 ±60 帧（边界对齐到 max_len，relative_transformer.py:146-153）——不是滑窗递推，而是一次前向、每帧有限感受野。论文原文："the model can generalize to arbitrarily long sequences without needing autoregressive inference techniques, such as sliding-window."
- **输出头**（全部 2 层 MLP，GELU）：
  - `final_layer` → **151 维 pred_x/帧** = body_pose r6d（126，21 关节×6）+ β（10）+ incam 全局朝向 r6d（6）+ **GV 全局朝向 r6d（6）** + local_transl_vel（3）——这是编码/解码的固定布局（`endecoder.py:102-137` encode、`161-185` decode，维度切分注释与代码一致）；
  - `pred_cam` 头 → 3 维弱透视相机，反归一化后 **s 下限 clamp 0.25**（relative_transformer.py:170-173，防负尺度）；
  - `static_conf` 头 → 6 维 logits（6 个静止关节的静止概率）。
- **avgbeta**：β 逐帧预测但**取全序列有效帧平均后复制回每帧**（relative_transformer.py:163-166）——β 是人的形状恒量，不该逐帧抖动。

**为什么这样设计**：

- **非自回归**是相对 WHAM（RNN 递推相对姿态）的根本转向：逐帧输出无递推依赖 → 无初始化要求、无误差沿序列累积。消融（论文 Table 3，RICH）：把逐帧 GV 全局朝向 Γ_GV 换成帧间相对朝向预测，WA-MPJPE100 从 78.8 恶化到 101.2——"相对化"正是误差累积的入口。
- **RoPE 相对位置**提供时间平移一致性（同一运动模式不论出现在序列哪个位置，表示一致）。消融：换绝对位置编码后 W-MPJPE100 从 126.3 崩到 304.4；加滑窗修复到 133.2，仍劣于 RoPE——绝对位置编码在长序列上外推失效是主因。消融还显示把整个 Transformer 换成时序卷积：WA-MPJPE 85.8（滑窗 84.2），全面劣于 78.8。
- **条件 dropout 0.1**：训练时随机置零条件流，推理时对低质量输入（SimpleVO 的噪声帧、遮挡帧特征）更稳。注意 AMASS 样本**天然条件为零**（无图像：图像特征置零、合成相机），等于在真实数据之外额外给了"缺条件"分布的训练信号（论文 §3.3）。
- **预测 151 维单一向量**而非多个独立输出：把"相机系朝向 + GV 系朝向 + 局部速度"放进同一回归目标，三者的几何一致性由训练数据强制（同一段 GT 运动编码出的三个分量必然自洽），不需要额外的正则项。

**代价是什么**：

- ±60 帧感受野是硬上界：超过两分钟前的信息不可达，长时序一致性（如"走一个大圈回到起点"）没有机制保证——网络不建场景、无地图，全局平移完全靠速度积分 + 后处理。
- 全部目标逐帧 MSE 监督，**没有对"展开后的全局轨迹"直接加损失**——唯一的全局轨迹损失（transl_w）用的是 GT 朝向做 rollout（§2.8），这是刻意把监督与展开误差解耦的设计，但也意味着展开链本身（yaw 累积、积分）永远不在训练回路里。
- zero_module 条件注入意味着训练初期网络几乎是"纯 2D 关键点驱动"——条件流的利用程度取决于训练动态，无法从结构上保证相机旋转条件被充分使用（无官方分析，属机制观察）。

### 2.5 世界坐标系序列的恢复：GV→世界系的几何展开

这是全报告最核心的一段：**"世界坐标序列"不是网络预测的，是展开出来的**。代码 `get_smpl_params_w_Rt_v2`（gvhmr_pipeline.py:321-384，函数标注 `@autocast(enabled=False)` 强制 fp32）逐步如下：

1. **cam_angvel → 帧间旋转**：rotation-6D 转矩阵得 R_t_to_tp1 (B,L,3,3)；接近恒等的帧（axis-angle 范数 < 1e-5）强制置为恒等，防数值噪声（gvhmr_pipeline.py:334-341）。
2. **恢复 R_c2gv**：网络自己预测的 Γ_GV 与 Γ_c 给出 R_c2gv = R_gv @ R_c^T；**视线方向在 GV 系下的表示** = R_c2gv 的第三列（z 列，"z 轴与视线最接近"，源码注释明确说 "Rc2gv is estimated, so the x-axis is not accurate, i.e. != 0"——网络预测的 x 分量不可靠，所以只用 z 列，gvhmr_pipeline.py:344-349）。
3. **下一帧视线**：R_cnext2gv = R_c2gv @ R_t_to_tp1^T 的 z 列——用相机帧间旋转把 t+1 帧视线转回 GV 系（gvhmr_pipeline.py:352-353）。
4. **1-DOF yaw 提取**：两个视线向量**去掉 y 分量、归一化**（= 投影到 GV 的 xz 水平面，重力轴被显式锁死），叉积给轴、acos 给角 → 帧间 yaw 轴角 aa_tp1_to_t（gvhmr_pipeline.py:355-364）。随后**沿时间做 gaussian_smooth**（gvhmr_pipeline.py:366）——直接平滑这个 1-DOF 信号，压制 VO 噪声。这一步与论文 §3.1 的 R_ΔGV 构造逐句对应：正文原句 "For a moving camera, we first compute the rotation R_ΔGV^t between the GV coordinate systems of frame t to frame t−1…"（借助输入相机相对旋转与预测朝向计算帧 t 与 t−1 的 GV 系间旋转），加上论文 Fig. 5 caption 原句 "R_ΔGV occurs exclusively around the y-axis (gravity direction)"。
5. **累积旋转**：R_t_to_0 = Π R_tp1_to_t（串行累积乘积，gvhmr_pipeline.py:370-374）→ **全局朝向 Γ_w = R_t_to_0 @ R_gv**（gvhmr_pipeline.py:376）。世界系 = 第 0 帧的 GV 系。
6. **平移 rollout**：网络的 local_transl_vel（SMPL 局部系根速度）逐帧经 Γ_w 旋到全局系，从原点 `torch.cumsum` 积分（`rollout_local_transl_vel`，hmr_global.py:151-171）→ 最后 `get_tgtcoord_rootparam(..., tsf="any->ay")` 把 GV0 的 y-down 翻成 y-up（gvhmr_pipeline.py:380-382）。

**为什么这样设计**：

- **把全局恢复拆成"旋转链 + 速度链"两条独立通道**。旋转链只含 yaw（1-DOF、可平滑、重力轴免疫）；速度链用 **SMPL 局部系**表示速度（v_local = R^T · v_global，hmr_global.py:132-148）——沿用 HuMoR/WHAM 的约定：网络学"人往自己身前走多快"，而不是"人往世界东边走多快"。速度与朝向解耦后，网络对"朝向预测错了一点但速度模式对"的情形不再受罚两次。
- **重力轴上无累积误差**是标题 "world-grounded" 的实现载体：yaw 展开的旋转轴恒为重力方向，y 分量在每一步都被置零重投影，重力方向的一致性是**结构保证**而非学习结果（论文 §3.1 原文："we utilize the consistency of the y-axis in the GV system to systematically avoid cumulative errors in the gravity direction"）。
- **世界系锚定 GV_0**：绕重力的旋转歧义按论文明示不求解（"any rotation of W around the gravity direction is valid"）——输出只在"第 0 帧 GV 系"这个约定下有定义。消费方若需要绝对朝向对齐（例如接到带地图的世界里），必须自己补一步外部对齐。
- 静态相机（`-s`）时整条展开链退化：R_w2c = I → cam_angvel 全零 → Γ_w = Γ_GV，平移照常 rollout（demo.py:178-179 + gvhmr_pipeline.py:99-100 走专用后处理）。

**代价是什么**：

- yaw 展开仍是**累积乘积**：绕重力的长程漂移没有被理论消除，只是从 3-DOF 降为 1-DOF（误差被结构性降阶，不是归零）；平移 cumsum 是一阶积分，漂移更大，靠 §2.7 的后处理拉回。
- 展开链不可训练：`get_smpl_params_w_Rt_v2` 是推理期函数（含 for-loop，"This function has for-loop" 注释，gvhmr_pipeline.py:85），训练中的 transl_w 损失用 GT 朝向 rollout——展开数值误差（取整、平滑、clamp）从不进入梯度。
- fp32 强制（`@autocast(enabled=False)`）+ 接近恒等的 clamp，说明作者在实践中遇到过数值稳定性问题；消费方自己做等价几何时同样要防。

### 2.6 SMPL-X 参数化人体模型的角色

**怎么做**——SMPL-X 在 GVHMR 里出现在三层，职责各不相同：

- **表示层（网络的"语言"）**：输出契约是 SMPL-X body 参数：body_pose 21 关节 × 3 axis-angle + β 10 维 + global_orient 3 维；**不含手部 articulation**（静止的手腕作为平移修正的锚点，见 §2.7）。β 逐帧预测但经 avgbeta 序列共享（§2.4）。编码/解码布局固定在 151 维向量的前 136 维（endecoder.py:102-137）。
- **几何层（损失与后处理的运动学引擎）**：`EnDecoder` 持有 `make_smplx("supermotion_v437coco17")` 的 SMPL-X 模型（endecoder.py:33），但只用它的**骨架**：`fk_v2` 按 β 取 22 个 body 关节骨架（`get_skeleton(betas)`，骨长 = skeleton − parent，endecoder.py:76-83），然后跑**轻量 TRS-FK**（`matrix.forward_kinematics`，不用完整 LBS 蒙皮）得到 (B,L,22,3) 关节——监督、后处理、IK 全在这个 22 关节骨架上进行。骨架随 β 变化意味着后处理/IK 是**体形感知**的。
- **渲染层（交付产物）**：demo 渲染用完整 SMPL-X（`make_smplx("supermotion")`）前向得 vertices，再经 `smplx2smpl_sparse.pt` 稀疏线性映射转成 **SMPL 拓扑**渲染（demo.py:210-216）——SMPL-X 只在中间存在，最终网格是 SMPL 拓扑。

**为什么这样设计**：

- SMPL-X 是训练数据的**统一参数化**：AMASS/BEDLAM/H36M/3DPW 的 GT 都被转换到该表示下监督（论文 §3.3），任何数据集进得来、任何下游消费者（渲染、IK、重定向）出得去。
- **body-only 是刻意的输出收窄**：单目视频里手部 articulation 不可靠，而"不预测手"让手腕成为干净的静止锚点（速度阈值生成的 GT 标签只覆盖 6 个手脚关节，gvhmr_pipeline.py:307）。代价论文自认：3DPW 上 PA-MPJPE 36.2 略逊 WHAM 的 35.9，作者归因 "we do not directly predict the SMPL parameters, but rather the SMPLX parameters, which might introduce some errors"（论文 §4.3）。
- **β 条件化的骨架**让 fk_v2/IK 不必假设平均体形——修正量作用在真实骨长上。

**代价是什么**：

- SMPL-X 参数化在该任务上实测略损精度（0.3 mm PA-MPJPE，上述论文原话）——换成 SMPL 输出可能更准，但会失去 SMPL-X 生态（手/脸扩展空间）。
- **许可传染**：SMPL-X 模型本身是 MPI 研究许可（事实卡 §3 权威文本，不重述）——它决定的是**产出物的可用范围**，不只是代码可用性。
- fk_v2 是 22 关节近似（不含 SMPL-X 完整 55 关节与 LBS），网络内部的运动学与最终渲染的蒙皮存在表示差——对 body 运动影响可忽略，但说明"SMPL-X 的角色"仅到骨架层为止。

### 2.7 后处理：stationary 概率 → 全局平移修正 → CCD-IK

**怎么做**（`hmr4d/model/gvhmr/utils/postprocess.py`，推理路径 postproc=True，gvhmr_pl_demo.py:38）：

静态关节集合固定为 6 个：`[7, 10, 8, 11, 20, 21]` = L_Ankle, L_Foot, R_Ankle, R_Foot, L_Wrist, R_Wrist（gvhmr_pipeline.py:307）。三步：

1. **全局平移修正（动相机，`pp_static_joint`，postprocess.py:20-58）**：对静态关节做 FK 得世界系位置，算帧间位移 (B, L−1, J=6, 3)；对 6 个静态关节**沿关节维做 softmax**（`static_conf_logits[..., None].softmax(dim=-2)`，张量形状 (B, L−1, 6, 1) 的 dim=-2 是**关节维**：该帧内部 6 关节权重和为 1，且 logits≤0 的通道先经 −1e6 门控、softmax 后权重趋零，postprocess.py:30-36），加权求和（`sum(-2)`，postprocess.py:37）得到该帧一个 3 维滑动修正向量；**逐帧**从全局平移的帧间位移里扣除该修正、重新 cumsum（postprocess.py:45-49）；x/z 高斯平滑；y 按全序列最低点落地（postprocess.py:50-56）。
2. **静态相机专用修正（`-s`，`pp_static_joint_cam`，postprocess.py:61-118)**：先用第 0 帧的 R_c2w 定死相机→世界变换 T_c2w（postprocess.py:79-84），把相机系关节投到世界系；根位置差**只修大错**（差异 > 0.25 m 才动手，且每帧 clamp 到 ±0.02 m，postprocess.py:89-93）；再按静止关节（sigmoid > 0.8）的平均位移修正，**y 分量不动**（postprocess.py:102-107）。
3. **CCD-IK 重解局部姿态（`process_ik`，postprocess.py:121-168）**：静止关节的目标位置 = 上一帧位置 × c + 本帧位置 × (1−c) 的**指数混合**（postprocess.py:128-133——置信度高则目标钉在上一帧位置）；对左右腿、左右手四条运动链各跑 **CCD-IK（max_iter=2）**（postprocess.py:143-163），重解出的 body_pose **同时回写** global 与 incam 两份参数（gvhmr_pipeline.py:103-106）——保证两个坐标系下的网格不脱节。

**为什么这样设计**：

- **脚滑不可能由网络消掉**：网络逐帧（±60 帧窗口）回归，帧间脚部位置一致性没有显式约束，速度 rollout 的积分误差必然让"该钉在原地的脚"漂移。后处理是**唯一**能看全序列的环节。
- **stationarity 是比"接触检测"更弱的信号**：不需要场景几何、不需要深度，只依赖运动学。GT 标签 = 关节速度阈值自动生成：训练 pipeline 从 config 读取 vel_thr（gvhmr_pipeline.py:305），官方训练配置 `hmr4d/configs/exp/gvhmr/mixed/mixed.yaml`（static_conf 段，行 50-51）设 **vel_thr: 0.15**——与同函数 docstring 注释"HuMoR 用 0.15 m/s"一致；`get_static_joint_mask` 的函数默认参数 0.25（hmr_global.py:331）在训练路径中未被使用；帧间隔 0.033 s 硬编码（hmr_global.py:336）→ 30 fps 假设。单目 + 无场景假设下这是可负担的监督。
- **逐帧即时扣除**（第 1 步）的直觉：累积漂移是"每一帧贡献一点滑动"的和，修正按帧独立扣除该帧滑动量、防止其在速度积分中继续累积，而不是事后硬性把某帧拉回。IK（第 3 步）保证修正不破坏骨架结构——平移改了之后姿态跟着适配。
- 消融证据（论文 Table 3，RICH）：去掉后处理 FS 从 3.0 恶化到 6.8 mm，jitter 从 12.8 到 14.5 m/s³。**脚滑指标的一半以上是后处理挣的**。

**代价是什么**：

- **后处理是精度主张的组成部分，不是可选润色**：README 明确警示测试脚本带后处理而训练不复用，"复现训练脚本时全局指标结果会与论文不同"（事实卡 §2 已收录该警示原文出处）。读论文数字时必须把这三步当成模型的一部分。
- 修正假设"该帧滑动量 ≈ 各静止关节位移按置信度的加权平均"（无静止关节的帧被 `is_static` 门控置零）——**连续走动（没有任何静止帧）时没有修正机会**；修正强度完全由 6 个关节的静止概率驱动，概率错了修正就错。
- IK max_iter=2 是效率取舍，极端修正量下能否收敛到位无官方数字（**推断**：CCD 两轮迭代对大位移修正可能不足；依据仅是迭代上限本身）。
- 落地（ground y = min）是"把最低点贴地"的粗对齐，源码注释自认 "this does not consider foot height"（postprocess.py:53-56）——地面高度不是物理测量的，是归一化约定。

### 2.8 训练配方与监督信号

**数据与目标**（论文 §3.3 + `gvhmr_pipeline.py` 训练分支）：AMASS（纯运动，**合成相机 + 图像特征置零**）+ BEDLAM + H36M + 3DPW 从零训练；序列长 L=120，batch 256，13 小时 @ 2×RTX 4090（论文 §4.4 原文 "The model converges after **500** epochs"；注意官方项目页写 420 epochs——两来源冲突，记入 §5 UNVERIFIED）。

**监督分三层**（gvhmr_pipeline.py:110-318）：

1. **simple MSE**：151 维归一化目标的逐维 MSE。关键细节：3DPW 样本带 `spv_incam_only` 标记，**第 142 维之后（GV 朝向 + 局部速度，即全局分量）不监督**（gvhmr_pipeline.py:119：`mask_simple[..., 142:] = False  # 3dpw training`）。（源码只给注释 "3dpw training"；为何 3DPW 不监督全局分量论文未明说——**推断**：其世界系 GT 与 AMASS 约定不对齐，监督会引入系统性偏差；标注为推断。）
2. **相机系附加损失**（`compute_extra_incam_loss`）：根相对 C-MPJPE 的 MSE；pred_cam 监督（把 GT transl 反算成 GT pred_cam 以防除零，带 z/尺度有效性 mask，gvhmr_pipeline.py:186-208）；2D 重投影损失（`project_to_bi01`，投影回 bbox 归一化平面，带深度阈值与出界 mask，gvhmr_pipeline.py:210-234）；根相对顶点损失（437 顶点）；顶点 2D 重投影。2D 重投影对 3DPW 同样跳过（`mask_reproj`）。
3. **全局附加损失**（`compute_extra_global_loss`）：
   - **transl_w**：`rollout_local_transl_vel(local_transl_vel, gt_global_orient_w, gt_transl_0)` 再对 GT 世界平移做 L1（gvhmr_pipeline.py:290-300）——**rollout 用的是 GT 朝向**，不是预测朝向。监督信号是"局部速度本身"，展开误差不进入损失（与 §2.5 "展开链不在训练回路"一致）。
   - **static_conf**：GT 静止标签由 GT 世界系关节速度阈值生成（6 关节，vel_thr=0.15 m/s，读自训练配置 mixed.yaml），与 logits 做 BCE（gvhmr_pipeline.py:303-316）。

**条件 dropout 0.1**（§2.4）+ cam_angvel 手动归一化（`stats_compose.cam_angvel["manual"]`，gvhmr_pipeline.py:47-50）。

**为什么**：把全局监督放在"速度 + 逐帧朝向"分解上而非端到端轨迹上，是因为累积量（轨迹）不可学、局部量（速度）可学——这是 HuMoR 以来的成熟经验，GVHMR 把它与非自回归逐帧预测组合。AMASS 的零条件样本 + 0.1 条件 dropout 共同构成对"缺输入"的鲁棒性训练。

**代价**：混合真实 + 合成数据（BEDLAM 合成渲染、3DPW 真实）意味着真实域的图像特征与合成域的分布差由 HMR2 冻结特征缓解——但域差仍存在于 2D 关键点质量上；3DPW 只监督相机系是信息损失（该数据集的真实世界轨迹没有被利用到全局监督里）。

### 2.9 与普通 HMR 的对照：根坐标在相机系 vs 世界系

普通 HMR（HMR/HMR2.0/CLIFF/PyMAF 类）与 GVHMR 的本质差别，一句话：**普通 HMR 的学习目标是"图像 → 相机系姿态"（相机运动是干扰项）；GVHMR 的学习目标是"图像 + 相机相对旋转 → 重力对齐全局姿态 + 局部速度"（相机旋转是输入条件、相机平移被排除出学习问题）**。

| 维度 | 经典 HMR（HMR2.0/CLIFF 类） | 自回归全局恢复（WHAM） | 优化式全局恢复（GLAMR/SLAHMR） | GVHMR |
| --- | --- | --- | --- | --- |
| 根节点坐标系 | 相机系（或 bbox 归一化弱透视系） | 世界系（递推相对量） | 世界系（优化） | 世界系，但**逐帧在 GV 系表达** |
| 相机旋转 | 不输入（或只用于弱→全透视转换） | 输入 | SLAM 全量输入 | 只输入**相对旋转**（cam_angvel） |
| 时序机制 | 逐帧/滑窗 | RNN 自回归 | 序列优化 | Transformer 逐帧并行 + RoPE |
| 误差累积 | 无全局概念 | 沿递推累积 | 收敛问题 | 仅 yaw 1-DOF 累积（重力轴结构免疫） |
| 重力一致性 | 无 | 差（论文 §2 指其重力方向一致性受损） | 不保证（"do not obtain gravity-aligned human motion"） | 结构保证（GV y 轴 = 重力） |
| 速度 | GVHMR 相机系分支保留此形态（smpl_params_incam 兼容输出） | 预测相对全局姿态+速度 | — | SMPL 局部系根速度 + 确定性 rollout |

逐条来源：相机系/弱透视形态 = CLIFF 式 pred_cam 与 `compute_transl_full_cam`（gvhmr_pipeline.py:82）；WHAM 自回归与误差累积 = 论文 §1 原文（"attempts to recover global motion by autoregressively predicting relative global poses with RNN. While this method achieves significant improvements, it requires a good initialization and suffers from accumulated errors over long sequences, making it challenging to maintain consistency in the gravity direction."）；GLAMR/SLAHMR 慢与不重力对齐 = 论文 §2（SLAHMR ">6 hours" vs 网络前向 0.28 s）；WHAC/TRAM 需精化网络 = 论文 §2。数字佐证（RICH 世界系指标，论文 Table 1）：GVHMR WA/W-MPJPE100 78.8/126.3 vs WHAM 109.9/184.6 vs SLAHMR 98.1/186.4 vs GLAMR 129.4/236.2；EMDB 上 GVHMR 111.0/276.5 vs WHAM 135.6/354.8。相机系指标则三者接近（3DPW PA-MPJPE：WHAM 35.9 vs GVHMR 36.2，GVHMR 反而 MPJPE 55.6 vs 57.8 更好）——**GVHMR 的增益集中在世界系指标上，相机系姿态质量与 WHAM 同级**，这正是"坐标系设计"而非"姿态估计器更强"的证据。

## 3. 能力边界与工程现实（与事实卡 §2/§4 互链）

事实卡 §2 已收录官方限制清单与许可/硬件边界，本节只讲**机制性**的展开：

1. **相机旋转依赖是结构性的**：GV 系构造（y 轴）与 yaw 展开（§2.5 第 4-5 步）都消费 cam_angvel——这个输入没有旁路（`-s` 静态相机是唯一旁路，且是用户决策）。但 1-DOF 结构使误差影响降阶（DPVO→GT gyro 实验，§2.2）。SimpleVO 替代 DPVO 的精度差距无官方数字（§5 UNVERIFIED 6）。
2. **预处理瓶颈是数量级的**：46 s（论文口径，含 DPVO）vs 0.28 s 前向（§2.3）；把 GVHMR 当"实时观察源"的前提不成立，它是**离线批处理生产者**。
3. **单主体是代码事实而非未验证**：`Tracker.get_one_track` 取 **bbox 面积和最大的 top-1**（tracker.py:71、81——长度排序算出但不参与选择），其余人直接丢弃（tracker.py:80-93）；demo 输出的 bbox 缓存形状 (L,4)（事实卡 §5 已注意）。多人在场时行为确定：**只恢复最显著一人**。这比事实卡"多人能力未验证"更精确一层：不是未实现的能力，是实现了但主动收窄的选择（YOLO 明明跟踪了所有人，tracker.py:28-40）。
4. **后处理是精度主张的组成部分**（§2.7，README 警示已收录事实卡 §2）——评估/复现时必须原样带上三步后处理，否则 FS 数字不可比。
5. **无场景概念**：不建环境、不做接触检测、地面是"最低点贴地"的归一化约定（§2.7）；±60 帧感受野之外无长时序一致性机制（§2.4）。
6. **遮挡/快速运动失败模式**：论文无 Limitations 章节、无系统失败分析（事实卡 §2 已标 UNVERIFIED，维持）；论文唯一相关的表述是定性图（Fig. 8）显示 WHAM 在"difficult motion"上失败、GVHMR 更稳——属作者自述对比，非边界声明。
7. **仓库内部不一致（本报告新发现）**：`hmr4d/configs/siga24_release.yaml:13` 引用 `NetworkEncoderRoPEV2`，但当前 main 的 `relative_transformer.py` 只定义了 `NetworkEncoderRoPE`（且该文件 git 历史仅一条 "Code release" commit，无 V2 类的踪迹）；demo 路径不受影响（`hmr4d/configs/demo.yaml` 走 store name `network: gvhmr/relative_transformer`）。checkpoint 内嵌 config 是否含 V2 未核验（**UNVERIFIED**，§5）。不影响本报告任何原理陈述（两个类名指向同一架构，差异只在配置别名层）。

## 4. 与 OmniWorld 的关系深化：World Contract 视角

从 World Contract 四要素（identity / time / ownership / confidence，权威文本 `docs/design/00-总体设计.md` §2）逐项对齐——事实卡 §6 已给定位结论，这里给**契约字段级**的深化：

- **identity**：GVHMR 的输出天然是**单条人体轨迹**（`smpl_params_global` 按一条 track 组织）。它不做多人身份管理——top-1 track 的选择发生在预处理（§3.3），对网络完全透明。含义：若评测面板需要多人观察源，identity 管理（谁的轨迹、轨迹断了算同一个体还是新个体）必须全部落在引擎侧/适配器外壳，GVHMR 只提供"这一段是谁"都不承诺。这与 SAM 2 卡的 obj_id 教训同构（`../projects/sam-2.md`：identity/confidence 必须住引擎侧）。
- **time**：输入被 demo 强制重编码为 30 fps（demo.py:87-93 的 copy 步骤 `get_writer(fps=30)`）；输出逐帧索引即时间基准。但**30 fps 假设还硬编码在机制深处**：静止标签的速度阈值计算用 0.033 s 帧间隔（hmr_global.py:336）——喂非 30 fps 素材时阈值语义漂移（0.15 m/s 阈值静默失效方向不可控）。契约含义：GVHMR 是"30 fps 逐帧生产者"，适配器必须把"帧索引 → 引擎时间轴"的映射显式化，且**不能信任其内部帧率假设**。
- **ownership**：预处理产物是四个磁盘缓存（bbx / vitpose / vit_features / slam 四个 .pt，demo.yaml paths 段），单写者、存在即复用、可整体重算——与运动数据层"单写者缓存"的契约形态同构；`hmr4d_results.pt` 是唯一最终产物（含 `net_outputs` 中间量）。契约含义：适配器可以把"预处理缓存目录"当作 GVHMR 侧的 ownership 单元整体托管，引擎侧只见 results。
- **confidence**：官方**唯一**的逐帧置信度是 `static_conf_logits`（6 关节静止概率）；2D 关键点置信度在输入侧被消费（> 0.5 可见性门控，relative_transformer.py:125）。**没有**逐帧整体 confidence、没有 VO 质量指标、没有检测缺失标记。契约含义：stationarity 之外的不确定性（VO 噪声、遮挡、track 断裂）GVHMR 不报告，适配器若要喂 confidence 字段给 World Contract，需要自己从 `net_outputs` 与预处理侧合成（例如 track 缺帧插值次数、SimpleVO 两视图求解的内点数——后者需要改预处理代码，属适配器工作量）。
- **边界重申**（权威在事实卡 §6，不重述）：适配器层、独立 Python 环境、可选依赖默认 OFF（ADR-0012 先例）、产出物标衍生许可。
