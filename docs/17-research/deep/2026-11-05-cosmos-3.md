## 0. 摘要

**它是什么**：Cosmos 3 是 NVIDIA 2026-05-31 发布的开放（OpenMDW-1.1）全模态世界基础模型家族，用一套 Mixture-of-Transformers（MoT）双塔架构把视觉推理（VLM）、世界生成（视频/音频生成器）、动作预测（forward/inverse dynamics、policy）合并进单一网络——官方自称 "the world's first fully open omnimodel"（[PR]/事实卡 §1）。三个基模 Edge 4B / Nano 16B / Super 64B，配套 Framework/Curator/Evaluator 后训练工具链。

**核心原理一句话**：**一条 token 序列、两套参数、一次联合注意力**——AR（reasoner）子序列走 causal next-token prediction，DM（generator）子序列走 rectified flow 去噪，两塔参数完全解耦但只在共享 attention 算子相遇（Q_DM 全注意力读 [K_AR; K_DM]），语言理解与像素生成互不污染又能互相看见（[TR §2.2-2.3]）。

**最关键的三个机制**：① **MoT 双塔**：非嵌入参数（LayerNorm/QKV/FFN）按塔解耦，双塔都从预训练 VLM 初始化——继承 MoT 论文证据的"以约 55-75% 计算量追平 dense 基线、训练动态更稳、胜过 MoE-4x"（[MoT]，[TR §2.3]）；② **统一动作接口**：异构本体（相机 9D/AV 9D/单臂 10D/双臂 20D/人形 29D/ego 57D）统一为"相对位姿伪动作 + 抓握状态"，域专属投影进出、MoT 主干共享，同一模型即可做 forward dynamics / inverse dynamics / policy 三种模式（[TR §2.1.3, Fig.4]）；③ **后训练→专用模型流水线**：Reasoner 权重初始化 Generator → pre/mid-training 课程 → 按模态独立 post-training（T2I/I2V SFT、DROID policy、交互仿真专用四阶段因果蒸馏课程 TF→TF-dCM→SF-DMD + 流式推理），从 16B 基座产出 Sim-Auto/Sim-Bimanual 等专用检查点（[TR §4]，[SIM §3]）。

**对本项目的意义**：它是事实卡 §6 裁定的"②适配器（离线数据生产者）+ Phase 4 候选被评对象"。深度层补上了事实卡装不下的机制结论：它的输出**天然没有 World Contract 四要素的任何一环**（无 identity 铸造、物理时间轴是位置编码而非时钟域、无作者权、无 confidence）——所以评测它必须走独立评测桥，不能塞进 `WorldModelAdapter::predict(Tick, WorldState) → Proposal[]`；同时它的 streaming 机制（chunk 因果、有界历史、control-to-observation latency）是 Phase 4 评测交互式世界模型时可以直接借用的**测量口径**。

## 1. 项目定位与生态位（简短）

生态位、许可、硬件、竞品对比（Genie 3 / Marble / World Labs）均在事实卡 [§6](../projects/cosmos-3.md#6-与-omniworld-的边界--族谱归宿)，此处只讲深度层新增的一句定位逻辑：

Cosmos 3 是 Cosmos 平台三代演化的收敛点。Cosmos 1.0（2025-01，[C1]）把平台定义为"**tokenizer + 预训练 WFM + 后训练样本 + guardrail**"四件套，模型按 diffusion（连续 token）与 autoregressive（离散 token）两条线分开做，再各自 post-train 成 Video2World / 相机控制 / 机器人操作 / AV 专用模型；Cosmos-Predict2 / Transfer 2.5 / Reason 2 时代（2025-06 至 2026，Apache-2.0 代码）是"每类用途一个模型家族"；Cosmos 3（2026-05）把三条线合并为单一 MoT omnimodel——**家族分层的"层"从模型间分工变成了模型内分工（双塔）**，而 tokenizer / 预测 / forward dynamics 的功能分工没有消失，只是全部收进一个前向数据流（§2.2）。

## 2. 原理详解

### 2.1 架构总览：一次前向的完整数据流

一次 Cosmos 3 生成调用的数据流（[TR §2.1-2.3]）：

```
文本 ────────────────► 语言 token ───────────────────┐
图像/视频(理解) ────► ViT 16×16 + 2×2 merge ────────►│ AR 子序列（reasoner 塔）
                                                     │   …lang, vision, <EOS>, <BOG>
图像/视频(生成) ────► Wan2.2 VAE（4×时间/32×32 空间）─┐│
音频 ───────────────► 音频 VAE（48kHz, hop 1920）────┼┤ DM 子序列（generator 塔）
动作 ───────────────► 域专属投影 Wi^(n) ─────────────┘│   [clean 条件] → [noisy 目标]
                                                     ▼
              每 transformer 层：双塔各自 LayerNorm/QKV/FFN → 共享联合注意力
              O_AR = Attn_causal(Q_AR, K_AR, V_AR)
              O_DM = Attn_full(Q_DM, [K_AR;K_DM], [V_AR;V_DM])
                                                     ▼
              输出：语言 = next-token；视频/音频/动作 = rectified flow 去噪
```

（注：文本 token 化的具体算法 TR 未指明——"BPE"/"byte pair" 在技术报告全文零命中，只说文本经语言 tokenizer 进入 AR 子序列，tokenizer 随 VLM 骨干沿用。）

三个关键点：

1. **action 是一等模态**。论文把 action 提升为与 language/vision/audio 并列的核心模态："a dedicated class of action tokens… linking directly to physically grounded control signals"（[TR §2]）。这是它区别于普通视频生成模型的结构性差异——世界演化可以被动作干预（§2.4）。
2. **理解与生成用两个编码器**。同一个视频，理解走 ViT（与主干联合训练），生成走 VAE（训练全程冻结）（[TR §2.1.1]）——因为 next-token 理解需要离散化语义特征，flow 去噪需要连续高保真潜变量，两条目标函数吃不同的表示。
3. **生成模式的统一编排**。所有 11 种工作流（t2v/i2v/v2v-transfer/v2v-predict/forward dynamics/…）共用一个 token 排版规则：（1）AR 全部排在 DM 前；（2）DM 内 clean 条件排在 noisy 目标前；（3）条件与目标内部按 vision→audio→action 排序（[TR §2.2.1]）。换任务 = 换哪些 token 是 clean、哪些是 noisy，**不改架构**——这是"一个模型覆盖 11 种工作流"的机制根源。

**为什么这样设计**：论文 §1 的论证是——VLM、视频生成器、VLA/WAM 的范式分裂"fundamentally limiting"：理解需要推演未来（生成），生成需要世界的结构化表示（理解），分裂的模型栈"suboptimal and computationally wasteful"（[TR §1]）。
**代价**：统一不是免费的——参数量翻倍（§2.3 代价）、Edge 只能做功能子集（事实卡 §2.1）、720p 下 74k 上下文只装得下 batch=1（[TR §5.3.1 Tab.9]）。

### 2.2 家族分层原理：tokenizer / 预测 / forward dynamics 各自做什么

这是"世界基础模型平台"这条产品线从 Cosmos 1.0 就确立的分层（[C1 Fig.2]），Cosmos 3 继承并内化了它。

#### 2.2.1 Tokenizer 层：把世界压进可学习的潜空间

**怎么做（Cosmos 1.0 谱系）**：[C1 §4] 把 tokenizer 定义为平台的"fundamental building blocks"，分 continuous（潜扩散用，向量）与 discrete（自回归用，量化索引）两型；Cosmos-Tokenize1 用因果时间卷积/注意力做"1+4k 帧→1+k 潜步"的时序压缩，首潜步编码首帧，从而图像/视频共享同一潜空间。**怎么做（Cosmos 3 现状）**：视频/图像生成 tokenizer 直接采用 **Wan2.2-TI2V-5B 的 VAE**——4× 时间压缩 + 32×32 空间压缩（16×16 卷积压缩再 2×2 patch merge），训练中冻结；音频 VAE 48kHz/hop1920 → 25 token/s；**动作没有 tokenizer**，用域专属线性投影直接进潜空间（[TR §2.1]）。

**为什么 tokenizer 是独立一层**：世界模型训练成本随 token 数增长，视频又是高度冗余的原始信号——tokenizer 决定了"潜空间里保留什么物理信息"这一上限。[C1] 原文："building a video tokenizer is similar to building a video codec"。压缩率与重建保真的权衡（[C1 §4]）直接决定下游生成模型的物理保真上限。
**代价**：VAE 冻结意味着 tokenizer 的信息瓶颈在训练中不可修复——4× 时间压缩下，快于 1/4 帧率尺度的物理过程（高速碰撞、弹道）在潜空间只能靠相邻潜步插值表达，这是 artifacts 清单里 "implausible dynamics"（事实卡 §2.1）的结构性来源之一（推断，依据：压缩率固定 + [TR] 未提 tokenizer 微调；官方只说 "The VAE encoder for generation is kept frozen during training"）。

#### 2.2.2 预测层：Text2World → Video2World 的谱系与 Cosmos 3 的合并

**怎么做（1.0）**：[C1 §5] 扩散 WFM 两步走：先 Text2World（纯文本条件生成视频），再微调出 **Video2World**（"generates the future based on the current observation (the past video) and control input (prompt)"）；自回归 WFM 同样两步：先 foresight 生成，再加文本条件。[C1] 明确说 Video2World "is a pre-trained world model"——"预测"层的职责定义是**给定观测 + 控制，生成未来观测**。
**怎么做（3.0）**：v2v-predict 工作流就是这个职责的直接后代："first 5 frames used, up to ~3 s of conditioning"（[Repo models.md]）——clean 条件帧在前、noisy 目标在后，扩散子序列里 `S_V2V = [S_AR, z_{1:ℓ}, ỹ_{ℓ+1:}]`（[TR §2.2.2]）。区别在于 1.0 的 Text2World/Video2World 是两个检查点，3.0 里两者是同一权重下 conditioning 帧数（cond=0 vs cond≥1）的差别——训练时 T2I/T2V/I2V/V2V 四模式按 20%/56%/16%/8% 混合采样（[TR §4.2.1]），预训练就把全部模式压进同一权重。

**为什么这样设计**：[C1] 的消融结论是预训练-后训练范式成立——"As the pre-trained WFM provides a great foundation, the dataset for post-training can be much smaller"；Cosmos 3 把多条件模式合进预训练，是让"预测"能力成为基座的通用先验而非后训练特权（[TR §4.2.1] 的多模式混合训练）。
**代价**：v2v-predict 的条件窗口被固定在 5 帧（≈2 个潜帧），更长历史的历史-预测一致性需要 Sim 类专用后训练补（§2.7）；models.md 用空表项明示"Empty cells mean that combination has not been measured yet"（事实卡 §2.1）。

#### 2.2.3 Forward dynamics 层：动作作为因果变量

**怎么做**：这是 [TR §2.1.3/§2.2.2 Fig.4] 最精巧的设计。对一段视频-动作序列，每个动作 token a_t 表示状态 s_{t-1}→s_t 的转移；通过选择 clean/noisy 排布，同一权重切换三种模式：

| 模式 | clean | noisy（去噪目标） | 语义 |
|---|---|---|---|
| **Forward dynamics** | 观测视频 + 动作 | 未来视频 | "这个动作会看到什么" |
| **Inverse dynamics** | 观测视频（前+后） | 动作 | "什么动作解释了这个变化" |
| **Policy** | 观测视频 | 动作 + 视频 | "动作及其视觉后果联合生成" |

**为什么这样设计**：动作被定义为 "causal variables that induce changes in the world state"（[TR §2.1.3]）——一旦动作成为 token，FD/ID/policy 就是同一序列模型上的条件方向翻转，不需要三个模型。论文引言里"机器人要拼装 VLM+VLA+Forward Dynamics Model 三套模型"的碎片化批评（[TR §1]）正由此消解。
**代价**：三种模式共享权重意味着互相牵制——训练中动作损失要 ×10 加权补偿归一化动作向量更小的逐元素 MSE（[TR §4.2.2]）；policy 模式闭环部署还要叠加自生成历史带来的 exposure bias，官方的解法是额外三阶段蒸馏（§2.7），基座本身不直接闭环。

### 2.3 MoT 双塔机制：参数解耦 + 双流联合注意力

**怎么做（机制本体）**：每个 transformer 层携带**两套完整参数**——reasoner 塔（处理 AR 子序列）与 generator 塔（处理 DM 子序列），各自拥有 LayerNorm、QKV 投影、FFN（[TR §2.3.1]）。两塔只在**共享的自注意力算子**相遇，且可见性不对称（[TR §2.3.2, Eq.7-8]）：

- `O_AR = Attn_causal(Q_AR, K_AR, V_AR)` ——语言塔只看自己的因果前缀，保持 VLM 的自回归完整性；
- `O_DM = Attn_full(Q_DM, [K_AR;K_DM], [V_AR;V_DM])` ——生成塔全注意力读语言条件 + 全部视觉/音频/动作 token；
- **"AR tokens are never updated based on DM tokens"**（[TR §2.3.2]）——信息单向流：语言条件作用于生成，生成结果永不回流污染语言推理。

双塔"all co-initialized from a pre-trained VLM"（[TR Fig.5 caption, §2.3.1]）——不是从零分工，而是把一个已会看世界的 VLM 复制两份，一份继续做理解、一份改学生成。

**为什么这样设计（三层依据）**：
1. **直接原因——目标函数冲突**：AR 训练 next-token prediction（离散、教师强制），DM 训练 flow matching（连续、迭代去噪）。MoT 论文的出发点是"conflicting training dynamics in a dense transformer model"、模态在特征空间天然聚类（[MoT §1, Fig.2]）——与其让一套参数迁就两种目标，不如按 token 所属塔做**规则化路由**（rule-based routing）：MoT 论文明确论证这优于 MoE 的学习型路由（无 router 负载均衡问题、无双层优化不稳定，[MoT §1]）。
2. **效率证据**：MoT 在 Chameleon 7B 设定以 55.8% FLOPs 追平 dense 基线；Transfusion 设定 7B MoT 以 <1/3 FLOPs 追平图像性能；实测 wall-clock：图像质量 47.2% 时间、文本质量 75.6% 时间；MoE-4x（参数更多）持续劣于 MoT 尤其在非文本模态（[MoT Abstract/§1]）。Cosmos 3 场景下还有一个额外红利：**reasoner 塔输出可跨去噪步缓存**——条件固定则其激活恒定，"compute the Reasoner forward pass once at the start of inference and cache its outputs for reuse across all subsequent denoising steps"（[TR §5.3.1 Reasoner tower caching]）——参数解耦使这个推理优化成为可能，dense 统一模型做不了。
3. **Cosmos 3 的具体改造**：MoT 原论文是"按模态（text/image/speech）分参数"；Cosmos 3 把解耦轴改为**按功能（AR vs DM）分参数**，同一模态（视觉）的 token 会因编码器不同被路由到不同塔（ViT→AR、VAE→DM）。官方原句点明它与同型工作（Deng et al. 2025）的差异在"training strategy, positional embeddings, and overall capabilities"（[TR §2.3]）。

**代价（三层）**：
1. **参数量精确翻倍**：官方句式 "Edge is a 4B-parameter model built upon a dense 2B-parameter transformer, Nano is a 16B…dense 8B…, Super is a 64B…dense 32B"（[TR §2.5]）——MoT 总参数 = 2× dense 主干，这就是 64B 的由来，也是事实卡 §2.2 显存估算（64B BF16 ≈ 128 GB）的官方依据（算术推断，非官方显存表）。
2. **推理路径分叉**：理解走 vLLM/TensorRT-LLM（Qwen3-VL 已有支持，复用即可）、生成走 vLLM-Omni（扩散专用栈）——两个 serving 生态、两套优化（[TR §5.3.2-5.3.3]）；事实卡 §5 的七后端清单背后是这条分叉。
3. **闭环里语言不上环**：AR 塔在纯生成模式下不参与去噪循环（可缓存），意味着生成结果无法触发语言推理再修正——"reasoning during generation" 需要上层编排（prompt upsampling 是单向一次性的：reasoner 先把短 prompt 扩成 JSON 长描述再交给 generator，[TR §5.3.1/§6.3.2]）。

### 2.4 统一动作接口：异构本体如何压进同一潜空间

**怎么做**：动作表征拆成三个几何构件（[TR §2.1.3 Fig.3]）：
- **ego pose 9D** = 3D 平移 + 6D 旋转（Zhou et al. 2019 的过参数化旋转表示，OpenCV 约定 z 轴沿手指/夹爪、x 向右）；
- **effector pose 9D**（腕/末端执行器）同构；
- **grasp state**：手 = 5 指尖 × 3D = 15D；夹爪 = 1D 开合。

由这些构件拼出官方动作维度：相机 9D、AV 9D、单臂 10D（9+1，DROID/UR/Fractal/Bridge/UMI）、双臂 20D、人形 29D、ego 57D（9+9+15+9+15，头 + 双腕 + 指尖，[TR §2.1.3]）。关键设计：**位姿用相对变换伪动作** `ΔT = T_{t-1}^{-1} T_t`（状态差分），"avoid embodiment-specific controller details such as PID parameters or low-level actuation interfaces"；grasp 却直接编码当前状态而非差分。进出主干用**域专属投影**：`z = W_in^(n) x + b_in^(n)`、`x̂ = W_out^(n) z + b_out^(n)`（[TR Eq.1-2]），n 是域 ID——每个本体一对投影矩阵，主干共享。预测的 6D 旋转经 SVD 投影回 SO(3)。

**为什么这样设计**：相对位姿使动作尺度与本体解耦（任何 SE(3) 本体都能表达为 3 平移 + 6 旋转 + 抓握），域投影吸收残余差异——"Domain-aware input and output projections handle heterogeneous action-vector lengths while preserving the shared semantic space"（[TR Fig.3 caption]）。这让"换本体 = 换一对投影矩阵 + 后训练"，主干权重保留（policy 后训练正是这么做的：fresh action encoder + 5× 学习率只加速动作参数，[TR §4.2.5]）。
**代价**：伪动作丢掉本体底层细节（PID、执行器接口），闭环控制精度依赖外置控制器（DROID policy 用 Franky 执行 32 步动作块，[TR §4.2.5]）；新本体的 57D 空间如果结构不同（如全身人形）需要在 mid-training 就见过——Sim 检查点的动作 embodiment 明确标注只有 AgiBot/YAM（[Repo models.md]），"other rigs need post-training"（相机机位同理，1-11 视角之外要后训练）。

### 2.5 3D mRoPE 与绝对时间调制：多模态对齐到同一物理时间轴

**怎么做**：位置编码沿用 Qwen3-VL 的 3D MRoPE（每头旋转通道分 t/h/w 三轴），加两项 Cosmos 3 专属改造（[TR §2.4]）：
1. **坐标分配**：语言 t=h=w 同值（退化为 1D RoPE）；ViT 视觉 token 帧内共享 t、h/w 按空间网格；VAE 视频 token 三轴全变且**每段视觉坐标清零**（段内绝对坐标，不是全局序列位置）；音频/动作 token 只有时间轴（h=w=0）。文本与视觉区间之间有模态偏移 φ。
2. **15000 时间间隙**：AR 末 token 与首帧视觉 token 若时间坐标相邻，会出现"over-saturation and checkerboard artifacts in the initial video frames"——官方在 AR 与 DM 子序列间插入固定 15000 的时间 gap，"without requiring architectural changes or additional learnable embeddings"。
3. **绝对时间调制（FPS modulation）**：不同模态 token 的时间步对应的物理秒数不同——定义每模态 TPS（视频 = FPS/4，音频 = 25，动作 = 采样率），时间增量按 `TPS_base/TPS` 缩放，TPS_base = 24/4 = 6（视频为主数据、24 FPS 最常见）。效果：16/24/30 FPS 的视频、音频、动作全部对齐到同一物理秒轴（[TR §2.4.2 Fig.6]）。

**为什么这样设计**：理解任务里"离散 token 序号"就够了，但 Cosmos 3 要**同时生成**不同帧率的视频、25 tok/s 的音频、任意采样率的动作——它们必须在注意力里互相对应同一物理时刻，否则音画错位/动作-画面失配。FPS modulation 是把"时间"从 token 计数改为物理量，[SIM §7.1.1] 在 Sim-Auto 里进一步用它对齐 30 FPS 相机（7.5 Hz 潜步）与 10 Hz LiDAR："Capture time determines this alignment independently of diffusion time, rotary coordinates, and packed sequence order"。
**代价**：时间语义被硬编码进位置编码 ⇒ 帧率/时长必须显式作为条件喂给模型（caption 里附 duration/FPS/timestamp 字段，[TR §4.2.1]）；15000 gap 是逐模型调出的超参（Super 上伪影最明显），跨架构迁移未验证。

### 2.6 训练课程：Reasoner→Generator 权重接力与三阶段

**怎么做**（[TR §4]）：
1. **Reasoner 先行**：从 Qwen3-VL-8B（Nano）/32B（Super）/内部预训练 LM（Edge）初始化，跳过独立对齐阶段（"we found such staged alignment to be unnecessary"）联合训练全部组件；24.2M 样本（22.0M 预训练 + 2.2M SFT），数据管线 = Qwen3-VL-Embedding/PE-Core 嵌入 → K-means 聚类 → 0.95 相似度去重 → Gemma-4-31B-it 当 AI-judge 质量过滤（[TR §3.1]）；SFT 混入 1:4 预训练数据防遗忘。
2. **接力**："the trained Reasoner weights are then used to initialize the Generator, transferring semantic and world knowledge into a model capable of synthesizing pixels, audio, and actions"（[TR §4]）——Generator 双塔都从训练完的 Reasoner 复制（[TR §2.3.1]）。
3. **Generator 三阶段**：pre-training（767M 图像 + 347.7M 视频片段，出自 78 亿原始图/30 亿原始视频的漏斗；多分辨率三档 + 74,000 token 定长序列打包免 padding；rectified flow 目标：`x_t = t·ε + (1-t)·x_0`，速度目标 `v* = ε - x_0`，逐模态独立时间采样，视频用 mode sampling、图/音/动作用 logit-normal，分辨率自适应 shift σ=1/3/5）→ **mid-training**（领域特化 + 多模态整合：动作/迁移数据在此引入，混合比 Table 6——action 25%、general transfer 20%、driving transfer 5%；σ 升到 3/5/10；动作损失 ×10）→ **post-training**（按模态独立，§2.7）。规模：Nano 预训练 31.05T tokens / 1024×GB200，Super 17.86T / 2048×GB200；mid-training Nano 2.4T / Super 1.9T tokens（[TR §4.2.1-4.2.2]）。
4. **训练期间 reasoner 塔冻结**："Only the generation-specific parameters are updated during the generator pre-training. The reasoner tower remains frozen, preserving the language and visual understanding capabilities"（[TR §4.2.1]）。

**为什么这样设计**：接力让生成塔免费继承世界知识（理解先于生成，[TR §1] 的论证）；多分辨率 + 定长打包是吞吐工程（"maximizing GPU utilization without padding"）；逐模态时间采样 + mode sampling 是官方消融结论（"using mode sampling yields better generation quality"）。
**代价**：三阶段课程意味着 mid-training 的混合比（Table 6）是硬编码的领域先验——换领域要重跑 mid-training 而非只做 post-training；Tokenizer 基础设施需要为 45 种静态形状（3 分辨率 × 5 长宽比 × 3 调用模式）做 AOT 编译分片，否则每次启动多 15 分钟（[TR §5.2.6]）。

### 2.7 Post-training 工作流：基座 → 专用模型的两条生产线

"把基座调成专用模型"在官方材料里是**两条已验证的生产线**：

**生产线 A：模态级 SFT（主报告示范）**（[TR §4.2.3-4.2.5]）——全部"share the exact same architecture with their corresponding mid-train models"（[TR §3.2 Fig.8]）：
- **T2I**：两阶段 SFT——20k 步广域特化（45% 真图/40% 合成图/15% 文字渲染，lr 1e-4）→ 2k 步 47 万对超高质量精修；只训 >720p；结果 UniGenBench 91.36、Artificial Analysis 开放权重榜 top-1。
- **I2V**：过滤后的预训练数据 + **agentic workflow 挖弱点**（"identifies model weak spots to retrieve targeted examples from the pre-training set"）+ 1000 条人工精选 + 2 万条合成片段；刻意保留 20% T2I token 防语义漂移；480p/189 帧（≈8s@24fps）定点特化。
- **Policy**：从 mid-trained Nano 恢复，fresh 动作编码器/解码头/动作嵌入 + 5× lr 加速适配；输入 = 本体感知状态 + 三视角拼图（540×640 canvas）；预测 32 步绝对关节位置 + 辅助 RGB 视频，15 Hz；推理仅 4 步去噪 + shift 5 + CFG=3 + 跳过视频潜解码 ⇒ 策略服务器 2×RTX Pro 6000；RoboArena/RoboLab 第一（[TR §4.2.5]）。
- **工具链**：Cosmos Framework 后训练算法表提供 SFT/DPO/GRPO/PPO（含 embodied-agent training）/OPD/DiffusionNFT 六项与 policy server-client 部署（[FW README]，该表无 LoRA 行）；LoRA 的出处是 NVIDIA/Cosmos 着陆仓库层级的表述——"for training infra (SFT, LoRA, RL, distillation etc.)"（[Repo] README）与 Platform 表 "SFT · LoRA · distillation · RL post-training"，以及 COOKBOOK 后训练配方 "full SFT or LoRA"（[Repo COOKBOOK.md]）；4-step 蒸馏 = **DMD2**（fake-score 网络 32B 同架构、从 teacher 初始化；canonical 配置 8 节点 ×4 GB200，[FW distill recipe]）——对应官方 Super-Text2Image/Image2Video-4Step 检查点 "17-25x faster"（[Repo models.md]）。

**生产线 B：交互仿真专用课程（cosmos-simulation 技术报告，2026-11-4）**（[SIM §3-4]）——把生成器改成"能从自己的输出继续生成"的流式模拟器，四阶段：
0. **Bidirectional adaptation**：全时间可见性下适配目标域与控制接口，产出冻结的双向 teacher；
1. **Teacher Forcing (TF)**：把 generator 的全注意力换成 **temporal-causal chunk attention**（chunk 内联合去噪、chunk 间因果），用干净参考历史学 chunk 预测；两遍 replay 实现清洁/噪声分支掩码（第一遍算 clean K/V 缓存，第二遍并行评 noisy 目标）；
2. **TF-dCM**：一致性蒸馏把多步去噪压成 few-step student（Euler 单步 teacher 推进 + 端点匹配损失）；
3. **SF-DMD**：Self Forcing + Distribution Matching Distillation——在 **student 自己生成的 rollout 历史**上训练（治 exposure bias），冻结 stage-0 双向 teacher 当参考分数 + 可训练 auxiliary score model。

配套 **streaming 推理机制**（[SIM §4]）：chunk 为预测单元（Sim-Bimanual = 2 潜帧/8 RGB 帧；Sim-Auto = 小潜步）；每 chunk 后 RefreshKV 把完成 chunk 追加进 clean K/V；**有界历史** = 初始 sink 区 + 滚动窗口（StreamingLLM 式），存储位置带逻辑时间戳与角色元数据、驱逐不改序号；编译固定形状 + CUDA graph + **maskless attention**（分组算注意力、log-sum-exp 合并，免建大掩码）；官方明确定义两个度量——`control-to-observation latency`（control_in→首帧受影响输出 obs）与 `RTF`（生成时长/物理时长 ≤1 为实时），且指出**接收整段控制流比逐 chunk 收控制延迟更低**（等输入也计入响应延迟，[SIM Eq.22-25]）。关键工程排序："complete adaptation before distillation…to preserve its few-step generation behavior"（[FW README]）——先适配后蒸馏，不要在蒸馏好的检查点上直接 SFT。

**为什么两条线分开**：生产线 A 处理"分布内条件下的质量/保真"（数据够了 SFT 即可），生产线 B 处理"分布外的自生成历史 + 实时约束"——必须因果化 + 蒸馏 + 流式化三件事一起做。**代价**：B 线每个专用检查点都要重走 4 阶段课程（[SIM §5-7] 三个例子各自独立训练）；蒸馏后检查点不宜再 SFT；官方同时承认这条线"assumes conditioning inputs are predetermined…Running with a prerecorded sequence of controls covers conditional generation but does not exercise feedback from policy-driven interaction"——**真闭环的 policy-in-the-loop 验证被官方明确列为未决事项**（"policy-driven simulator utility requiring separate closed-loop validation"，[SIM §1/§2.3]）。

### 2.8 为什么它是 "Physical AI 数据工厂"

官方定位证据链（[Site][PR][TR]）：

1. **模型栈本身就是数据生产线**。TR §1 开篇立论：真实世界训练 "slow, expensive, and could be dangerous" ⇒ "we must construct a training facility to enable safe and scalable learning in simulated worlds"；Fig.2 把基座画在中心，四个后训练箭头分别指向 Text-to-Image/Synthetic Data Generation/Policy/**Training Environment**。产品页组件按此对齐：**Cosmos Data Factory**（"Accelerate data curation, processing, and generation with agentic blueprints"）、**Cosmos Curator**（"Curate, filter, and transform multimodal data into high-quality training datasets"）、**Cosmos Evaluator**（"Automatically score and validate generated synthetic video quality"）、**Cosmos Datasets**（"Open, large-scale synthetic datasets for training world models"，[Site]）。
2. **数据飞轮在训练管线里已闭环**（[TR §3/§5.1]）：78 亿原始图 → 767M 训练图的漏斗靠 TransNetV2 切片、嵌入去重、47 类语义打标、DOVER/VTSS 质量分、in-house VLM 语义打标与质量过滤（注意：AI-judge/Gemma-4-31B-it 是 §3.1 Reasoner 数据管线的过滤器；生成器视觉漏斗的过滤是 "a small suite of in-house VLM models"，[TR §3.2.1]）；**合成数据被有意注入** mid-training 混合（60% 真图 + 36% 合成 + 4% 文字渲染）以补长尾物理场景；I2V 后训练直接用 agentic workflow 挖模型弱点再取回定向样本——数据管线跟着模型弱点迭代。
3. **专用检查点就是 SDG（合成数据生成）机**。Transfer-Auto：11 相机 + LiDAR 同步 SDG；WSM（World Scenario Map）控制信号 = 车道线/道路边界/人行横道（crosswalk）/标志 + 投影 3D 长方体（语义色 = 类别、着色 = 朝向）——**输入是结构化场景布局，输出是带物理一致性的传感器数据**（[SIM §7.1]）；Sim-Transfer 用"外部模拟器维护物理状态、模型只做渲染转移"，8 并行环境实时跑在一张 GB200（[Repo models.md]）。新闻稿佐证定位："state-of-the-art synthetic data generation"、"reducing physical AI training and evaluation cycles from months to days"（[PR]）。
4. **许可让工厂产出可自由出厂**：OpenMDW-1.1 明文"does not impose any restrictions or obligations with respect to any…outputs generated by using the Model Materials"（事实卡 §3 逐项 #5）——**数据工厂的产出无许可负担**，这是与其他闭源世界模型（Genie 3/Marble）在"数据工厂"定位上的决定性差异。

**代价/边界**：工厂产出的"数据"是像素与 JSON 动作，没有 identity/ownership/confidence 语义（§4）；长时程/复杂物理的 artifacts 与"需额外验证、护栏与系统级安全分析"是官方 Limitations 原文（事实卡 §2.1）；跑工厂的算力档位（S=1×≤96GB 到 XL=>64 GPU，[Repo COOKBOOK.md]）远高于本开发机（事实卡 §4）。

## 3. 能力边界与工程现实

机制层的限制（与事实卡 §2/§4 互链，此处只列事实卡装不下的**结构性**边界）：

1. **Edge 是功能子集且有独立血统**：仅 256p/480p、50-150 帧、无音频生成；它的 LLM 是从零训练的自家 Nemotron 系 dense 2B（去 QK-norm、ReLU² 激活），不像 Nano/Super 继承 Qwen3-VL——意味着 Edge 的 reasoner 能力上限独立于主家族演进（[TR §2.5]；Edge 权重按 [TR] 写作时"will be included in a later release"，2026-07 已发布，[Repo README What's new]）。
2. **条件长度天花板**：v2v-predict 只吃 5 帧（≈2 潜帧）条件；Sim-Auto/Sim-Bimanual 的闭环是 post-training 产物而非基座能力；基座 + 无蒸馏的推理在长时程自回归下会累积误差——官方为此造了整条 SF-DMD 流水线，且仍承认"policy-driven simulator utility requiring separate closed-loop validation"（[SIM]）。
3. **serving 栈分叉**：reasoner 复用 Qwen3-VL 生态（vLLM/TRT-LLM），generator 需要 vLLM-Omni/FlashDreams 等扩散栈；7 后端矩阵里 Sim 检查点只标了 PyTorch/vLLM-Omni/FlashDreams/SGLang（[Repo models.md]）。
4. **720p 上下文墙**：74,000 token 定长上下文在 720p 只装 1 个样本——batch 加速在 720p 为零，吞吐与分辨率直接冲突（[TR §5.3.1 Tab.9]）。
5. **基准表是"已测"不是"支持"**："Empty cells mean that combination has not been measured yet — not that it is unsupported"（[Repo inference_benchmarks.md]，事实卡 §2.1）——评 Cosmos 前先查表是否覆盖自己的工作流组合。

## 4. 与 OmniWorld 的关系深化（World Contract 四视角）

主归宿（②适配器-离线数据生产者 + 副归宿评测对象）已由事实卡 §6 裁定，此处从契约四要素深化**为什么不能更进一步**：

- **Identity**：契约②"runtime 唯一铸造（单调 id、不复用）"（`docs/design/00-总体设计.md:36-44`）。Cosmos 3 的输出是像素流；WSM 控制里的长方体有语义类别与朝向着色、逐帧描述运动，但官方材料**未承诺跨帧实体 ID 连续性**（[SIM §7.1.1] 只有 "Semantic colors identify object categories, cuboid shading conveys heading, and successive frames describe motion"）——从生成视频反解稳定实体身份是评测桥要做的事，Cosmos 不提供。Sim-Bimanual 的动作通道倒是有"validity mask 记录哪些字段被观测"（[SIM §5.1]）——这与"关联判定可替换"的契约精神同构，值得借鉴。
- **Time**：契约③"单一 tick 单调时钟域；墙钟仅诊断"。Cosmos 3 恰好相反——它**主动放弃了单一计数时间轴**：FPS modulation 把 t 轴改造成物理秒轴，Sim-Auto 里相机（7.5Hz 潜步）与 LiDAR（10Hz）"align the streams by physical timestamp"且"Capture time determines this alignment independently of diffusion time"（[SIM §7.1.1]）。可借鉴的分层：**物理时间（对齐多源观测）与生成时间（diffusion time/chunk 序）显式分离**——对应到 OmniWorld，tick 域之外如果要接多速率传感器数据，"capture time vs tick"的分离就是 Cosmos 已验证的先例；但 OmniWorld 不应因此把 tick 换成墙钟（契约③冻结）。
- **Ownership**：契约④"每字段单一作者；v1 真值独占运动学+类别；他人结构性无写接口"。机制级对照：MoT 双塔本身就是参数级 ownership 设计——reasoner 参数永不读 DM 输出（[TR §2.3.2]），等价于"AR 域对 DM 域结构性无写路径"。而 Cosmos 作为数据源进 OmniWorld 时：OpenMDW-1.1 输出不受限（事实卡 §3）使生成帧可按 D1 纪律入库（脚本+清单+SHA256+许可记录），但这些帧只能是**观察源**，不能是运动学真值作者——真值作者权在数据集标注侧，模型输出无作者权资格（事实卡 §2.2 推断，本报告维持）。
- **Confidence**：契约五元组 Proposal 只断言 transform + class_tag（`src/core/proposal.hpp:16`，事实卡 §2.2）。Cosmos 3 的输出既无置信度字段，官方 Limitations 又明列 temporal inconsistency/action-state inconsistency 等 artifacts——因此评测桥的正确形状是：把"生成误差"当作独立于"观测噪声"的第三类误差源建模（闭环笔记 §6.1 已裁定"真实预测器会在此基础上再叠加生成误差"），ECE/校准口径对生成式预测器需要重新定义而非直接复用。**可借用的测量口径**：官方的 RTF 与 control-to-observation latency（[SIM §4.2 Eq.22/24]）恰好是 Phase 4 评"交互式世界模型响应性"的现成度量定义——这是本次深调对评测桥切片最直接的可移植产出。

**接口缺口的机制解释**（事实卡 §2.2 说"装不下"，这里说清为什么）：`WorldModelAdapter::predict(Tick, WorldState) → Proposal[]` 假设输入是结构化状态、输出是可裁决主张；Cosmos 3 的 v2v-predict 输入是 5 帧像素 + 文本（不是信念账本），输出是像素 + 可选 JSON 动作（不是 Proposal）。读真值违反闭环笔记 §4"世界模型必须读信念"——两边的类型系统在入口和出口都不匹配，评测桥必须是独立切片（像素→主张的转换本身就是被评对象的一部分）。
