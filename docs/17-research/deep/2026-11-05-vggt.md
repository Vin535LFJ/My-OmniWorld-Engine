## 0. 摘要

VGGT（Visual Geometry Grounded Transformer，CVPR 2025 Best Paper，Meta AI × Oxford VGG）是一个 ~1.2B 参数的**前馈 Transformer**：输入一个场景的 1～数百张视图，**一次前向推理**同时输出相机外参/内参、深度图、3D 点图与跨帧 3D 点轨迹，每类稠密输出自带逐像素置信度。核心原理一句话：**把 SfM/MVS 的多阶段迭代优化问题，摊销（amortize）成一个在 17 类带 3D 标注的数据集上端到端训练的序列到序列几何回归问题**——输入是若干帧的 patch token 序列，输出是首相机坐标系下的全部几何量。

最关键的三个机制：

1. **Alternating Attention（交替注意力）**：24 层 backbone，每层先做帧内自注意力（frame-wise self-attention）再做跨帧全局自注意力（global self-attention）。消融显示在等参数量下它同时优于 global-only（ETH3D Overall 0.827 → 0.709）与 cross-attention（1.061 → 0.709）。
2. **Camera token + 首帧特化**：每帧 1 个 camera token + 4 个 register token 拼进 patch token；首帧用**另一组**可学习 token，使网络能识别参考帧——所有输出定义在首相机坐标系，从而消掉尺度/坐标系 gauge 模糊。
3. **Aleatoric uncertainty 即置信度**：DPT 头每个像素多输出 1 个通道，经 `1+exp` 激活后作为损失中的逐像素权重（`γ·L·conf − α·log conf`）；训练均衡点使 conf 与预期误差成反比（高 conf ⇔ 低预期误差，precision 型量），置信度由此"从损失函数里长出来"，无需单独的校准监督。

对本项目的意义：VGGT 是"评测是第一个应用"（ADR-0008）语境下最对位的**几何观测生产者**——四类输出与 World Contract 的 identity（跨帧轨迹）/confidence（逐像素置信度）语义天然同构。但它每场景一次前馈、无时序模型、无增量接口，time 轴与 ownership 必须由引擎侧接管（§4）。许可与显存现实见事实卡 §3/§4：**只可外部运行、产物入环，不可进发行物**。

## 1. 项目定位与生态位

VGGT 在论文谱系上是 PoseDiffusion → VGGSfM → CoTracker 的汇流：把前两者的"几何"与后者的"轨迹"合并进单一前馈架构（事实卡 §1 Research Progression）。生态位判定与 OmnidWorld 归宿（②适配器——几何观测生产者，Adapter only）见事实卡 §6，此处不重复。原理层需要补充的一点是它**与 DUSt3R/MASt3R 的架构分野**：DUSt3R 系是"图对 + 推理时全局对齐"（pairwise + test-time optimization），VGGT 是"任意帧数 + 无测试时优化"——论文明确以此为核心卖点："This is a substantial departure from DUSt3R, MASt3R, or VGGSfM, which still require costly iterative post-optimization to obtain usable results"（[论文 §1](https://arxiv.org/html/2503.11651v1)，检索 2026-11-05）。分野的机制根源（多视图原生训练、GT 归一化消 gauge、交替注意力撑住任意帧数）在 §2.3/§2.8 展开。

## 2. 原理详解

> 来源约定：**[P-§x]** = 论文原文对应小节（https://arxiv.org/html/2503.11651v1，检索 2026-11-05）；**[code:path:L行]** = 官方仓库 main 分支源码（https://github.com/facebookresearch/vggt，检索 2026-11-05，行号以当日 main 为准）。论文与代码冲突处两说并注明。

### 2.1 架构总览：一次前馈的几何观测流水线

**怎么做。** 数据流（[P-§3, Fig.2]；[code:vggt/models/aggregator.py:187-265]、[code:vggt/models/vggt.py:29-96]）：

```
images [B,S,3,H,W]                        （值域 [0,1]，518 基准，14 的倍数）
  │ ImageNet mean/std 归一化               [code:aggregator.py:205]
  ▼
DINOv2 ViT-L/14-reg patchify               [code:aggregator.py:163-185; P-§3.2]
  每帧 K=(H/14)×(W/14) 个 patch token（embed_dim=1024）
  ▼
拼每帧 1 个 camera token + 4 个 register token    [code:aggregator.py:217-221]
  ▼
Aggregator：24 层 ×（frame-wise 自注意力 → global 自注意力）   [P-§3.2；code:aggregator.py:241-252]
  │ 中间层缓存：仅第 4/11/17/23 层，frame⊕global 拼接 → [B,S,P,2048]
  ▼                                       [code:aggregator.py:254-261]
├─ CameraHead（吃 camera tokens）→ pose_enc [B,S,9]        §2.4
├─ DPTHead×2（吃 patch tokens）→ depth [B,S,H,W,1]+conf；world_points [B,S,H,W,3]+conf   §2.5
└─ DPT 特征器 + BaseTrackerPredictor → track [B,S,N,2] + vis + conf（需给 query points）  §2.7
```

规模与实现要点：总参数 ~1.2B；每层 1024 维、16 头、MLP ratio 4；QK-norm + LayerScale（init 0.01）；PyTorch `nn.MultiheadAttention` 开 flash attention；RoPE 2D（`rope_freq=100`，camera/register token 位置编码置零）；相机/深度/点图三个头在 fp32 下运行（`torch.cuda.amp.autocast(enabled=False)` 包裹）（[P-App B]；[code:aggregator.py:52-71,227-232]；[code:vggt/layers/attention.py:44-62]；[code:vggt.py:63-83]）。

**为什么这样设计。** 论文自述是"最小 3D 归纳偏置 + 大数据"路线（"a simple architecture with minimal 3D inductive biases, letting the model learn from ample quantities of 3D-annotated data"，[P-§3.2]）：不写极线几何、不写代价体、不写优化层，几何全部由数据学出。代价是训练规模（64×A100×9 天，[P-§3.4]）换推理时的极简（单次前馈）。

**代价是什么。**
- 全局自注意力的显存随帧数平方级增长是全模型的主瓶颈：官方基准（H100 + flash attention v3、336×518、仅特征骨干）1 帧 1.88 GB → 200 帧 40.63 GB（[P-§5 Runtime and Memory, Table 9]）。⚠️ 该表是 **2026-05-15 显存修复前**的基准，数字与现状的差异及本机 8 GB 约束见事实卡 §2.1/§2.3/§4，此处不复述。
- 头部并非零成本：camera head ≈ 特征骨干运行时的 5%、显存的 2%；DPT 头平均每帧 +0.03 s / +0.2 GB（[P-§5]）。
- DPT 头逐帧独立预测——帧间信息交换**只**发生在 backbone 内（[P-§5]："inter-frame relationships are handled only within the feature backbone, and the DPT heads make independent predictions per frame"）。这也正是官方给出的降显存逃生门：显存不够可逐帧过 DPT 头（[P-§5]；[code:dpt_head.py:115-170] 的 `frames_chunk_size=8` 分块即该机制的实现）。

### 2.2 Token 化与 camera/register token：几何的"接口"

**怎么做。** 每帧 token 序列 = `[camera_token(1), register_tokens(4), patch_tokens(K)]`，`patch_start_idx=5` 之后的才是 patch token（[code:aggregator.py:130-134,217-221]）。两个关键细节：

1. **首帧特化**：camera/register token 各有**两套**独立可学习参数（shape `(1,2,X,C)` 的第 0 位给首帧、第 1 位给其余帧），经 `slice_expand_and_flatten` 展开（[code:aggregator.py:128-138,315-338]）。论文原话：首帧用不同的 learnable tokens "allows the model to distinguish the first frame from the rest, and to represent the 3D predictions in the coordinate frame of the first camera"（[P-§3.3]）。
2. **camera token 如何变得有内容**：初始只是 std=1e-6 的近零可学习 embedding（[code:aggregator.py:137-138]），但它要过完整 24 层交替注意力；帧内自注意力让它与同帧 patch token 交换信息，论文指出"the refined camera and register tokens now become frame-specific"正是靠帧内注意力层实现（[P-§3.3]）。出 backbone 后，camera head 取的正是每帧序列第 0 位（[code:camera_head.py:86-89]）。register token 输出被丢弃（[P-§3.3]；[code:dpt_head.py:206] 各头都从 `patch_start_idx:` 切片）。

**为什么这样设计。**
- **坐标系 gauge 问题**：同一组图像可以在任意相似变换下重建，必须钉死一个规范解。VGGT 的选择：一切输出定义在首相机坐标系（point map 是 viewpoint-invariant 的、定义于 g₁ 坐标系；首帧外参恒等：q₁=[0,0,0,1]、t₁=[0,0,0]；训练时 GT 也归一化到首相机系，见 §2.8）。首帧特化 token 就是网络识别"g₁ 在哪"的物理机制；架构因此对除首帧外的所有帧置换等变（"Order of Predictions"，[P-§3.1/§3.3]）。
- **camera token 单独存在的原因**：相机参数是每帧一个全局量，让一个专用 token 汇聚该帧全部几何线索，避免与逐像素稠密预测争用表征；register token 沿用 DINOv2 w/ registers 的既有发现（[P-§3.3 引 19]）。
- 位置编码处理：patch token 用 RoPE 2D 网格位置，camera/register token 位置置 (0,0)——它们是"槽位"而非空间位置（[code:aggregator.py:227-232]）。⚠️ RoPE 一节为纯代码事实，论文正文/附录只说 "we use DINOv2 and add positional embedding"（[P-App B]），未提 RoPE。

**代价是什么。** 每帧只加 5 个 token，开销可忽略；但 camera token 全程参与 24 层全局注意力（token 数里含它）；且"首帧 = 参考系"意味着输出的绝对坐标系绑定于**输入顺序**——第 0 帧换一张图，整个输出的 gauge 就换掉（[P-§3.1]；对 OmniWorld 的含义见 §4）。

### 2.3 Alternating Attention：帧内与全局的交替

**怎么做。** 24 个"层"，每层 = 1 个 frame-wise 自注意力块 + 1 个 global 自注意力块，**两套独立权重**（两个各 24 块的 `ModuleList`；[code:aggregator.py:81-113,241-252]）。帧内注意力把 token 排成 `(B·S, P, C)`——S 帧互不相干、可当大 batch 并行；全局注意力排成 `(B, S·P, C)`——一帧的每个 token 对所有帧的所有 token 做注意力（[code:aggregator.py:267-312]）。`aa_order=["frame","global"]`、`aa_block_size=1`，即严格一帧内一全局地交替（[code:aggregator.py:66-67]）。

**为什么这样设计。** 论文给出明确机理："This strikes a balance between integrating information across different images and normalizing the activations for the tokens within each image"（[P-§3.2]）——全局注意力负责跨帧信息融合（多视图三角化的"对齐"），帧内注意力负责把融合回来的信息按帧归整/增强（激活在帧内归一化）。消融证据（[P-§4.5 Table 5]；等参数量 2L 层、同 hidden dim/heads，ETH3D 点图 Overall↓）：

| 变体 | Acc. | Comp. | Overall |
|---|---|---|---|
| Cross-attention（每帧对其他帧 cross-attend） | 1.287 | 0.835 | 1.061 |
| Global self-attention only | 1.032 | 0.621 | 0.827 |
| **Alternating-Attention** | **0.901** | **0.518** | **0.709** |

论文还补了一句经验结论：初步实验里 cross-attention 一致劣于 self-attention，且帧数增长时运行时开销更大（[P-§4.5]）。

**代价是什么。**
- 全局自注意力的注意力矩阵是 `(S·P)²`，这是 §2.1 显存曲线陡峭的算术来源；论文承认"naive implementation of global self-attention can be highly memory-intensive"，缓解方向是 LLM 部署技术（如 Fast3R 的 tensor parallelism 可直接移植）（[P-§5]）。
- 训练侧靠 gradient checkpointing（`model.train()` 时启用，[code:aggregator.py:30,282-283]）+ bfloat16（[P-§3.4]）。
- 工程实作层面：2026-05-15 官方修复的显存问题是"中间张量冗余持有"——aggregator 从缓存全部 24 层中间输出改为仅缓存第 4/11/17/23 层（`cached_layer_indices`，其余层条目为 None）（事实卡 §2.1/§2.3 已核验；[code:aggregator.py:71,119-120,254-261] 即修复后代码）。该修复只砍**输出缓存**，注意力本身的平方复杂度不变——**推断**：8 GB 上的帧数天花板仍由全局注意力主导，实测前不可乐观（事实卡 §7 的"立项前实测"结论因此成立）。
- 单帧退化：S=1 时全局注意力没有跨帧对象可融合，等效于帧内注意力——这正是官方"单视图重建零样本可用"的架构原因（"global attention simply transitions to frame-wise attention"，[P-§5 Single-view Reconstruction]）。

### 2.4 Camera head：camera token → 9 维位姿编码 → 迭代精化

**怎么做。** 输入取**最后一层**缓存的 camera tokens `[B,S,2048]`（frame⊕global 拼接后的 2048 维；[code:camera_head.py:86-89]；[code:vggt.py:24]）：

1. **主干**：4 个 transformer block（dim 2048、16 头）+ 输出映射——对应论文"four additional self-attention layers followed by a linear layer"（[P-§3.3]；[code:camera_head.py:51-56]）。
2. **位姿编码**：`absT_quaR_FoV`，9 维 = 平移 t(3) + 旋转四元数 q(4) + FoV f(2)，主点假设在图像中心；沿用 VGGSfM 参数化（[P-§3.1]；[code:camera_head.py:30-43]）。激活（[code:camera_head.py:34-36]、[code:head_act.py:12-35]）：t 线性、q 线性、f ReLU（保证视场角为正）。
3. **迭代精化**（代码实现，论文正文未述，见 §5 UNVERIFIED-2）：默认 4 轮。每轮把当前位姿预测（首轮用 learnable `empty_pose_tokens`）线性嵌入 → DiT 式 adaLN 调制（SiLU+Linear 产出 shift/scale/gate，`gate·(1+scale)+shift`，[code:camera_head.py:119-123,144-149]）→ 过 4 层主干 → MLP 回归**位姿增量**，累加到当前预测；上一轮预测在进入下一轮前 `detach`（不回传跨轮梯度）（[code:camera_head.py:95-141]）。`vggt.py` 返回 `pose_enc_list`（每轮一个）与最后一轮的 `pose_enc`（[code:vggt.py:67-69]）。

**为什么这样设计。**
- **quaternion + FoV 而非 R/t/f 矩阵**：四元数无奇异、9 维紧凑，是 VGGSfM 已验证的参数化（[P-§3.1 引 125]）。
- **增量式迭代精化**：把"一步回归到位姿"改成"逐步修 delta"，对小样本难场景更稳；detach 是工程上避免跨轮 BPTT 不稳定/省显存的常见做法（[code:camera_head.py:115-116]）。
- **f 用 ReLU 而非 sigmoid/exp**：FoV 只需为正、无需上界（[code:camera_head.py:36]）。

**代价是什么。** 主点居中假设（[P-§3.1]）——真实相机会有偏差，这是机制性近似；四元数 q 与 −q 同一旋转，激活为线性、官方代码/论文均未见符号连续化处理（§5 UNVERIFIED-4）；位姿头无逐像素置信度——camera 置信度语义在 VGGT 中缺席（对 §4 的 World Contract 有影响）。

### 2.5 DPT 多任务头：多尺度特征融合 → 深度/点图/轨迹特征

**怎么做。** 深度头与点图头是**同一个 DPT 架构**（Dense Prediction Transformer，Ranftl et al.，[P-§3.3 引 87]）的两个实例，仅输出维度与激活不同（[code:vggt.py:25-26]）：

| 头 | output_dim | 值激活 | conf 激活 | 输出 |
|---|---|---|---|---|
| depth_head | 2（depth+conf） | `exp`（depth=exp(x)>0） | `expp1`（1+exp） | [B,S,H,W,1] + [B,S,H,W] |
| point_head | 4（xyz+conf） | `inv_log`（sign(y)·expm1(\|y\|)） | `expp1` | [B,S,H,W,3] + [B,S,H,W] |

DPT 内部（[code:dpt_head.py:43-113,205-234]；[P-App B] "feed the tokens from the 4-th, 11-th, 17-th, and 23-rd block into DPT for upsampling"）：

```
4 层缓存 token [B,S,P,2048]（去掉前 5 个特殊 token）→ 重排回 patch 网格
  → 每层 1×1 conv 投影到 {256,512,1024,1024} 通道（4 个"尺度分支"）
  → resize：ConvTranspose×4 / ConvTranspose×2 / Identity / Conv↓2（上采样到 4 倍/2 倍/1 倍/半倍 patch 分辨率）
  → refinenet1-4 融合块逐级融合（residual units）
  → 双线性插值回原图分辨率（down_ratio=1 → 518）
  → 3×3 conv → 1×1 conv 出 output_dim 通道
```

轨迹头不直接出坐标：一个 `feature_only=True` 的 DPT（down_ratio=2、128 通道、无输出卷积）把 token 变成每帧稠密特征图 T_i，喂给追踪器（[code:track_head.py:50-68]；[P-§3.3] "the DPT head also outputs dense features T_i ∈ R^{C×H×W}, which serve as input to the tracking head"）。

**为什么这样设计。**
- **为什么要 DPT 而不是一层线性头**：token 只有 patch 分辨率（518/14=37 格），线性头无法恢复全分辨率细节；DPT 的价值是从 backbone 的**多个深度**取特征（4/11/17/23 层——浅层有高频、深层有语义/几何），多尺度重组合后上采样，这是 ViT 稠密预测的标准解（[P-App B]；[code:dpt_head.py:52]）。
- **为什么深度用 `exp`、点图用 `inv_log`**：深度恒正，`exp` 天然保证值域；点图坐标有正负、量级可以很大，`sign(y)·(exp(|y|)−1)`（[code:head_act.py:115-125]）是对称的无界 log 域参数化，大值处梯度被对数压缩、训练更稳。**推断**（论文未明说该选择的理由）：这一非对称设计来自两个任务的值域差异。
- **为什么深度/点图/相机三头并训（over-complete）**：三者闭合关联——点图+相机即可解 PnP 反推相机，深度可由点图+相机导出（[P-§3.1 Over-complete Predictions]）。但消融证明全训最好（§2.8），且推理时**用相机头+深度头反投影出的 3D 点比点图头直出的点更准**（"unprojecting the predicted depth maps to 3D using the predicted camera parameters yield higher accuracy"，[P-§4.3]）——把难任务（点图）拆成两个较易子任务（深度+相机）有额外收益。官方 `unproject_depth_map_to_point_map` 工具即这条推荐路径（事实卡 §5）。

**代价是什么。** 逐帧独立 → 无帧间几何一致性约束（一致性由 backbone token 承载，[P-§5]）；每帧 0.03 s/0.2 GB；DPT 融合块参数量在头里占比不小（四个 256~1024 通道分支，[code:dpt_head.py:51]）。

### 2.6 逐像素置信度：从 aleatoric uncertainty 损失里长出来

**怎么做（机制）。** 置信度**不是独立模块**，是 DPT 输出通道的最后一维：`xyz = out[..., :-1]`、`conf = out[..., -1]`，经 `expp1` 激活 `conf = 1 + exp(raw)`，值域 [1, ∞)（[code:head_act.py:74-110]；[code:vggt.py:25-26]）。训练目标是 aleatoric-uncertainty 损失（[P-§3.4]；论文引 Kendall 系 [58,75,59,76]）：

```
L_depth = Σᵢ ‖Σᵢᴰ ⊙ (D̂ᵢ − Dᵢ)‖ + ‖Σᵢᴰ ⊙ (∇D̂ᵢ − ∇Dᵢ)‖ − α·log Σᵢᴰ     （点图同构，用 Σᵢᴾ）
```

released 训练代码的等价形式（[code:training/loss.py:281-367]）：

```python
loss_reg  = ‖gt − pred‖₂                        # 逐像素 L2
loss_conf = gamma * loss_reg * conf − alpha * log(conf)   # gamma=1.0, alpha=0.2（代码默认）
# 另有 4 尺度下采样的梯度损失（gradient_loss_multi_scale_wrapper, scales=4），conf 同样加权
# valid_range=0.98 分位数过滤离群损失项（filter_by_quantile）
```

**为什么这样设计（取舍）。** 对固定残差 L，上式关于 conf 求导得 f'(conf) = γ·L − α/conf，零点 `conf* = α/(γ·L)`（f'' = α/conf² > 0 为极小）——均衡点上**置信度与预期残差成反比**（高 conf ⇔ 低预期误差；conf 是 precision 型量，数值越大代表预期越准）：容易像素报高置信度（压低第一项 `γ·L·conf`）、拿不准的像素报低置信度，但全报低置信度又被 `−α·log conf` 惩罚（防坍缩）——方向与源码注释 "This encourages the model to be confident on easy examples and less confident on hard ones"（[code:training/loss.py:311]）一致。于是无需任何校准数据集，网络就被激励学会"报出自己预期的残差水平"。论文的表述："the uncertainty maps are used in the loss and, after training, are proportional to the model's confidence in the predictions"（[P-§3.3]）。与 DUSt3R 的差异：VGGT 额外把 conf 用进了**梯度损失的多尺度加权**（代码注释自认 "hacky, but very easier to implement"，[code:loss.py:267-268]），使平滑区域的置信度也受监督。

**代价是什么（限制）。**
- conf ≥ 1 且无上界，是**损失侧乘性权重**（precision 型量：数值越大代表预期越准，§2.6 均衡点推导），不是 [0,1] 概率；它的绝对数值没有独立的概率语义，跨 checkpoint（如原始检查点 vs 商用检查点，事实卡 §2.1 末条）之间是否可比无官方说明。与轨迹头的 conf（sigmoid → [0,1]，§2.7）**语义不同族**——两者进 World Contract 的 confidence 域时不能直接同列（§4）。
- 该机制学出的是"模型自己的误差感知"，**无官方校准主张**（ECE/覆盖度等）——**UNVERIFIED-1**。
- 置信度图的实际消费方式（过滤阈值等）是使用者约定；官方 README 的掩蔽建议针对的是"反光/天空/水面"类内容（事实卡 §2.1，不复述）。
- camera 输出没有对应的置信度头（§2.4），整个模型只有稠密与轨迹两个置信度族。

### 2.7 Track head：CoTracker2 式相关度追踪（粗初始化 + 迭代精化）

**怎么做。** 两段式（[code:track_head.py:12-104]；[P-§3.3 Tracking]）：

1. **特征提取**：`feature_only` DPT 出每帧 128 通道、半分辨率（down_ratio=2）特征图（[code:track_head.py:50-57]）。
2. **BaseTrackerPredictor**（CoTracker2 架构，[P-§3.3 "we use the CoTracker2 architecture"]；[code:track_modules/base_track_predictor.py:82-209]）：
   - **粗初始化**：query 点 `(B,N,2)` 直接复制到所有 S 帧作为初始坐标（源码注释："the search will start from the position of query points at the reference frames"，[code:base_track_predictor.py:106-108]）；query 特征从第 0 帧特征图双线性采样，复制 S 份作为初始 track 特征（[code:base_track_predictor.py:110-114]）。
   - **迭代精化 ×4**（`iters=4`，[code:track_head.py:23,70]）：每轮取当前位置的 **7 层相关度金字塔**（`corr_levels=7, corr_radius=4`——每层在特征图金字塔上取 ±4 px 邻域，7×81=567 维相关特征，[code:base_track_predictor.py:48-49,123-131]）+ 当前坐标相对 query 的 flow 的 Fourier 编码 + track 特征 → 拼接过小 transformer（`hidden_size=384` 的 updateformer）→ 回归坐标增量与特征增量；坐标累加、特征残差更新；**query 帧坐标被强制回写为原始 query 点**（"we assume the query points should not be changed"，[code:base_track_predictor.py:184-186]）；轮间梯度 detach（[code:base_track_predictor.py:123-128]）。
   - **可见性/置信度**：最终 track 特征各过一个 Linear → sigmoid，得 `vis [B,S,N]`（BCE 训练，[P-§3.4]）与 `conf [B,S,N]`（[code:base_track_predictor.py:195-204]）。

**为什么这样设计。**
- **相关度金字塔 + 局部窗口**：每轮只需在当前位置附近 ±4 px 搜索，靠金字塔层级覆盖大位移、靠 4 轮迭代累计大运动——比全局匹配便宜得多，且 N 个 query 完全并行。这是 PIPs/CoTracker 系的标准机制（[P-§2 Tracking-Any-Point]）。
- **不假设时间顺序**："similar to VGGSfM, our tracker does not assume any temporal ordering of the input frames"（[P-§3.3]）——输入是图像**集合**不是视频，这使轨迹头可用于无序多视图而不只是视频流。
- **训练时 query 恒取第 1 帧**（[P-§3.3 "during training, we always set q=1"]），推理时任意帧可作 query。

**代价是什么。**
- 局部相关窗 + 有限迭代次数意味着单轮运动范围有上限；金字塔缓解但未消除（机制性限制，推断：官方未单独给出轨迹头的位移上限测试——**UNVERIFIED**）。
- **released 训练代码不含 track 损失**：`MultitaskLoss` 里 track 分支直接 `raise NotImplementedError("Track loss is not cleaned up yet")`（[code:training/loss.py:72-74]），微调默认配置 `track: null`（[code:training/config/default.yaml:108]）。即官方发布栈只支持 camera/depth(/point) 微调，轨迹头微调要自己补损失或用 CoTracker 侧方案（事实卡 §1 的下游用法是"拿预训练 backbone 增强 CoTracker"，[P-§4.6]）。
- 轨迹头需显式给 query points，四头中唯一"按需"运行的分支（[code:vggt.py:85-91]）。

### 2.8 训练目标与数据配方：为什么"一次推理"能出几何

**怎么做。** 多任务损失 `L = L_camera + L_depth + L_pmap + 0.05·L_track`，前三项量级相近无需加权、轨迹项压 0.05（[P-§3.4]）。camera loss 论文用 Huber（smooth L1）（[P-§3.4]）；released 代码改用 L1 并注释了原因（"The paper uses smooth l1 loss, but we found l1 loss is more stable"，[code:loss.py:168-171,175-177]），四个精化轮次按 `gamma=0.6` 的时间衰减加权（末轮权重 1.0，[code:loss.py:85,114-135]）。**GT 归一化**（gauge 消除的第二半）：先把一切量移到首相机系，再以"点图全体 3D 点到原点的平均欧氏距离"定尺度，平移/点图/深度全部按此缩放；且**只归一化 GT、不归一化预测**，强迫网络学会输出这个规范变体（[P-§3.4 Ground Truth Coordinate Normalization]；与 DUSt3R 对预测也做归一化的差别及理由见 [P-§5 Normalizing Prediction]——实测无必要且有训练不稳定风险）。

数据配方：17 类数据集（Co3Dv2、BlendMVS、DL3DV、MegaDepth、Kubric、WildRGB、ScanNet、HyperSim、Mapillary、Habitat、Replica、MVS-Synth、PointOdyssey、Virtual KITTI、Aria SE、Aria DT、类 Objaverse 合成资产），标注来源含传感器、合成引擎与 SfM（[P-§3.4 Training Data]）。轨迹 GT 的构造：深度图反投影成 3D → 重投影到目标帧 → 重投影深度与目标深度图一致性过滤（[P-App B]）。

训练规模：AdamW，160K iters，cosine LR 峰值 2e-4、warmup 8K；每 batch 恒 48 帧（每场景随机抽 2–24 帧）；518 最长边、宽高比 0.33–1.0 随机；64×A100×9 天；梯度裁剪 1.0；bf16 + gradient checkpointing（[P-§3.4, App B]）。

**为什么这样设计（这是"前馈能出几何"的根本）。**
1. **任务即监督**：相机/深度/点图/轨迹各有稠密真值，多任务同训互相校准。消融（[P-§4.5 Table 6]，ETH3D Overall↓）：去掉 camera loss 伤害最大（0.709→0.834），去掉 track（→0.790）次之，去掉 depth（→0.727）边际——相机估计对几何质量的杠杆最大。
2. **GT 归一化把回归目标钉死成唯一解**：网络不必预测"某个合法的相似变换"，只需预测训练分布中的规范解——这是前馈回归可行的前提。
3. **DINOv2 初始化**：对比 14×14 conv patchify，DINOv2 表征"better performance + much more stable training (initial stages) + less sensitive to hyperparameters"（[P-§5 Patchifying]）。⚠️ 论文声称端到端训练；released 微调默认冻结 aggregator（`frozen_module_names: ["*aggregator*"]`，[code:training/config/default.yaml:121-122]）是**微调**设置，与预训练设置不同（[training/README.md](https://github.com/facebookresearch/vggt/blob/main/training/README.md)，检索 2026-11-05）。
4. **每帧独立强增广**（逐帧 color jitter）：逼网络靠几何而非外观配对（[P-App B]）。

**代价是什么。** 几何先验全部来自这 17 类数据集的分布——分布外的几何形态（大幅非刚性、极端旋转、鱼眼/全景投影模型）落在先验之外，是 §3 所列官方限制的机制根源；另外多任务同训意味着**没法只训一个头而完全不动别的**（共享 backbone 梯度互相牵制，released 微调因此选择整体冻结 aggregator 只调头，[code:training/config/default.yaml:121-122]）。

### 2.9 与优化式重建（COLMAP/BA）的原理对比

**COLMAP/BA 侧的原理**。传统 SfM 是多阶段管线：图像匹配 → 三角化 → bundle adjustment（BA），COLMAP 是该管线的代表实现（[P-§2]）。BA 的本质是**在参数空间里迭代最小化重投影误差**的非线性最小二乘（标准表述；论文用"iterative optimization techniques like Bundle Adjustment"刻画其迭代属性，[P-§1]）：给定近似初值，反复"线性化-解增量"直至收敛；它对初值敏感、需要跨视图匹配作为观测、逐场景求解。

**VGGT 侧的原理**。把同一问题**摊销**：训练时用 17 类数据集的 GT 几何把"匹配-三角化-优化"的复合映射压进网络权重；推理时一次前馈直出全部几何（[P-§1] "substantial departure"）。两者的机理差异在四点：

| 维度 | COLMAP/BA | VGGT（前馈） |
|---|---|---|
| 计算形态 | 逐场景迭代优化（10 帧 ~15 s，[P-§4.1 Table 1]；帧数增加耗时进一步增长——推断） | 单次前馈，10 帧 0.2 s（H100）（[P-§4.1 Table 1]） |
| 初值依赖 | 需要良好初值与充分匹配观测 | 无（先验内置于权重） |
| 失败模式 | 匹配失败/弱纹理/重复纹理 → 优化无处着落 | 训练分布外的几何（§3） |
| 误差性质 | 收敛后局部最优，可很准 | 单帧回归误差，但整体一致性好（无逐场景发散） |

官方数字对照（10 随机帧、H100、AUC@30，[P-§4.1 Table 1]）：

| 方法 | Re10K (unseen) | CO3Dv2 | 时间 |
|---|---|---|---|
| COLMAP+SP+SG | 45.2 | 25.3 | ~15 s |
| VGGSfM v2 | 78.9 | 83.4 | ~10 s |
| DUSt3R | 67.7 | 76.7 | ~7 s |
| MASt3R | 76.4 | 81.8 | ~9 s |
| **VGGT（纯前馈）** | **85.3** | **88.2** | **~0.2 s** |
| **VGGT+BA** | **93.5** | **91.8** | **~1.8 s** |

**关键nuance——混合形态才是上限**。论文与附录都明确：纯前馈在 phototourism 基准 IMC 上**并不压过**优化式 SOTA——VGGT 前馈 AUC@10 = 71.26 vs VGGSfMv2 的 76.82；加上 BA 后跳到 84.91（AUC@3 从 39.23 → 66.37），拿下 IMC SOTA（[P-App C Camera Pose Estimation on IMC]）。机理上 VGGT+BA 快于传统 BA 链路的原因：VGGT 直出的 3D 点/位姿已是"close-to-accurate"初始化，**省掉三角化与迭代精化**两个阶段（[P-§4.1]；[P-App C]）。即论文的诚实结论是："while the feed-forward mode of VGGT outperforms all previous alternatives…there is still room for improvement since post-optimization still brings benefits"（[P-§4.1]）。

**可微 BA 为什么被放弃**：试过 VGGSfM 式可微 BA，效果有希望，但 Theseus 实现使每训练步慢 ~4×，对大规模训练不可接受，遂放弃（留作无 3D 标注场景的监督信号方向）（[P-§5 Differentiable BA]）。这一取舍说明了架构边界：**优化没有被消灭，只是被移出了推理路径**——需要更高精度时官方自己的答案仍是"回到 BA"（`demo_colmap.py --use_ba`，事实卡 §5）。

**对 OmniWorld 的边界推论**（推断，依据如上事实）：VGGT 适合当"毫秒-秒级几何伪真值生产者"，不适合当"高精度标定工具"——后者仍属于优化式管线的能力范围；伪真值管线的精度预算应按前馈误差水平设定，需要更高精度时挂 BA 后处理（代价 ~1.8 s/场景量级）。

## 4. 与 OmniWorld 的关系深化（World Contract：identity / time / ownership / confidence）

前提（事实卡 §6 已定）：VGGT = 几何观测生产者，Adapter only，产物入环、本体不入仓。以下按 World Contract 四轴深化**契约语义**层面的对接点：

**identity。** VGGT 唯一提供"同一物理点跨帧身份"的机制是 track head（§2.7）：给定 query 点，输出它在所有帧的对应位置 + 可见性——这是 surface element 级别的 identity 观测，与引擎侧"同一实体跨 tick 的身份轴"直接同构。但注意两条边界：① 该 identity 只在**单次调用内**成立——两次调用之间 VGGT 没有任何跨场景/跨调用的点身份注册表，跨调用身份必须引擎侧自建（推断，依据：无状态前馈架构，[P-§3]）；② 相机/深度/点图三头不带身份语义，从点图到"实体"的聚合是引擎侧责任。

**time。** VGGT 的输入是**无序帧集合**——追踪器不假设时间顺序（§2.7，[P-§3.3]），模型没有递归/流式状态，每个调用是对"一个静态场景快照"的观测。对引擎的含义：time 轴完全由引擎持有；VGGT 的输出本质是 `t_obs` 时刻帧集的一次性几何快照，时间连续性（滑窗重推理、帧间外推）是适配器/引擎的活（与事实卡 §2.2 "无增量式/流式接口"的推断一致）。工程含义：入环产物必须携带引擎时间戳，VGGT 自身无任何 time 元数据输出。

**ownership。** 坐标系 gauge 是最尖锐的对接点：VGGT 把输出钉死在**首输入帧**的相机坐标系（§2.2），而 World Contract 要求世界状态有引擎侧统一的 canonical frame。两次相邻调用若首帧不同，输出的世界坐标 gauge 不同——**VGGT 不能拥有世界坐标系，canonical frame 的 ownership 必须在引擎侧**；适配器要做的是 gauge 对齐（同帧集内一致、跨帧集由引擎锚定）。这同时呼应所有权三问（research-queue "Conflict-resolution policy family" 行）：VGGT 产物应作为带 producer 标识的 observation 写入，不参与仲裁。

**confidence。** VGGT 是四个调研对象中唯一**逐像素**带置信度输出的：深度/点图 conf（[1,∞) 的 precision 型乘性权重——数值越大代表预期越准，§2.6）与轨迹 vis/conf（[0,1] sigmoid 族，§2.7）。对接 World Contract 的三个注意点：① 两族语义不同（precision 型权重 vs 类概率），入库时应分域标注而非混入同一数值域（推断）；② 无官方校准主张（**UNVERIFIED-1**）——research-queue "Minimal uncertainty propagation" 行所问的"proposal confidence 的校准"在这里有现成的实验对象：用伪真值管线自比 GT 即可测 ECE/覆盖度，方法与本仓 problem-log 015 的 closed-loop 指标组方法论同构；③ camera 输出无置信度（§2.4），位姿观测的 confidence 需要引擎侧另造（如用重投影残差自估，推断）。

2. **camera head 迭代精化的论文↔代码差**：论文正文只写"4 层 self-attention + linear"（[P-§3.3]），4 轮 adaLN 增量精化仅见于代码（[code:camera_head.py:95-141]）；且 released training 栈自称"re-implementation…please open an issue if anything looks off"（[training/README.md]）——原始 1.2B 训练与 released 代码的一致性无官方逐项声明。
3. **原始训练的实际损失超参**：`training/config/default.yaml` 只是 Co3D 微调配置（camera weight 5.0 / depth 1.0 / point·track 关闭，γ/α 走代码默认 1.0/0.2，[code:training/config/default.yaml:93-108]；[code:training/loss.py:199,239,281]）；1.2B 原始训练的配置文件未发布。
4. **四元数符号连续性处理**：q 与 −q 表示同一旋转，官方代码（`quat_act="linear"`）与论文均未见符号对齐/连续化逻辑，训练如何避免四元数翻转抖动无来源。
5. **RoPE 2D 的论文缺失**：`rope_freq=100`、特殊 token 零位置仅见于代码（[code:aggregator.py:69-79,227-232]），论文 App B 只提 "positional embedding"。
6. **轨迹头单轮位移上限**：局部相关窗（±4 px×金字塔）+ 4 轮迭代的可追踪最大位移无官方测试数据。

**证据缺口**（有来源但证据不闭合，多数已登记在事实卡 §7，此处只列原理层新增）：

- Table 9 显存/延迟基准是 2026-05-15 显存修复**前**的数据（事实卡 §2.1/§2.3 已核验并链 commit diff）；修复后同显存预算官方称约 2-3× 帧数，但**无官方新基准表**——8 GB 实测仍是适配器立项前置条件。
- 单目（单视图）重建性能作者明确未做定量测试（事实卡 §2.1，社区 issue #36 对比非官方）。
- **轨迹头训练路径断裂**：released `MultitaskLoss` 对 track 直接 `NotImplementedError`（[code:training/loss.py:72-74]）——若要微调轨迹头（如针对本仓目标域），官方发布栈内无现成损失，需自行移植 CoTracker 损失或等官方补齐。
- VGGT-Omega（事实卡 §7）与 VGGT 原理栈的关系（架构是否沿用 AA/camera token）未调研——本报告只覆盖 VGGT 本体。
