## 0. 摘要（给赶时间的人）

SAM 2 是 Meta FAIR 的可提示视觉分割基础模型，把图像视为单帧视频，用一个**流式记忆 transformer** 统一图像与视频分割（[论文](https://arxiv.org/abs/2408.00714)，2026-11-05）。核心原理一句话：**视频逐帧流入，当前帧特征通过 cross-attention 读取一个有界记忆库（近期帧空间特征 + 提示帧记忆 + object pointers），在每帧 O(1) 于视频长度的代价下把目标身份从过去帧"搬"到当前帧**。三个最关键的机制：① **Memory Attention**——4 层 self-attn→cross-attn→MLP 的 transformer 块，把当前帧 unconditioned 特征条件化到记忆上；② **Memory Encoder + 记忆库**——把"预测掩码 × 当前帧特征"融合成 64 通道空间记忆写入 FIFO（近期 6 帧 + 提示帧永不逐出），object pointer（256 维语义向量，≤16 个）走单独的轻量通道；③ **Promptable 统一嵌入**——点/框/掩码经 prompt encoder 全部进入同一个 256 维 token 空间，任意帧可补提示、掩码可作提示。对本项目的意义：SAM 2 输出的是掩码**不是身份**——`obj_id` 是调用方管理的 client-side id，模型侧无再识别机制（推断，见 §2.7/§5）、无语义标签；identity/confidence 必须由引擎侧 World Contract 接管，"跟丢"应映射为观测缺失 + confidence 衰减而非身份切换。它是 Observation 契约真实半边的"分割观测生产者"（②适配器），定位与许可结论见事实卡 §6。

## 1. 项目定位与生态位

SAM 2 在本仓库族谱中的归宿是 **②适配器（分割观测生产者）**：给真实视频帧序列生产逐帧掩码观测，与 depth 适配器同族不同类（第二类真实观测）。族谱理由、接入形态（Python 进程外适配器，无官方 ONNX/C++）、与 World Contract 的边界等结论已在事实卡 §6 给出，此处不重复。本报告只回答事实卡装不下的问题：**它的流式记忆分割在机制上是怎么做到的，为什么掩码不等于身份跟踪，代价是什么**。

### 2.1 架构总览：一条帧在 SAM 2 里的生命周期

**怎么做。** 官方设计声明：*"For real-time processing of arbitrarily long videos, we take a streaming approach, consuming video frames as they become available"*（[P]，2026-11-05）。四个模块、一条逐帧流水线：

```
视频帧(1024×1024)
  │
  ▼  ① Image Encoder: MAE 预训练 Hiera-L（层级化，一次性产出 unconditioned tokens）
  │     FPN 融合 stride-16/32 特征 → 记忆注意力输入（stride-16 → 64×64 = 4096 tokens）
  │     stride-4/8 特征绕过记忆注意力，作为 skip connection 直达 decoder 上采样
  ▼  ② Memory Attention: L=4 层（d_model 256）
  │     当前帧特征 self-attn → cross-attn 读记忆库（空间记忆 + object pointers）→ MLP
  ▼  ③ Mask Decoder: TwoWayTransformer(depth 2) + hypernetwork 动态掩码 + 上采样(skip 融合)
  │     输出：掩码(3 候选)、predicted IoU、object_score_logits、output token(→obj_ptr)
  ▼  ④ Memory Encoder: 掩码降采样 ⊕ 帧特征 → CXBlock 融合 → out_proj → 64 通道空间记忆
  │
  └──→ 写入该对象的记忆库（FIFO 近期帧 + 提示帧 + obj_ptr 队列），供后续帧的 ② 读取
```

- **Hiera-L**（[cfg21]，2026-11-05）：`embed_dim 144`、`stages [2,6,36,4]`、`global_att_blocks [23,33,43]`（仅 3 层全局注意力）、`window_spec [8,4,16,8]`；neck `d_model 256`、`backbone_channel_list [1152,576,288,144]`。为速度做的取舍：移除图像编码器的所有 relative position bias（RPB）以启用 FlashAttention-2。消融（Table 10，SA-V val J&F/速度）：默认配置（图像编码器无 RPB + 记忆注意力 2d-RoPE）68.3、1.00×；加回 RPB 则 67.9、0.93×（RPB 阻止 FlashAttention-2）；无 RPB 也无 RoPE 67.1、1.04×——**移除 RPB 是提点又提速的双赢**，−1.2 点的差距属于"从记忆注意力中去掉 RoPE"，与 RPB 无关（[P] Table 10，2026-11-05）。
- **"unconditioned tokens"**：*"The image encoder is only run once for the entire interaction and its role is to provide unconditioned tokens"*（[P]，2026-11-05）——image encoder 输出不依赖记忆/提示；所有条件化（记忆 + 提示）都发生在其后的轻量模块里。这是"编码一次、条件化多帧"的流式关键。
- **多对象**：objects 独立处理，只共享逐帧 image-encoder 特征（[P]；[vpred] 中 backbone 特征 expand 到对象数后逐对象跑记忆管线，2026-11-05）。
- **记忆注意力特征分辨率**：stride-16（FPN 融合 stride 16/32，[P]）；SAM 2 默认输入 1024×1024 下即 64×64 = 4096 tokens/帧。

**为什么这样设计。** 图像与视频统一：图像就是一个只有一帧、只有提示帧记忆的视频（[P] 的 PVS 任务定义）。流式 + 有界记忆库让每帧计算量与视频长度无关——这是与"整段视频进 3D transformer"的离线路线的本质区别，也是"约 44 FPS"实时口径的架构基础（[blog]；测速细节链接事实卡 §1，2026-11-05）。

**代价。** 逐帧两次 attention（读记忆 + 写记忆后的下一帧再读）比无记忆推理贵；记忆注意力层质量对深度敏感（消融 (2,2)→67.3 / (3,2)→64.1 / (4,4)→68.3，砍层数掉点明显，[P]，2026-11-05）；多对象时记忆管线按对象数重复执行（§2.7 的代价）。

### 2.2 Memory Attention：当前帧如何"读"记忆

**怎么做。** 官方定义：记忆注意力 *"condition[s] the current frame features on the past frames features and predictions as well as on any new prompts"*，堆叠 L 个 transformer 块，每块 **self-attention → cross-attention 到记忆库（提示帧与非提示帧的空间记忆 + object pointers）→ MLP**（[P]，2026-11-05）。

- 每层结构（[mattn]，2026-11-05）：`MemoryAttentionLayer` 依次 `_forward_sa(tgt, query_pos)` → `_forward_ca(tgt, memory, ...)` → MLP（residual 连接）；输入处位置编码以 **0.1 缩放**相加（`output + 0.1 * curr_pos`）；层栈末端接 LayerNorm。
- 位置编码（[cfg21]，2026-11-05）：sinusoidal 绝对 PE + **2d RoPE**（`rope_theta: 10000.0`，self 与 cross 都用）；配置 `pos_enc_at_attn: false`、`pos_enc_at_cross_attn_keys: true`——位置信息主要靠 RoPE 携带，cross-attention 的 keys 侧显式加 PE。
- **Object pointer tokens 被排除在 RoPE 之外**：`MemoryAttention.forward` 对 RoPEAttention 传 `num_k_exclude_rope = num_obj_ptr_tokens`，指针 token 无空间对应关系，不应赋 2d 旋转位置（[mattn] + [P] 原话 *"The object pointer tokens are excluded from RoPE as they do not have specific spatial correspondence."*，2026-11-05）。
- 维度（[cfg21]，2026-11-05）：`d_model 256`、`dim_feedforward 2048`、cross-attention `kv_in_dim 64`——记忆 keys 是 64 维（§2.3 的 mem_dim），在注意力内投影到 256。
- 深度：论文 L=4 层；配置 `num_layers: 4`（每层都含一次 self + 一次 cross，即 (4 self, 4 cross)，[cfg21] + [P]，2026-11-05）。

**为什么这样设计。**
1. **条件化全交给 attention**：image encoder 一次前向产出 unconditioned tokens，"带着记忆看当前帧"这一步用轻量的 4 层 transformer 完成，而不是重跑编码器——这是流式实时的直接来源。
2. **cross-attention 的 keys 同时含空间记忆与语义指针**：当前帧的每个空间位置都能同时查询"过去帧这里长什么样"（空间记忆）与"这个目标整体是什么"（obj_ptr），两类记忆在同一个注意力里竞争融合，由数据决定权重——这是帧间保持目标的统一机制。
3. **vanilla attention + FlashAttention-2**：论文明确不用花哨的记忆算子，*"vanilla attention"* 直接吃高效内核红利（[P]，2026-11-05）。

**代价。**
- cross-attention keys 随记忆库线性增长：6 个近期帧 × 4096 tokens + 提示帧记忆 + ≤64 个指针 token（§2.4）。消融：N=8 时相对速度 0.93×（N=6 为 1.00×）（[P] Table 9c，2026-11-05）。
- **软注意力无硬门控**：匹配是连续权重而非离散判定，外观相似对象间权重会互相渗透——这是官方"相似邻近对象混淆" limitation 的机制根源之一（§3）。
- 只能读**自己的**记忆：跨对象无通信，单对象管线的视角内没有"别的对象占了这批记忆"的概念。

### 2.3 Memory Encoder 与记忆库：帧间如何用记忆保持目标

**怎么做。** 两个动作：**写**（`_encode_new_memory`）与**读**（`_prepare_memory_conditioned_features`）。

写（[base] + [menc]，2026-11-05）：
1. 取当前帧最高层特征（stride-16）；
2. 预测掩码 → `sigmoid` 后按 `sigmoid_scale_for_mem_enc: 20.0` / `sigmoid_bias_for_mem_enc: -10.0` 做**近二值化**（sigmoid(-10)≈4.5e-05，把软掩码 logits 拉成近乎 0/1 的通道）；来自点提示的掩码还可直接二值化（`binarize_mask_from_pts_for_mem_enc` 分支）；
3. `MaskDownSampler`：conv 栈（每层 Conv2d→LayerNorm2d→GELU）把 1 通道高分辨率掩码降到记忆分辨率（代码默认 per-layer kernel 4/stride 4、`total_stride=16`，最终 1×1 conv 升到 embed_dim；2.0 配置用 kernel 3/stride 2 ×4 层，总 stride 同为 16）；
4. **逐元素相加**：`x = pix_feat_proj(pix_feat) + masks`——"这一帧长什么样"与"目标在哪"在特征级相加，这是记忆的信息本质：**带外观的空间记忆，不是裸掩码**；
5. `CXBlock` fuser（ConvNeXt 风格：7×7 depthwise conv + LayerNorm + 4× 扩展 pointwise ×2 + residual）融合信息；
6. `out_proj`（1×1 conv）投影到 **mem_dim 64**（[cfg21] `out_dim: 64`），输出 `maskmem_features` + `maskmem_pos_enc`（空间位置编码，逐帧相同故全局缓存一次，[vpred]，2026-11-05）。

读（[base]，2026-11-05）：
- **记忆库三类条目**：(a) **近期帧**：当前帧前 `num_maskmem-1 = 6` 帧的空间记忆，FIFO 滚动；eval 默认逐帧存（`memory_temporal_stride_for_eval=1`，代码注释对照"XMem and Cutie use r=5"）；(b) **提示帧（cond frames）记忆**：存于独立的 `cond_frame_outputs`，**永不逐出**；(c) **object pointers**（§2.4）。`num_maskmem=7` 的官方注释：*"1 input frame + 6 previous frames"*；`max_obj_ptrs_in_encoder=16`（[base] 注释，2026-11-05）。
- **时间嵌入**：7 个可学习槽位向量 `maskmem_tpos_enc`（形状 `(num_maskmem,1,1,64)`，`trunc_normal_` 初始化），消费时 `maskmem_enc = maskmem_enc + self.maskmem_tpos_enc[self.num_maskmem - t_pos - 1]`。近期帧按"距当前帧的相对步数"占 6 个槽位；提示帧统一 `t_pos=0`、共享第 7 个槽位——**论文口径**："We embed temporal position information into the memories of N recent frames"，**提示帧不加时间位置**（训练信号更稀疏、推理时提示帧时间跨度不定，[P]）；代码的实现方式即提示帧固定映射到同一个常量槽位（表达"这是提示帧"，不表达时间距离）。反向传播对空间记忆只是从当前帧另一侧取帧（forward/reverse 两个分支），无符号运算（[base]，2026-11-05）；有符号时间编码仅存在于 obj_ptr 通道（§2.4）。
- 选中的记忆展平后与 obj_ptr tokens 一起成为 cross-attention 的 keys（§2.2）。

**为什么这样设计。**
1. **特征记忆而非掩码传播**：与"把上一帧掩码当 prompt 重喂"的路线相比，直接条件化特征保留了外观与布局信息，信息带宽大得多——这是 SAM 2 与其前代视频扩展思路的分水岭。
2. **64 通道够用**：消融 mem_dim 64→68.3 vs 256→66.4，且存储省 4×（论文原话 *"4× smaller"*，[P] Table 9d，2026-11-05）。空间记忆要的是"指回哪里+像什么"的线索，不是全量特征。
3. **直接存储足够，GRU 无增益**：Table 11 同口径（两行都不带 object pointers）对比：GRU 65.3 vs 直接存储 64.5（SA-V val；GRU 略高但更慢，0.97× vs 1.00×）；带指针的直接存储（默认）68.3。论文结论：GRU 不带来改善（LVOSv2 略有例外：68.9 vs 67.0），直接存储更简单、更高效（[P] Table 11，2026-11-05）。读的时候用注意力按需取，已足够保信息。
4. **提示帧永不逐出**：用户的意图锚点不随 FIFO 漂移；近期帧 FIFO 提供运动连续性。两套窗口分工：短期靠 6 帧空间记忆，长期靠提示帧锚点 + 16 帧 obj_ptr（§2.4）。

**代价。**
- **空间记忆只覆盖最近 6 帧**：超出窗口的长期一致性全押在提示帧与指针上；提示帧数量 M 官方未给固定上限口径（[P] 只给 FIFO 描述，2026-11-05）。
- **记忆由自己的预测生成**：错误掩码经 memory encoder 写入记忆，会被后续帧读到——误差自我强化的通道是结构性的。官方 limitation 表述为"可能跟丢/混淆"；"自我强化"这一归因是**推断**（依据：记忆写入无外部真值校验 + `no-obj` 信号只调权不阻断写入，[base]）。
- **代码中无记忆丢弃规则**：目标消失的帧同样写记忆（仅加遮挡嵌入，§2.6）——长时遮挡期间记忆持续"过时"，重现时匹配质量下降（与官方"long occlusion" limitation 对应，§3）。
- 每帧一写一读的固定开销：无记忆的帧也要为将来付编码成本。

### 2.4 Object Pointers：高层语义的轻量通道

**怎么做。**（[base] + [P]，2026-11-05）
- **来源**：mask decoder 的 output token。2.1 起开启 `use_multimask_token_for_obj_ptr: true`（[cfg21]）：multimask 输出时用 multimask token 组，再按 predicted IoU 选出最佳 token（[dec] 返回 `mask_tokens_out[:, 1:]`；[base] 中 `sam_output_token = sam_output_tokens[batch_inds, best_iou_inds]`）；2.0 语义下即单掩码 token。经 `obj_ptr_proj`（`Linear(hidden_dim, hidden_dim)`，或 `use_mlp_for_obj_ptr_proj` 时的 3 层 MLP）得到**每帧 1 个 256 维向量**——论文称之为 *"lightweight vectors for high-level semantic information"*（[P]，2026-11-05）。
- **入库窗口**：≤15 个非提示帧 pointer（代码 `for t_diff in range(1, max_obj_ptrs_in_encoder)`，t_diff∈[1,15]）+ 提示帧 pointer 另行收集——默认单提示帧场景合计 16（`max_obj_ptrs_in_encoder=16`，`t_diff_max=15`），比空间记忆的 6 帧窗口**更长**（[base]，2026-11-05）。
- **进注意力**：mem_dim(64) < C(256)，故 reshape `C // mem_dim = 4`——每个指针切成 **4 个 64 维 token**（与论文"256-dim object pointer 分成 4 个 64-dim token"一致），最多贡献 64 个 cross-attention keys。
- **时间编码**：2.1 用**有符号帧距**过 `get_1d_sine_pe(Δ/t_diff_max)` 再 `Linear` 投影（`add_tpos_enc_to_obj_ptrs: true` + `proj_tpos_enc_in_obj_ptrs: true` + `use_signed_tpos_enc_to_obj_ptrs: true`，[cfg21]；2.0 配置 `add_tpos_enc_to_obj_ptrs: false`——此机制是 2.1 增补）。反向传播时（`track_in_reverse`）有符号帧距乘 `tpos_sign_mul = −1`——代码中该符号翻转**只作用于 obj_ptr 的时间编码**，空间记忆无此操作（[base]，2026-11-05）。与空间记忆不同，指针**不加 RoPE**（§2.2）。
- **no-obj 混合**：混合权重 λ 默认是**硬指示 𝟙[object_score_logits > 0]**（`soft_no_obj_ptr` 默认 False，2.1 hiera-L 配置未开启）；`fixed_no_obj_ptr: true` 下先 `obj_ptr = λ·obj_ptr`，再 `obj_ptr += (1-λ)·no_obj_ptr`（`no_obj_ptr` 是 `trunc_normal_(std=0.02)` 的可学习参数）——**默认配置下，目标被判不存在的帧 obj_ptr 恰好等于可学习的 no_obj_ptr 本身**（逐帧二值切换，无渐变）；`sigmoid(object_score_logits)` 的软混合仅存在于可选的 `soft_no_obj_ptr=True` 路径（[base]，2026-11-05）。

**为什么这样设计。**
1. **职责分离**：空间记忆承载"长什么样/在哪"（appearance + where），指针承载"是什么"（what，高层语义）。消融证据：去掉指针 SA-V val 64.5→68.3（+3.8）、LVOSv2 67.0→71.6（+4.6）、MOSE 73.1→73.0（≈0）（[P] Table 11，2026-11-05）——语义向量在对象稀疏场景收益显著，在拥挤同现场景无增益。
2. **便宜且可拉长窗口**：16×256 个标量对比 6×4096×64 的特征图，几乎免费；因此指针窗口可以比空间记忆窗口更长，远期连续性用向量续、近期精确外观用特征图续。
3. **no-obj 混合让"消失"成为可传播状态**：被判不存在的帧指针统一为 no_obj_ptr 的"无对象"语义，重现帧又切回目标指针——"有没有"这个状态本身进入记忆通道（配合 §2.6 的遮挡嵌入）。

**代价。**
- 拥挤/相似对象场景（MOSE 类）指针无增益——一个 256 维向量装不下"同类多实例"的区分度，区分仍要靠空间记忆的软匹配。
- 默认配置的 no-obj 切换是**逐帧二值**的（无衰减渐变）：遮挡帧指针完全等于 no_obj_ptr，长时遮挡期间"目标语义"不随时间被稀释，但重现时的匹配质量仍取决于空间记忆是否过时（§2.3）。
- 2.1 对时间编码/混合方式的多次调整（signed tpos、fixed_no_obj_ptr）说明初版设计在此处留有余量，机制细节随版本在变——引用行为结论时必须绑定版本。

### 2.5 Promptable 接口：点/框/掩码如何进同一个嵌入空间

**怎么做。** Prompt encoder *"identical to SAM's"*，接受 clicks（正/负）、boxes、masks（[P] 原话；[penc]，2026-11-05）：

| 提示 | 编码 | 形态 |
| --- | --- | --- |
| 点 | 坐标 +0.5（取像素中心）→ 归一化坐标的正弦位置编码 **⊕ 4 种可学习类型嵌入之一**（正点/负点/框左上角/框右下角） | 256-dim sparse token |
| 框 | 两个角点，分别 ⊕ 左上/右下 corner 嵌入（复用同一套点机制）；无框时补 padding 点（坐标 0，label −1 → `not_a_point_embed`） | 2×256-dim sparse tokens |
| 掩码 | 输入 256×256（= 4× 64×64 embedding 分辨率）→ 两层 stride-2 conv（1→in/4→in）+ 1×1 conv → 256 通道 | B×256×64×64 **dense map，加到 image embedding 上** |
| 无掩码 | 可学习 `no_mask_embed` 展开成同尺寸 dense map | 同上 |

- 稀疏输出 `B×N×256`（N=点数+角数），稠密输出 `B×256×64×64`（[penc] docstring，2026-11-05）。
- 两类提示进**同一个** Mask Decoder 的 TwoWayTransformer（depth 2、mlp_dim 2048、8 heads，[base]）：点/框是 token 序列，掩码是加性 dense 条件，双向注意力把提示与图像 token 互相更新——**点/框/掩码不在三个接口里，在同一个 256 维嵌入空间里**。
- **视频侧提示的生命周期**（[vpred] + [base]，2026-11-05）：任意帧 `add_new_points_or_box` / `add_new_mask` → 输入按 `frame_idx` 存入 state → 该帧输出进入 `cond_frame_outputs` → `propagate_in_video` 的 preflight 阶段对临时输出跑 memory encoder，把该帧写进**永不逐出**的提示帧记忆（§2.3）——**提示的效力通过记忆向前（及向后）传播，而不是作为持续输入的 prompt**。掩码提示有两条路：走 SAM heads（`mask_inputs` 进 decoder，产生真实 obj_ptr）或 `_use_mask_as_output`（固定 logits `20·mask − 10`，注释明示 `sigmoid(-10.0)=4.5398e-05`，dummy IoU=1；`is_obj_appearing` 直接从掩码 `any>0` 推出）（[base]，2026-11-05）。

**为什么这样设计。**
1. **统一嵌入 = 交互模型**：用户可在一帧上混合叠加点+框+掩码任意组合，因为它们解码到同一空间、同一 decoder 消费；"任意帧补提示"（PVS 任务定义）依赖提示→cond 帧→记忆这条不区分提示类型的通路。
2. **点/框用 token、掩码用 dense map**：提示带宽各自匹配——点要灵活可叠、掩码要空间精度，两种形态经双向注意力等价可用。消融证据（17 数据集平均 J&F）：1-click 64.7 / 3-click 75.3 / 5-click 77.6 / box 74.4 / **GT mask 79.3**（[P] Table 4，2026-11-05）——提示信息量直接决定可达质量。
3. **训练分布覆盖全部提示类型**：初始提示按 GT mask p=0.5 / 正点 p=0.25 / 框 p=0.25 采样（§2.8），模型被迫学会消费所有形态。

**代价。**
- **最小提示的 ~15 点缺口**（1-click vs GT mask）：靠 multimask 候选 + 用户补点逐步消化，不是模型自动消解（§2.6）。
- 掩码提示进 decoder 前已降采样到 256×256：亚 4×4 像素的精细结构在 decoder 阶段不可见（[penc] 的 `mask_input_size = 4×image_embedding_size`）。
- **没有语义/文本提示**：SAM 2 家族的提示只在"指到哪"（pointing）层面工作；SA-V 标注本身不施加语义约束（事实卡 §1，2026-11-05）——分割输出与类别无关是接口层面的设计决定，不是能力缺口。

### 2.6 遮挡头与歧义处理：object presence 与多候选掩码

**怎么做。**
- **Occlusion head**：decoder 加一个额外 token + MLP → `object_score_logits`（标量）；`is_obj_appearing = object_score_logits > 0`（[P] 原话 *"an additional head that predicts whether the object of interest is present on the current frame"*；[base]，2026-11-05）。目标不在时三路联动：(a) 掩码 logits 全置 `NO_OBJ_SCORE = -1024.0`（[base] 常量）；(b) 记忆特征加 `no_obj_embed_spatial`（权重 `1 − is_obj_appearing`；2.1 配置开启，2.0 无此键——2.1 增补，[cfg21] vs [cfg20]）；(c) obj_ptr 按默认硬指示 λ=𝟙[obj>0] 与学习的 `no_obj_ptr` 逐帧二值切换（sigmoid 软混合仅 `soft_no_obj_ptr=True` 可选路径，§2.4）。论文口径：**学习到的遮挡嵌入加到"被预测为遮挡"帧的记忆特征上**（[P]，2026-11-05）——"这一帧没有对象"本身就是被传播的记忆内容。
- **歧义处理**：decoder 有 4 个 mask token（1 单掩码 + 3 multimask，[dec] `num_mask_tokens = num_multimask_outputs + 1`）。multimask 门控：`multimask_output_in_sam ∧ (是初始提示帧 ∨ multimask_output_for_tracking) ∧ (点数 ∈ [multimask_min_pt_num, multimask_max_pt_num])`；2.1 配置三值全开（tracking 时也多候选；点数 ∈ [0,1]；**框算 2 个点**，故框提示不触发 multimask）（[base] + [cfg21]，2026-11-05）。多候选时按 **predicted IoU argmax** 选（[base] `best_iou_inds`）；另有推理期回退 `dynamic_multimask_via_stability`：稳定性分数 = `area(mask>+δ)/area(mask>−δ)`，不稳定时回退 IoU 最佳候选（[dec]，2026-11-05）。视频传播中的规则（论文原话）：歧义未被后续提示消解时，**逐帧传播预测 IoU 最高的掩码**（[P]，2026-11-05）。

**为什么这样设计。**
1. **视频需要"对象不在"是合法输出**：图像分割默认提示指向对象；视频逐帧传播必须显式建模缺席——没有遮挡头，消失帧会把错误掩码写进记忆、污染后续所有帧（§2.3 的写入机制放大了缺席建模的必要性）。
2. **歧义推迟消解**：交互式哲学——模型给出多个候选并自报 IoU，把"选哪个"留给用户后续提示；训练时多掩码只监督最低损失者（逼真值对齐到候选之一）、occlusion head 永远监督（[P] 训练节，2026-11-05）。

**代价。**
- presence 是**每帧一个标量**：只回答"在不在"，不回答"去哪了"——无任何定位/重定位机制（§2.7 的机制原因之一）。
- "IoU 最高者胜"的传播策略在相似对象间可能逐帧滑到别的实例上（官方"外观相似邻近对象混淆" limitation 的机制根源，§3）。
- 稳定性回退仅在推理且非训练时生效（[dec] `and not self.training`）——训练与推理的候选选择行为不完全一致。

### 2.7 obj_id 语义与"掩码 ≠ 身份跟踪"的机制原因

**怎么做。** `obj_id` 的官方定义就在注释里：*"mapping between client-side object id and model-side object index"*——`obj_id_to_idx` 是一个 OrderedDict，`obj_idx` 是按添加顺序分配的 dict 槽位号，不带任何语义；官方注释明示 *"We always allow adding new objects (including after tracking starts)"*（[vpred]，2026-11-05）。每个对象独立持有推理状态：`output_dict_per_obj[obj_idx] = {cond_frame_outputs, non_cond_frame_outputs}`——**记忆库是 per-object 的**（每条 compact output 含 `maskmem_features / maskmem_pos_enc / pred_masks / obj_ptr / object_score_logits`）；推理循环外层按帧、内层按对象，共享的只有 image encoder 特征（expand 到对象数）；最终掩码按对象拼回（[vpred]，2026-11-05）。

**机制原因（为什么掩码 ≠ 身份跟踪）——四条，全部可追溯到机制：**
1. **身份不进模型**：`obj_idx` 只是内存槽位；模型内部**没有任何对象间比较/通信模块**（论文明示 objects 独立处理，[P]）——"这两个掩码是不是同一个东西"这个问题在架构里不存在。
2. **外观匹配只对"自己的记忆"做**：memory attention 的 keys 全部来自该对象**自己**的记忆库（§2.2/§2.3）；没有 gallery、没有检测器、没有 re-ID 打分。模型从未回答"这是不是我"，只回答两个更弱的问题："它还在不在"（occlusion head）与"它此刻长这样"（掩码）。对象消失再出现时，唯一可依赖的是（可能过时的）自己的记忆；匹配失败没有任何自动恢复路径——官方给出的缓解手段是**任意帧补提示**（事实卡 §2.1，2026-11-05）。
3. **输出无语义、无标签**：掩码无类别（SA-V 标注不施加语义约束，事实卡 §1）——masklet 是纯几何/外观对象。
4. **新 `obj_id` = 新 masklet**：同一物理对象被两个 obj_id 分别提示会得到两个互不知晓、各自独立记忆的 masklet，永不合并（per-object 状态的直接后果，[vpred]，2026-11-05）。

> ⚠️ "无再识别（no re-identification）机制"是对以上官方材料的**综合推断**：官方从未使用该措辞，其局限清单（"crowded scenes、prolonged occlusion 后可能 lose track of or mix up the target object"，[P] Appendix C / [blog]）+ 遮挡头语义 + obj_id 客户端 id 三者共同支持它。采纳为设计假设前建议做小实验（对象消失再现的 masklet 行为），见 §5/事实卡 §7。

**为什么这样设计。**
- **用户是身份的 oracle**：segment-anything 的哲学是提示即身份指派——"我要跟谁"由提示定义，模型保持任务无关（不假设封闭世界的对象集合），才能成为基础模型。身份外部化是它的**功能**而非缺陷：任何下游都可以带自己的身份定义进来。
- 每对象独立换来的是"跟踪开始后随时可加对象"（12/11/2024 新 video predictor 的官方卖点，[rel]）与单对象记忆管线的一致性。

**代价。**
- 引擎侧必须自己维护 identity 的分配与稳定（这正是 World Contract 的活，§4）；跨 gap 的身份连续性无保证。
- 多对象时 memory attention 按对象数重复执行、只共享 backbone——官方承认多对象效率"下降明显"（事实卡 §2.1，2026-11-05）。
- 帧间掩码无时间平滑约束（博客原话，事实卡 §2.1）——输出天然会抖，身份稳定≠掩码稳定。

### 2.8 训练如何塑造记忆行为（为什么这些机制可用）

**怎么做。**（[P] 训练节，2026-11-05）
- **模拟交互**：8 帧序列，随机选 ≤2 帧可提示；概率性纠正点击（7 次 vs SAM 的 8 次）；初始提示分布 GT mask 0.5 / 正点 0.25 / 框 0.25；时间顺序以 p=0.5 反转（前向/反向传播都练）；p=0.1 时点击直接从 GT 采样（容忍噪声标注）；每序列 ≤3 个 masklet。
- **损失**：focal + dice（掩码）: MAE（IoU 预测）: CE（object presence）= **20:1:1:1**；多掩码只监督最低损失者；**遮挡头永远监督**。
- **阶段**：SA-1B 预训练（ℓ1 IoU loss）→ SA-V + 内部视频 + SA-1B 子集全量训练 → 16 帧微调阶段（取 50% 最多被编辑的 masklet）。

**为什么这样设计。**
- 模拟交互把"**记忆会被读**"写进损失：传播质量不是事后评测，而是训练目标本身；概率性纠正让记忆学会容忍不完美预测（错误不至于不可恢复——正好对冲 §2.3 的自我强化风险）。
- 16 帧微调把记忆窗口的时序依赖拉长（超出 8 帧窗口的传播被显式练过）。
- object presence 以 CE 单独监督（权重 1）→ 遮挡头有独立梯度，缺席建模不是掩码损失的副产品。

**代价。**
- 训练分布决定记忆窗口的行为边界：镜头切换、超长视频是分布外（官方 limitation 与此对应，§3）。
- 损失里没有时间平滑项 → 输出抖动无惩罚（博客承认"时间平滑性无保证"，事实卡 §2.1）。

## 3. 能力边界与工程现实

官方承认的机制性限制（[P] Appendix C / [blog] Limitations 节），逐条对应到本文的机制根源：

| 官方限制 | 机制根源 | 本文位置 |
| --- | --- | --- |
| 镜头切换处可能分割失败 | 6 帧空间记忆 + 提示帧锚点假设外观/布局连续；镜头切换在训练分布外 | §2.3/§2.8 |
| 拥挤场景、相似邻近对象混淆 | cross-attention 软匹配无硬门控；obj_ptr 在 MOSE 类场景消融增益 ≈0 | §2.2/§2.4 |
| 长时间遮挡后跟丢 | 消失帧仍写记忆（遮挡嵌入），长时遮挡下记忆内容过时；无重定位机制 | §2.3/§2.6 |
| 帧间预测抖动、无平滑保证 | 训练损失无时间平滑项 | §2.8 |
| 输出无语义标签 | 接口层面设计决定（SA-V 无语义约束） | §2.5 |
| 多对象效率下降明显 | 逐对象独立记忆管线，仅共享 backbone 特征 | §2.7 |

工程现实（许可/显存/平台/无 ONNX 等硬事实**链接事实卡 §2–§5，不复制**）中与原理直接相关的一条：官方推理 API 是**会话模型**——`init_state` 一次绑定整段视频（`offload_video_to_cpu / offload_state_to_cpu / async_loading_frames` 控制帧与状态的存放设备），`propagate_in_video` 从最早的提示帧向两个方向传播（[vpred]）；模型层是流式的，但 API 形态不是逐帧推送的在线接口。`vos_optimized=True`（全模型 torch.compile）提速但引入小幅数值方差（[rel]，2026-11-05）——对位级确定性主张的复用者（如本仓库 ADR-0009）这是必须记录的行为差异。

## 4. 与 OmniWorld 的关系深化（World Contract 四视角）

**identity。** SAM 2 是"identity 必须归引擎管"的现成教学案例（事实卡 §2.2 已立论，此处给机制深度）：`obj_id` 是调用方 id、模型侧只有无语义槽位（§2.7），匹配永远只对单对象自己的记忆做、无再识别（推断）、输出无标签。推论：掩码观测入库时，identity 由引擎分配并保持稳定；**SAM 2 的跟丢必须表现为引擎侧"观测缺失"，绝不能表现为"身份切换"**——把 masklet 的中断当成实体消亡/新生，会把一次跟踪失败放大成世界状态的拓扑变化。

**time。** 流式记忆是一个**有界窗口信念**：近期 6 帧 FIFO + 提示帧锚点（永不逐出、专属槽位嵌入）+ 16 帧 obj_ptr——三段式时间视野，越远的记忆越轻量。提示帧锚点策略 ≈ 引擎侧 keyframe/anchor 策略的神经网络版：用户在意的时刻被钉住，其余时间靠滚动窗口维持。两个对接细节值得引擎记住：(1) SAM 2 的时间轴是 session 的 `frame_idx`，时间权威在调用方；(2) 它支持**反向传播**（`track_in_reverse`，时间编码符号取反，[base]）——观测可以不按单调时间到达，引擎的 World Contract 不能假设观测生产者只顺时间走。

**ownership。** SAM 2 只拥有"掩码观测的生成"；identity 的分配、confidence 的解释、语义的赋予全部在引擎侧（事实卡 §6.3 已立论）。机制层面补充：模型自报的三个置信信号——`object_score_logits`（存在性）、predicted IoU（掩码质量）、`NO_OBJ_SCORE=-1024`（缺席哨兵）——都是**模型内部的量**，其校准性（calibration）未经官方验证（§5）；引擎把 `object_score_logits` 的 sigmoid 直接当世界级 confidence 用之前，应先按 problem-log 015 的纪律把分割观测指标按 producer 分组计量，与引擎侧身份稳定性分开。

**confidence。** 引擎侧的正确映射：遮挡头判负/跟丢 → 引擎观测缺失 + confidence 衰减（time 轴上的洞），而不是删除实体或换 id；候选掩码的 predicted IoU 可作为观测质量的一次性权重，但不构成跨帧的连续置信轨迹。SAM 2 没有跨帧 confidence 传播机制——每帧的 IoU 是独立预测——跨帧置信管理天然是引擎的职责。

## 5. 未解决问题 + 证据缺口

**UNVERIFIED 清单：**

1. **"无再识别机制"**——对官方材料的综合推断（§2.7 四条依据），官方无此措辞。采纳为设计假设前应做小实验：对象消失若干帧再出现，观察 masklet 是续接（匹配记忆成功）还是断掉（需要补提示）。与事实卡 §7 同一条，共用一个实验即可。
2. **逐模块延迟占比**（image encoder vs memory attention vs decoder）——论文附录 D.3 在本次可读的页面快照中被截断，未取到官方拆分；已核验的只有消融表的相对速度因子（N=8 → 0.93×、N=4 → 1.01×，[P] Table 9c）。对适配器的帧预算设计，此缺口需实测补齐。
3. **2.1 hiera-l 配置中 MaskDownSampler 的 per-layer kernel/stride**——本轮已核验代码默认（4/4，`total_stride=16`）与 2.0 配置（3/2 ×4 层），但 2.1 配置的该段未逐行读取；"总 stride 16 → 64×64 记忆分辨率"的结论锚定在代码默认值 + 2.0 配置上，2.1 若改过 per-layer 参数不影响总 stride 结论，但未直接核验。
4. **`obj_ptr_proj` 的更细内部结构**（是否含 LayerNorm 等子层）——本轮源码提取确认其为 `Linear` / 3 层 MLP / `Identity` 三形态之一且对 obj_ptr 无 sigmoid（sigmoid 仅出现在 no-obj 的 λ 混合与掩码近二值化），更细结构未逐行核验；对机制理解无影响。
5. **HF Transformers `Sam2Model`/`Sam2VideoModel` 的 streaming video inference 与官方 `SAM2VideoPredictor` 的行为一致性**——来自 HF 官方模型卡示例，未运行验证（事实卡 §7 已登记）。
6. **每模型显存占用**——官方渠道无数字（事实卡 §4），本报告不提供；8 GB 档位选择只能实测。

**证据缺口：**
- 论文消融中"完全无记忆"的基线数字（对比 N=4/6/8）在可读页面快照内未出现（Table 9c 从 N=4 起），"记忆带来多少收益"的绝对量级暂无官方单一数字。
- 训练用的"internal video"数据不可得，训练分布对记忆行为的完整影响只能从官方描述推断。
- SAM 2.1 相对 2.0 的机制性改动（遮挡空间嵌入 `no_obj_embed_spatial`、signed pointer tpos `use_signed_tpos_enc_to_obj_ptrs` 及其投影 `proj_tpos_enc_in_obj_ptrs`、`add_tpos_enc_to_obj_ptrs` false→true）有配置差异佐证（[cfg21] vs [cfg20]）；注意 `fixed_no_obj_ptr` 两代配置均为 true（2.0 配置亦含），**非 2.1 新增**。官方未发布逐 flag 的变更说明——"2.1 新增"的表述以两份配置文件的存在性差异为据。
