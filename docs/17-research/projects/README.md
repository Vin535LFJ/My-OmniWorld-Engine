## 卡结构（固定八节 + Trust label 头）

```markdown
# <项目名> 项目卡
> Trust label: [Research] —— 一等来源；每条事实附 URL 与检索日期；未核验标 **UNVERIFIED**。
> 最后核验：<YYYY-MM-DD> · 状态：首建

## 0. 一句话
## 1. 是什么 + 官方能力声称      （| 事实 | 来源 |）
## 2. 边界与限制（官方承认 vs 我们推断，分开）
## 3. 许可（代码 / 权重 / 数据 三分）
## 4. 硬件要求（显存/驱动/OS）
## 5. 可集成接口（API / 导出 / 控制面 / 资产格式）
## 6. 与 OmniWorld 的边界 + 族谱归宿（②适配器候选 / ③技能项目 / ⑤明确让渡 / 竞品参照 / 评测对象）
## 7. 未解决问题 + 重查触发条件
## 8. 来源清单
```

## 纪律

1. **一等来源**：官方文档、官方仓库（README / LICENSE / 公告）、论文原文、官方 API 参考。二手转述不进卡。
2. **每条事实可溯源**：`| 来源 |` 列写域名+路径，§8 汇总完整 URL + 检索日期。
3. **UNVERIFIED 纪律**：来源不可达或互相矛盾时如实标注并说明原因——不作为决策依据，但保留在卡里（"seen" ≠ "suspected"）。
4. **活文档**：版本事件、许可变更用**日期小节追加**（先例：D1 note §6.1），不删原文；`最后核验` 行随更新滚动。
5. **引用不复制**：与既有日期笔记（`docs/17-research/2026-*.md`）重叠的内容一律链接过去，不重述。
